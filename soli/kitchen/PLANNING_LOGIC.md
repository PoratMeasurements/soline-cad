# PLANNING_LOGIC.md — האלגוריתם של מנוע-התכנון (Soli Kitchen)

הצינור המלא שבו `plan_kitchen.js` הופך **מדידת-חדר** (קירות + נקודות-תשתית מהמודל של Soline)
ל**תוכנית-מטבח לנגר**: רצף מודולים לכל קיר, עם מיקומים, רשימת-מודולים ורשימת-אזהרות.

---

## קלט
- `.ordx` (XML של Soline Measure / InnoDraw) **או** `room.json` פשוט.
- מבנה-חדר: `walls[]`, כל קיר = `{num, sx,sy,ex,ey, length, height, thick, fixtures[]}`.
- כל fixture = `{name, desc, w, h, x, y}` — כאשר `x` = מיקום לאורך הקיר (נחשב **מרכז**),
  `y` = גובה מהרצפה (לחלונות = סף; לפתחים = 0).

---

## שלבי-האלגוריתם

### 1. סיווג (classify)
כל fixture ממופה לסמנטיקה לפי מילות-מפתח דו-לשוניות (עברית/אנגלית):
`water · drain · gas · elec · window · door · beam · ceiling · panel · other`.
מים/גז/חשמל/ניקוז = **תשתיות**; חלון/דלת = **פתח**; קורה/עמוד = **מכשול**.

### 2. ניתוח-קיר → קטעים בָּנִיִים (analyseWall)
לכל קיר בונים שני מרחבי-חסימה לאורך אורך-הקיר:
- **baseBlocked** — היכן ארון תחתון לא יכול לעמוד:
  - **דלת/פתח** (סף < גובה-משטח) → חוסם תחתון+עליון.
  - **חלון** — אם הסף < ~900 חוסם גם תחתון; אם הסף ≥ גובה-המשטח, **התחתון מותר מתחת** (רק העליון נחסם).
  - **קורה מלאת-גובה** (h ≥ 80% מגובה-הקיר, או מתחילה ברצפה) → חוסמת הכל.
- **wallBlocked** — היכן ארון עליון לא יכול להיתלות: חלון, דלת, כל קורה שחוצה את פס-העליונים.

`spans = [0, L] פחות baseBlocked` → רשימת קטעים חופשיים לבנייה (מסננים פערים < 30 מ"מ).

### 3. בחירת-קירות ועוגני משולש-העבודה
- מדרגים קירות לפי עושר-תשתית: `+4 מים, +4 גז, +1 חשמל, + אורך-בנייה/1000`.
- **כיור** ← ממוקם על נקודת-המים; **כיריים** ← על נקודת-הגז (או חשמל אם אין גז);
  **קולט-אדים** ← עליון מעל הכיריים; **מקרר** ← על הקיר-העשיר-הבא שאינו קיר-הכיור/כיריים.
- שלוש עמדות אלו הן קודקודי **משולש-העבודה** (בקואורדינטות-עולם דרך `worldPoint`).

### 4. מיקום-עוגנים (placeAnchor)
כל מודול-פונקציונלי (כיור/כיריים/מדיח/מקרר) הוא ברוחב-קבוע ממוקם **במרכז נקודת-התשתית**,
מוצמד (clamp) לתוך הקטע הבָּנוי.

### 5. מילוי-חמדני (fillSegment)
הפערים לפני/בין/אחרי העוגנים מתמלאים ברוחבי-Base מהגדול-לקטן
(1200→…→150), והשארית < 30 מ"מ נספגת כסקרייב.

### 6. עליונים (planUppers)
`[0, L] פחות wallBlocked` → מתמלא ברוחבי-עליונים. מעל הכיריים מסומן `SW-HOOD`.

### 7. ולידציה (validate) — סימון קונפליקטים
- **משולש-עבודה:** כל צלע 1.2–2.7 מ', סכום < 8 מ'. חריגה → אזהרה.
- **חלון מול ארון:** מסומן "אין עליון בקטע זה".
- **תשתית בתוך פתח:** נקודת-שירות שנופלת בתוך פתח/דלת → "לא שמישה לארון".
- **חסר-תשתית:** אין מים → אי-אפשר כיור; אין גז → כיריים-חשמל (3 פאזות).

### 8. פלט
- `report()` בעברית לקונסולה + נשמר ל-`out/<room>_kitchen_plan.md`.
- JSON מלא ל-`out/<room>_kitchen_plan.json` (layout + triangle + modules + warnings).
- **רשימת-מודולים (Cut list):** ספירת כל קוד-מודול (`moduleList`).

## וריאנט מטבח-פנים מול מטבח-חוץ
דגל `--outdoor` מוסיף בדיקות/אזהרות דלתא (ראה KITCHEN_STANDARDS §5):
GFCI לכל שקע, ברז-גז-ניתוק נגיש, ניקוז/חורף, חומרים עמידי-מזג (נירוסטה 316/בטון/HPL),
ו-15" מרחב-הנחה עמיד-חום בכל צד של הגריל. הגיאומטריה והמילוי זהים; משתנים החומרים והתשתיות.

```
node plan_kitchen.js <room.ordx|room.json> [--outdoor] [--out DIR]
node plan_kitchen.js            # ברירת-מחדל: חדר allelem של הממיר
```

## הנחות-תכן מתועדות
1. `x` של fixture נחשב **מרכז** לאורך הקיר.
2. גובה-משטח גמור = 900 מ"מ (סף המבחין חלון-חוסם-תחתון מול חלון-מעל-משטח).
3. רזרבת-פינה מיושמת דרך מילוי/סקרייב בקצוות הקטעים.
4. פערים < 30 מ"מ אינם מודול נפרד אלא סקרייב.
5. המנוע **מכבד את מיקום-התשתית הנמדד** גם כשהוא יוצר ארגונומיה גרועה — ואז **מסמן אזהרה**
   במקום להזיז את התשתית (החלטת-הזזה היא של המתכנן/האינסטלטור).
