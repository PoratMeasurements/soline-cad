# Soli Carpentry — מודולי-תכנון לכל סוגי-הנגרות בבית

> **מה זה:** אוסף מודולי-תכנון של Soline ("Soli"), אחד לכל **סוג-נגרות** בבית — במקביל
> למודול-המטבח (`../kitchen/`). כל מודול הופך **מדידת-חדר** (קירות + נקודות-תשתית מהמודל
> של Soline) ל**תוכנית-נגר**: רצף-מודולים לכל קיר, מיקומים, רשימת-חיתוך (Cut list) ואזהרות.

> **גבול קניין-רוחני (חוק-ברזל):** כל המודולים נבנו **אך ורק** מתקני-תעשייה ציבוריים
> ומהיגיון מקורי של Soline. לא נפתח/הועתק שום קובץ/מודול/DWG של צד-שלישי, ובפרט **לא**
> שום דבר מתחת ל-`קבצים ללמידת מכונה`. כל מספר ניתן-לאימות מול המקורות המצוטטים בכל `STANDARDS.md`.

## חוזה-הקלט המשותף (Measurement-model input contract)
זהה למודול-המטבח. מנוע-משותף: [`_lib/carpentry_core.js`](./_lib/carpentry_core.js).

```jsonc
room = {
  name,
  walls: [                    // כל קיר:
    { num, sx, sy, ex, ey,    // קצות-הקיר בקואורדינטות-עולם
      length, height, thick,
      fixtures: [             // כל fixture:
        { name, desc,         // שם + תיאור (דו-לשוני עברית/אנגלית)
          w, h,               // רוחב × גובה של האלמנט
          x,                  // מיקום לאורך הקיר — נחשב **מרכז**
          y }                 // גובה מהרצפה (חלון=סף; פתח/דלת=0)
      ] }
  ]
}
```

**קלט נתמך:** `.ordx` (Soline Measure / InnoDraw XML) **או** `room.json` פשוט — דרך `C.loadRoom(file)`.
כל מנוע קורא את אותו חדר; ההבדל הוא רק **מה כל סוג עושה** עם הקירות והתשתיות.

### המנוע-המשותף (`_lib/carpentry_core.js`)
- `classify(fx)` — סיווג דו-לשוני: `window·door·beam` (פתחים/מכשולים) · `water·drain·gas·tv·data·duct·elec` (תשתיות) · `ceiling·panel·other`.
- `analyseWall(wall)` — כל fixture → חוסם עם **רום-אנכי** `[z0,z1]` או נקודת-תשתית.
- `bandSpans(analysis, z0, z1)` — קטעים פנויים לרכיב שתופס את הרום `[z0,z1]`; רק חוסם שרומו חופף מסיר אורך. זהו הלב הגיאומטרי שמשותף לכל הסוגים (ארון מלא-גובה, מזנון-נמוך, מראה מעל-משטח וכו').
- `fillSegment / layFrom` — מילוי-חמדני של רצף ומיקומו לאורך הקיר.
- `worldPoint / dist` — מרחקים בקואורדינטות-עולם (מעברים, ולידציה).
- `moduleListFrom` — רשימת-חיתוך (ספירת קודים).

## הרצה
```bash
node <type>/plan_<type>.js [room.ordx|room.json] [flags] [--out DIR]
# ברירת-מחדל: חדר allelem של הממיר, אחרת sample_room.json של הסוג
```
כל מנוע מדפיס תוכנית בעברית לקונסולה ושומר `out/<room>_<type>_plan.md` + `.json` (layout + modules + warnings).

דגלים לפי-סוג:
| סוג | דגלים |
|---|---|
| wardrobe | `--wall N` · `--hinged` · `--reach-in` |
| walkin | `--depth MM` · `--no-island` |
| vanity | `--wall N` · `--comfort` · `--double` · `--tower` |
| media | `--wall N` · `--tv 65` |
| bookshelf | `--wall N` · `--material melamine\|ply\|solid` · `--height MM` · `--low` · `--depth MM` · `--pitch MM` · `--base` · `--fixed` |
| office | `--wall N` · `--depth MM` · `--uppers-cabinet` · `--no-uppers` · `--tower` |
| entry | `--wall N` · `--per-person W` · `--coat-lockers N` · `--child-rail` |
| laundry | `--wall N` · `--us` · `--stacked` · `--sink` · `--no-tall` |
| kids | `--age toddler\|child\|teen` · `--wall N` |
| understairs | `--run N` · `--rise N` · `--going N` · `--steps N` · `--descend` |

## איך זה מתחבר ל-Soli
`../README.md` מגדיר שסולי (העוזרת-לנגר) מכסה כרגע **ניווט + הבנת-קבצים**, ומציין ש**תכנון**
הוא "מודול-אח נפרד שנבנה כעת". התיקייה הזו היא אותו מודול-אח, בפיצול ל-**כלי-תכנון לכל סוג-נגרות**:
מודול-המטבח (`../kitchen/`) + 10 מודולי-הנגרות כאן. סולי תדע להפנות אליהם — הנגר בוחר סוג,
מזין את מדידת-החדר (אותו `.ordx`/`.sol` שכבר בחבילה), ומקבל תוכנית-נגר עם רשימת-חיתוך ואזהרות.

**עקרון משותף עם המטבח:** המנוע **מכבד את מיקום-התשתית הנמדד בפועל** — הוא לא מזיז מים/גז/חשמל,
אלא **מסמן אזהרה** כשהמיקום יוצר קונפליקט (תשתית מאחורי ארון, כיור בלי ניקוז, פתח שחוצה ריצה).
החלטת-ההזזה נשארת אצל המתכנן/האינסטלטור.
