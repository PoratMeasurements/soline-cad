# soline-social

הצינור השיווקי של סולין: מאנדקס את כל ארכיון הצילומים, מקבץ אותו לאתרים פיזיים לפי GPS, מאתר סיפורי לפני/אחרי, ומייצא חבילות פרסום נקיות ממטא-דאטה.

Node בלבד, **ללא תלויות חיצוניות** — כולל פרסר EXIF ומנקה מטא-דאטה שנכתבו מאפס. רץ אופליין.

## למה בלי ספריות

`npm install` נכשל על Google Drive (EBADF — הדרייב הווירטואלי לא מסתדר עם `node_modules`). במקום להילחם בזה, פרסור ה-EXIF וניקוי ה-JPEG נכתבו ישירות מול הבייטים. יתרון נוסף: אין מה לשבור ואין מה לעדכן.

## פקודות

```bash
node index-photos.js                       # סורק הכל → data/catalog.json
node organize.js                           # מפת סדר בארכיון → data/ORGANIZE.md
node build-sites.js                        # אשכולות GPS → data/sites.json
node pair.js                               # סיפורי לפני/אחרי → data/stories.md
node thumbs.js story S0012                 # תמונות לבדיקה ויזואלית
node build-library.js --all                # בונה את "שיווק\לפני ואחרי" (כולל יישור סיבוב)
node export-post.js S0012 --label "מטבח"   # חבילת פרסום נקייה
```

הערה ל-`fix-rotation.ps1`: הוא ASCII בלבד ודורש `-Path` מפורש. Windows PowerShell 5.1 קורא קבצי `.ps1` בקידוד ANSI כשאין BOM, וזה הרס נתיבי ברירת מחדל בעברית.

## איך זה עובד

**האינדוקס** קורא 192KB מראש כל קובץ — מספיק ל-EXIF — ומריץ 64 קריאות במקביל, כי צוואר הבקבוק הוא הרשת של הדרייב ולא המעבד. תוצאות נשמרות במטמון לפי size+mtime, כך שריצה חוזרת כמעט חינם, ויש checkpoint כל 2000 קבצים.

**אשכול האתרים** הוא הרעיון המרכזי: כמעט כל צילום בארכיון צולם מאייפון עם GPS פעיל. שני צילומים במרחק 45 מ' זה מזה הם אותו אתר פיזי — גם אם הם יושבים בשתי תיקיות שונות לגמרי, בהפרש של שנה, ובלי שום דמיון בשם הקובץ. זה מה שמאפשר לחבר "לפני" ל"אחרי" בארכיון שאין בו שום מוסכמת שמות.

**יישור הסיבוב** הוא שלב שהתברר כקריטי: 77% מהצילומים נשמרים באייפון לרוחב, עם דגל EXIF שאומר לצופה לסובב. אינסטגרם מכבדת את הדגל; חלונות תצוגה וכלי העלאה רבים לא — ולכן הספרייה נראתה כמו ערימת תמונות על הצד. `fix-rotation.ps1` מסובב את הפיקסלים עצמם דרך מנוע ה-Transformation של GDI+ — טרנספורמציה ברמת בלוקי ה-DCT, בלי פענוח ובלי דחיסה מחדש, ולכן בלי אובדן איכות. `build-library.js` מריץ אותו אוטומטית בסוף.

**ייצוא הפרסום** מנתח את ה-JPEG ברמת הסגמנטים, זורק כל APP1/APP13/COM (שם EXIF, GPS, XMP, IPTC יושבים), שומר את פרופיל הצבע, ומזריק בחזרה בלוק EXIF של 26 בייט שמכיל אך ורק את דגל הכיוון — אחרת צילומי פורטרט יוצאים מסובבים. לבסוף הוא קורא את הקובץ שנוצר ומוודא שהניקוי באמת עבד לפני שהוא מאשר אותו לפרסום.

## פלטים

| קובץ | תוכן |
|---|---|
| `data/catalog.json` | כל קובץ מדיה + EXIF + סימון כפילות |
| `data/projects.json` | רשומה לכל פרויקט/תיקייה |
| `data/ORGANIZE.md` | דוח סדר: כפילויות, תיקיות זבל, חורים במטא-דאטה |
| `data/sites.json` | אתרים פיזיים לפי GPS |
| `data/stories.md` | סיפורי לפני/אחרי מדורגים |
| `data/publish/<id>/` | נכסים מוכנים לפרסום, נקיים ממטא-דאטה |

**כל מה שתחת `data/` פרט ל-`publish/` הוא פנימי** — מכיל שמות לקוחות וקואורדינטות. לא לשתף.
