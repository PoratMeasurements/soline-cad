# מדידת רצפה ותקרה מתחנת-חצובה — Leica DISTO X6 + DST 360-X

> מסמך-תכן (research + design). **קריאה-בלבד — אין שינויי-קוד.** נכתב 2026-08-24.
> מטרה: להפוך את סקר-המישוריות הקיים (height-only, `FloorLevelSolver`) ל**סקר-תחנה מלא בסגנון תחנה-טוטאלית** — נקודות XYZ אמיתיות ממדידה מתחנה-קבועה על חצובה, התאמת **מישור-דאטום** best-fit, ודיווח סטייה (גבוה/נמוך במ"מ) + שיפוע-כללי + גובה רצפה-לתקרה.
>
> **הנחת-החומרה:** X6 מורכב על מתאם **DST 360-X** על חצובה. המתאם מוסיף את הזווית-האופקית (azimuth) שכבר פוענחה ומגיעה ב-`Reading.hAngleDeg` (char `3ab1010f`, float32 LE ברדיאנים). כל מדידה נותנת שלישייה: **(slant distance, hAngle, vAngle)** = קואורדינטות-קוטב כדוריות מהתחנה. זה בדיוק מה שתחנה-טוטאלית עושה.

## 0. תקציר-מנהלים (מה מומלץ)

- **השיטה:** תחנה-בודדת קבועה על חצובה. יורים N נקודות על הרצפה ו-N על התקרה; כל ירייה → נקודת XYZ במערכת-התחנה דרך המרה כדורית→קרטזית. מתאימים **מישור-דאטום best-fit** (least-squares / PCA) לענן-הנקודות, ומדווחים לכל נקודה את המרחק-הניצב מהמישור (± מ"מ), את שיפוע-המישור הכולל (mm/m ואחוז), ואת המפתח רצפה↔תקרה.
- **למה best-fit ולא נקודת-0 יחידה:** נקודת-ייחוס יחידה (המצב הנוכחי) רגישה — אם ה-0 יושב על גבשושית, כל החדר "נמוך". מישור best-fit מבטל את הרעש הזה ונותן את **מדד-המישוריות האמיתי (TIR — Total Indicated Runout)** בדיוק כפי שעושים בתעשיית ה-FF/FL.
- **דיוק:** X6 ±1.0 מ"מ מרחק, tilt ±0.2°. הגורם-המגביל הוא **שגיאת-הזווית × המרחק** (0.2° ≈ 3.5 מ"מ ל-1 מ' אופקי). לכן: תחנה מרכזית, זוויות-נטייה מתונות, וממוצע-נקודות. חדר טיפוסי 4×4 מ' → 25–36 נקודות רצפה נותנות מפת-מישוריות אמינה.
- **אינטגרציה:** המודל הקיים `level_points` (x, y, rawMm, deviationMm, isZero) **כמעט מספיק** — צריך תוספת שדה `z` (מיגרציה 4) ופונקציית-fit חדשה `DatumPlaneSolver`. `LevelGrid` ו-`FloorLevelSolver` נשארים; מוסיפים מסלול-fit על-גביהם.

## 1. השיטה — המתמטיקה (distance + hAngle + vAngle → XYZ → מישור-דאטום → סטיות)

### 1.1 מודל-התחנה (station frame)

מרכז-המדידה של ה-X6 קבוע בחלל כל עוד החצובה לא זזה. הוא הראשית `O=(0,0,0)` של **מערכת-התחנה**. כל ירייה מחזירה קואורדינטות-קוטב כדוריות:

| סמל | מקור ב-`Reading` | משמעות |
|---|---|---|
| `d` | `distanceMm` | מרחק-אלכסוני (slant range) מהמרכז לנקודה |
| `φ` (phi) | `hAngleDeg` | זווית-אופקית (azimuth) מ-DST 360-X, סביב ציר-ה-Z האנכי |
| `θ` (theta) | `vAngleDeg` | זווית-נטייה אנכית (inclination), 0=אופקי, +מעלה |

> **חשוב על מוסכמת-θ:** ה-DISTO מודד inclination **מהמישור-האופקי** (0° = אופקי, לא zenith). הנוסחאות למטה מניחות זאת. אם בכיול-שדה מתגלה שהמכשיר מדווח zenith (0°=מעלה), מחליפים `sin↔cos`. יש לאמת חד-פעמית מול משטח-ידוע (ראה §4.4).

### 1.2 המרה כדורית → קרטזית (הליבה)

מפרקים את הקרן. הרכיב-האופקי (טווח-בתוכנית) הוא `r = d·cos(θ)`. משם:

```
X = d · cos(θ) · cos(φ)     ← מזרח/מערב בתוכנית
Y = d · cos(θ) · sin(φ)     ← צפון/דרום בתוכנית
Z = d · sin(θ)              ← גובה מסומן מול המרכז (+מעלה, −מטה)
```

- **רצפה** (יורים למטה, θ<0) → Z<0, מתחת למכשיר.
- **תקרה** (יורים למעלה, θ>0) → Z>0, מעל המכשיר.
- ה-(X,Y) נותנים את **המיקום-בתוכנית האמיתי** של הנקודה — מה שחסר היום. כרגע הקוד שם `x = d·cos(θ)`, `y = 0` (§3), כלומר כל הנקודות על קו — אין מפה. עם `φ` מקבלים ענן-נקודות דו-ממדי אמיתי שאפשר לפרוש כמפת-חום.

זהו בדיוק מה שתחנה-טוטאלית מחשבת: `RZ = IZ + SD·cos(ZA)` וקואורדינטות-מישור מ-`horizontal angle + horizontal distance` — רק שאנו עובדים במערכת-תחנה יחסית (לא צריך גובה-מכשיר מוחלט; הוא מתבטל בהתאמת-המישור).

### 1.3 התאמת מישור-דאטום (best-fit plane)

לענן נקודות-הרצפה `{Pᵢ = (Xᵢ, Yᵢ, Zᵢ)}` מתאימים מישור `Z = aX + bY + c` (או, יציב יותר, מישור כללי `n·(P−C)=0`) שממזער את סכום-ריבועי המרחקים-הניצבים. שתי דרכים:

**(א) Least-squares על Z (פשוט, מהיר, מתאים למשטח כמעט-אופקי):**
פותרים את מערכת-הנורמל `3×3` עבור `(a,b,c)`:
```
minimize  Σ (aXᵢ + bYᵢ + c − Zᵢ)²
```
פתרון סגור (normal equations) על סכומי `ΣX², ΣXY, ΣX, ΣXZ …`. `a,b` = שיפועים בכיווני X,Y; `c` = גובה-המישור בראשית.

**(ב) PCA / eigenvalue (יציב, המומלץ):**
1. מרכז-הכובד `C = (1/N)ΣPᵢ`.
2. מטריצת-קווריאנס `M = Σ (Pᵢ−C)(Pᵢ−C)ᵀ` (3×3).
3. **הנורמל `n`** = הווקטור-העצמי של הערך-העצמי הקטן-ביותר (כיוון-השונות המינימלי).
4. המישור עובר ב-`C` עם נורמל `n`.

PCA עדיף כי הוא לא מתפוצץ כשהמשטח תלול ולא מטה את התוצאה לכיוון-Z. לחדר טיפוסי שתי השיטות כמעט זהות; נשתמש ב-PCA כברירת-מחדל.

### 1.4 סטייה לכל נקודה (המספר שמיכאל רוצה)

המרחק-הניצב-המסומן מהנקודה למישור-הדאטום:
```
devᵢ = n · (Pᵢ − C)          (מ"מ, מסומן ±)
```
- `dev > 0` → הנקודה **מעל** המישור (ברצפה: גבשושית/בליטה).
- `dev < 0` → הנקודה **מתחת** למישור (ברצפה: שקע).

מדדים מצטברים (בשפת ה-FF/FL וה-QC):
- **TIR (Total Indicated Runout)** = `max(dev) − min(dev)` — הפרש-המישוריות הכולל, המדד המקובל ל"כמה לא-ישר".
- **גבוה/נמוך קיצוני** = `max(dev)` (הגבשושית הגבוהה) ו-`min(dev)` (השקע העמוק).
- **RMS** = `√(Σdev²/N)` — חספוס ממוצע.

### 1.5 שיפוע-כללי (levelness) ומפתח רצפה↔תקרה

- **שיפוע (tilt) של המשטח** ביחס לאופק-האמיתי: מכיוון שציר-ה-Z של התחנה **כבר אנכי** (חיישן-ה-tilt מייחס ל-כבידה), הזווית בין נורמל-המישור `n` ל-`ẑ=(0,0,1)` היא שיפוע-הרצפה עצמו:
  ```
  slope = acos(|n·ẑ|)        →  mm/m = 1000·tan(slope)
  כיוון-השיפוע (fall line) = atan2(n_y, n_x)   ← "לאיזה כיוון החדר יורד"
  ```
  זה נותן גם "הרצפה יורדת 8 מ"מ/מ' לכיוון דרום-מזרח" — מידע קריטי לנגר/ריצוף. (השוואה לתקן: 1/8" ל-10' ≈ FL≈25.)
- **מפתח רצפה↔תקרה (גובה-חדר):** מתאימים מישור-רצפה ומישור-תקרה מאותה תחנה. הגובה בכל (X,Y) הוא `Z_ceil(X,Y) − Z_floor(X,Y)`. מדווחים גובה-מינימלי/מקסימלי/ממוצע ואת מפת-השונות (למשל "התקרה נמוכה ב-15 מ"מ בפינה הצפונית").

### 1.6 מדוע best-fit עדיף על נקודת-0 יחידה (המצב הנוכחי)

היום `deviation = Zᵢ − zeroZ` — כל התוצאה תלויה באיכות ירייה-אחת. אם ה-0 על גבשושית → כל החדר "נמוך" באופן מלאכותי, וה-TIR נשמר אבל ה-datum מוטה. מישור best-fit הוא ה-datum ה"הוגן" שממזער את סך-הסטיות — בדיוק העיקרון של **Best-Fit Flatness TIR** בתעשייה (מבטל את השפעת נקודות-הייחוס הגרועות). **נשמור תאימות-לאחור:** אפשר להציג סטייה מול best-fit *או* מול נקודת-0 ידנית (למשל גובה-סף-דלת קיים) — המשתמש בוחר את ה-datum.

## 2. זרימת-העבודה בשטח (on-site UX)

```
[1] הצבת-חצובה  →  [2] סימון-דאטום/אופק  →  [3] לכידת N נקודות-רצפה
                                                    ↓
[6] דוח + ייצוא ← [5] קריאה-חיה: מישוריות/שיפוע ← [4] לכידת N נקודות-תקרה
```

### שלב 1 — הצבת-התחנה (Set up tripod)
- מציבים את החצובה **מרכזית** בחדר ככל האפשר (ממזער מרחקים → ממזער את שגיאת-הזווית×מרחק). גובה נוח ~1.2–1.5 מ' כדי לירות גם למטה (רצפה) וגם למעלה (תקרה) בזוויות-נטייה מתונות.
- מוודאים חיבור-BLE ל-X6 + שה-DST 360-X פעיל (מסך מציג "hAngle חי" — דיאגנוסטיקה שכבר קיימת בכותרת המסך). **החצובה לא זזה עד סוף-הסקר** — הזזה פוסלת את מערכת-התחנה. אזהרה בולטת ב-UI.

### שלב 2 — סימון-דאטום / קליברציית-אופק (Mark datum)
- **אזימוט-אפס:** יורים ירייה-אחת לכיוון-ייחוס (למשל לאורך קיר ראשי / פינה) ולוחצים "קבע 0° אזימוט". כל ה-φ נמדדים יחסית אליו → התוכנית מיושרת עם החדר (לא עם כיוון-אקראי של המתאם).
- **דאטום-גובה:** שתי אפשרויות, המשתמש בוחר:
  1. **Best-fit אוטומטי** (מומלץ) — המישור ייגזר מהנקודות עצמן; אין צורך בירייה-מיוחדת.
  2. **דאטום-ידני** — יורים לנקודת-ייחוס ידועה (סף-דלת קיים, קו-מים של בנאי) ומקבעים אותה כ-0; שימושי כשצריך להתאים לגובה-קיים.
- אין צורך לדעת את גובה-המכשיר — הוא מתבטל בהתאמה (עובדים ב-Z יחסי).

### שלב 3 — לכידת נקודות-רצפה (Capture N floor points)
- **מצב-רשת מודרך (מומלץ):** `LevelGrid` כבר מייצר רשת-יעד כל 60 ס"מ בהיסט-קבוע מהקיר. המסך מראה את המפה עם הנקודה-הבאה מודגשת ("ירֵה לנקודה 7 — פינה צפ-מז"). המשתמש מכוון את ה-Point Finder (זום-4×) ולוחץ — הירייה נקלטת one-shot (המנגנון `armed/ts` שכבר קיים).
- **מצב-חופשי:** פשוט יורים לאן שרוצים; כל ירייה מוסיפה נקודת-XYZ. טוב לנקודות-חשד (סביב ניקוז, מפתן).
- כל ירייה מציגה מיד: מרחק/φ/θ גולמיים + ה-XYZ המחושב + הסטייה-הזמנית מול ה-best-fit-עד-כה (מתעדכן חי).

### שלב 4 — לכידת נקודות-תקרה (Capture N ceiling points)
- זהה, מתג "תקרה". אותה תחנה, אותו φ-אפס → הרצפה והתקרה באותה מערכת → מפתח-הגובה מחושב ישירות. (אפשר לדלג אם רק רצפה נדרשת.)

### שלב 5 — קריאה-חיה: מישוריות/שיפוע (Live readout)
- **מפת-חום** של הסטיות (ירוק ≤3 מ"מ, ענבר ≤10, אדום >10 — סף כבר קיים ב-`devColor`), נפרשת על מפת-החדר האמיתית (עכשיו אפשרי בזכות X,Y).
- **פס-סטטוס:** TIR נוכחי, שיפוע (mm/m + חץ כיוון-נפילה), נקודה-גבוהה/נמוכה, מס' נקודות.
- **אינדיקציית-איכות:** אזהרה אם זווית-נטייה תלולה מדי / מרחק גדול מדי (שגיאת-זווית גבוהה) או אם N קטן מדי לאמינות.

### שלב 6 — דוח + ייצוא
- טבלת-נקודות (idx, X, Y, dev±), סיכום (TIR/RMS/slope/מפתח-גובה), מפת-חום. נכתב ל-`.sol` (§3) → הממיר יכול לרנדר תוכנית-מישוריות ב-HTML/DXF/PDF.

### 3.1 מה כבר קיים ומתאים

| `ui/level/LevelSurveyScreen.kt` | קליטת-ירייה one-shot, נקודת-0, רשימה | מרחיב: קורא גם `hAngleDeg`, מחשב XYZ, מציג מפה+TIR+שיפוע. |

| `ui/AppUi.kt` · `LevelHost` | route קיים לרצפה/תקרה | מזרים `z` ב-callbacks. |

### 3.2 הרכיב החדש — `geometry/DatumPlaneSolver.kt` (pure-Kotlin, בלי Compose)
מקביל ל-`StationSolver`/`FloorLevelSolver`. אחראי על:
```kotlin
object DatumPlaneSolver {
  data class P3(val x: Double, val y: Double, val z: Double)
  // 1.2 — המרה כדורית→קרטזית
  fun toXYZ(distanceMm: Double, hAngleDeg: Double?, vAngleDeg: Double?): P3
  // 1.3 — PCA best-fit; מחזיר centroid + normal
  data class Plane(val cx:Double, val cy:Double, val cz:Double,
                   val nx:Double, val ny:Double, val nz:Double)
  fun fitPlane(points: List<P3>): Plane
  // 1.4 — סטייה ניצבת מסומנת
  fun deviation(p: P3, plane: Plane): Double
  // 1.5 — שיפוע כללי + כיוון-נפילה
  data class Slope(val mmPerM: Double, val fallDirDeg: Double, val tiltDeg: Double)
  fun slope(plane: Plane): Slope
  // מדדים מצטברים
  data class Stats(val tir:Double, val hi:Double, val lo:Double, val rms:Double, val n:Int)
  fun stats(devs: List<Double>): Stats
  // 1.5 — מפתח רצפה↔תקרה בנקודת (x,y)
  fun gap(floor: Plane, ceil: Plane, x: Double, y: Double): Double
}
```
כשה-`hAngleDeg==null` (X6 בלי מתאם / D2) — `toXYZ` נופל חזרה ל-(H, 0, Z) של היום, וה-fit מתנוון לפרופיל-1D. כך הפיצ'ר עובד בשני המצבים ומשתדרג אוטומטית כשהמתאם מחובר.

### 3.3 כתיבה ל-`.sol` וגשר-לממיר
- `export/SolWriter.kt` כבר כותב room-json נייטיב; מוסיפים בלוק `levelSurvey: { floor:{points[], plane, stats}, ceiling:{…} }` עם ה-XYZ, הסטיות והמדדים.
- הממיר (`readSol.js` + מנוע-ההדמייה `viz_engine.js`) יכול לרנדר תוכנית-מישוריות (מפת-חום) ב-HTML/DXF/PDF — עקבי עם הצנרת הקיימת.

## 4. דיוק והנחיית-מספר-נקודות

### 4.1 תקציב-שגיאה (error budget)
| מקור | גודל | השפעה על Z/סטייה |
|---|---|---|
| מרחק X6 | ±1.0 מ"מ (טוב), ±2.0 (קשה) | ישיר, קטן |
| tilt (vAngle) | ±0.2° | `dZ ≈ d·cos θ · Δθ` → **ל-3 מ' אופקי: ±10 מ"מ** אם θ גדול; קטן כשθ≈0 |
| hAngle (DST 360-X) | תלוי-מתאם (~±0.1–0.3°) | משפיע על X,Y (מיקום-בתוכנית) — לא על הגובה. סטיית-מישוריות עמידה יחסית. |
| תזוזת-חצובה | חייבת 0 | קריטי — כל תזוזה מזייפת את כל הסקר |

**המסקנה המעשית:** הגורם-השולט הוא **שגיאת-הזווית × המרחק**. לכן:
1. **תחנה מרכזית** — ממזער מרחקים (מחצית-אלכסון-החדר במקום כל-האלכסון).
2. **זוויות-נטייה מתונות** — ירייה תלולה לרצפה קרובה עדיפה על ירייה שטוחה-ורחוקה. חדר גדול → 2 תחנות ואיחוד (עתידי, §5).
3. **ממוצע-נקודות** — ה-best-fit ממצע רעש; יותר נקודות = מישור יציב יותר.
4. **אימות-θ חד-פעמי** (§4.4) לפני-הסתמכות.

### 4.2 כמה נקודות? (point-count guidance)
מבוסס על עקרון ASTM E1155 (34 מדידות ל-1000 ft² ≈ 93 m² → ~1 נקודה ל-2.7 m²), מותאם לחדרי-Soline:
| שימוש | צפיפות | חדר 4×4 מ' |
|---|---|---|
| בדיקת-שיפוע גסה (levelness) | פינות + מרכז | 5–9 נקודות |
| מפת-מישוריות אמינה (מומלץ) | רשת ~60 ס"מ (`LevelGrid` ברירת-מחדל) | **25–36 נקודות** |
| QC מחמיר / משטח-בעייתי | רשת ~40–50 ס"מ + נקודות-חשד | 50+ נקודות |
- לרצפה ולתקרה בנפרד. מינימום מוחלט להתאמת-מישור: **3 נקודות** (אז אין יתירות → אין ביקורת-איכות); מומלץ ≥8 לקבלת RMS משמעותי.

### 4.3 מגבלות
- **תחנה-בודדת** מכסה קו-ראייה בלבד — פינות מוסתרות/מאחורי-עמוד לא נמדדות. פתרון: תחנה שנייה (§5).
- דיוק יורד עם המרחק ועם זווית-נטייה תלולה — לתייג נקודות "מרחק/זווית גבוהים" באדום-אזהרה.
- משטחים מבריקים/כהים → X-Range Power עוזר אך לא תמיד; לתעד "no-return".

### 4.4 אימות-שדה חובה (open item מה-HANDOFF §5)
לפני-הסתמכות: מדידה מבוקרת מול משטח-ידוע (למשל לוח-ישר עם shim ידוע), לאמת ש-(א) מוסכמת-θ נכונה (sin/cos), (ב) הסטייה תואמת את ה-shim, (ג) hAngle נותן X,Y יציבים בסיבוב-המתאם. זה ה-gate ש-Michael ביקש ("לא תואם ללייקה").

## 5. תכנית-מימוש (מה לבנות באפליקציה)

**שלב א — ליבה מתמטית (בלי-UI, בר-בדיקה מיידית):**
1. `geometry/DatumPlaneSolver.kt` — `toXYZ` (כדורי→קרטזי עם φ), `fitPlane` (PCA 3×3 eigenvector), `deviation`, `slope`, `stats`, `gap`. Pure-Kotlin, מקביל ל-`StationSolver`. **בדיקות-יחידה** על ענן-סינתטי (מישור-נטוי ידוע → מוודא slope+dev).
2. הרחבת `FloorLevelSolver` (או ניתוב אליו) כך שההמרה-המלאה חיה במקום-אחד.

**שלב ב — נתונים:**
3. `LevelPointEntity` + שדה `z` · `SolineDatabase` **MIGRATION_3_4** (`ALTER TABLE level_points ADD COLUMN z REAL NOT NULL DEFAULT 0`).
4. `SolineDao`/`Repo` — `addLevelPoint(... z ...)`; אופציונלי `datumMode` (best-fit / manual-zero) per-surface.

**שלב ג — UI:**
5. `LevelSurveyScreen` — לצרוך `hAngleDeg`, לחשב XYZ, לשמור z. פס-סטטוס חי: TIR / slope+חץ / hi-lo / N. אזהרת "חצובה-לא-זזה" + "hAngle חי".
6. **מפת-חום** על מתאר-החדר (`WallBuilder.layout` כבר נותן את המתאר; הנקודות עכשיו ב-X,Y אמיתי) — Canvas Compose, צביעה ב-`devColor`.
7. מצב-רשת-מודרך: להראות יעדי-`LevelGrid` ולהדגיש את הבא-בתור.

**שלב ד — ייצוא ואימות:**
8. `SolWriter` — בלוק `levelSurvey` ל-`.sol`; גשר-ממיר לרינדור מפת-מישוריות.
9. **אימות-שדה** (§4.4) מול משטח-ידוע → לנעול מוסכמת-θ ולסגור את ה-open-item מה-HANDOFF.

**הרחבות-עתיד (מחוץ-לגל-זה):**
10. **ריבוי-תחנות** — איחוד סקרים משתי-תחנות דרך נקודות-ייחוס משותפות (הבסיס קיים ב-`Trilateration.twoCircleIntersection` + `StationSolver` §7.6 anchor-relocation).
11. אינטגרציה עם מדד-FF/FL פורמלי אם יידרש ללקוחות-QC.

### סדר-עדיפויות מומלץ
`DatumPlaneSolver` + בדיקות (שלב א) → מיגרציה+repo (שלב ב) → חיווט-UI בסיסי עם TIR/slope (שלב ג 5) → **אימות-שדה** (שלב ד 9, gate) → מפת-חום ורשת-מודרכת → ייצוא-`.sol`.
