# Soline Measurement Engine (v0)

מנוע המדידה — הליבה של מה שהמודד עושה בשטח: **בונה חלל מאלמנטים**, המנוע **בונה את המתאר
במדויק**, ומריץ **בקרות שמונעות טעות** לפני שהיא הופכת ללוח חתוך לא נכון.

**ללא תלויות** — Node טהור. רץ ישירות (גם מ-Google Drive).

## הרצה
```bash
node demo.js
```
מדפיס דו״ח בקרה לשני תרחישים וכותב `out/control-report.html` (תצוגה).

## שלושת החלקים

### 1. ספריית אלמנטים · `src/elements.js`
אוצר המילים שהמודד "מניח" — לא נקודות גולמיות אלא אלמנטים סמנטיים, כל אחד עם המקורות
(X6/D2/Manual) לאימות צולב:
`wall` (אורך, גובה, זווית-פינה) · `opening` (חלון/דלת/מעבר) · `service` (חשמל/מים/ניקוז/גז/מפסק/תקשורת) ·
`obstacle` · `clearance` (מרווח אנכי) · `diagonal` (אלכסון בקרה).

### 2. לוגיקת בניית חלל · `src/space.js`
**טרברס:** מנקודת התחלה ומזימוט, כל קיר מונח לפי אורכו, ואז הכיוון מסתובב לפי הזווית בפינה.
המנוע מחשב: קודקודים, **שגיאת סגירה**, סכום זוויות, שטח והיקף, מיקום עולמי של פתחים/שירותים,
ואלכסונים מחושבים. `createSpace()` הוא builder שקורא כמו זרימת העבודה של המודד.

### 3. מנוע הבקרה · `src/controls.js`  ← "שלא יטעה"
כל בדיקה מחזירה עובר/נכשל + **הודעה בעברית שאומרת בדיוק מה למדוד שוב**:

| בקרה | מה היא תופסת |
|---|---|
| **אימות צולב** | שני מכשירים לא מסכימים על מידה קריטית |
| **סגירת מתאר** | המתאר לא חוזר לנקודת ההתחלה — קיר/זווית שגויים |
| **סכום זוויות** | Σ הזוויות ≠ (n−2)·180 — זווית נמדדה שגוי |
| **אלכסון בקרה** | אלכסון נמדד ≠ אלכסון מחושב — צורת חדר שגויה |
| **התאמת פתחים** | פתח חורג מהקיר או חופף פתח אחר |
| **סבירוּת** | אורך/גובה/זווית מחוץ לטווח פיזי |
| **עקביות מרווח** | קפיצה לא-סבירה במרווח לתקרה |
| **שלמות** | חסר קיר/גובה/מרווח/אלכסון |

## הלקח המרכזי (מהדמו)
בתרחיש השגיאה, המודד קרא את W3 קצר ב-60 מ״מ — ו**שני המכשירים "הסכימו"** (כיוון לנקודה
שגויה פעמיים). **האימות הצולב עבר.** אבל **סגירת המתאר (60 מ״מ) והאלכסון (48.6 מ״מ) תפסו את
הטעות.**

> אימות צולב בין מכשירים לבדו לא מספיק — הוא לא תופס טעות כיוון שיטתית. הבקרות הגאומטריות הן
> שכבת ההגנה. זה כל הרעיון של "שהמודד לא יטעה".

## ספריית האלמנטים (DXF Master Database) · `src/catalog.js`
מסד הנתונים שהמודד בוחר ממנו בשטח **מה למדוד**, נגזר ממסמך האפיון — **145 אלמנטים, 4 חלקים**
(חשמל · אינסטלציה · דלתות/חלונות · בנייה/תקרות/מיזוג). לכל אלמנט: חלק/קטגוריה, פאזה (שלד/גמר),
מאחז (קיר/רצפה/תקרה), מידות/וריאנטים, ו**שיטת מיקום** (`locateBy`) — הלב של "מרכזים/היסטים":

| locateBy | איך המודד ממקם | דוגמאות |
|---|---|---|
| `point` | מרכז — היסט לאורך המאחז + גובה | שקע, ספוט, ניפל, קופסה |
| `array` | מרכז ראשון + כמות + **מרווח מרכזים** | רצף קופסאות (71 מ״מ), שורת ספוטים |
| `span` | התחלה→סוף (היסטים) | צנרת, פרופיל לד, תעלה |
| `opening` | היסט מפינה + רוחב (+גובה, סף) | דלת, חלון, נישה |
| `area` | מרכז + רוחב×עומק | קופסת רצפה, קסטת מיזוג |

`src/placement.js` פותר מיקום → קואורדינטות עולמיות מול הגאומטריה, ו**מוודא** שהאלמנט יושב בתוך
המאחז (היסט+רוחב ≤ אורך קיר), בגובה חוקי, ושמערך לא חורג — כך מיקום שגוי נתפס.

`gen-picker.js` מייצר את **בורר האלמנטים בשטח** (`out/picker.html`) מהקטלוג — המודד בוחר → רואה
את שיטת המיקום → ממלא מרכז/היסט/גובה → מוסיף לרשימת המדידה.

## מבנה
```
src/catalog.js   → ספריית האלמנטים (145 אלמנטים, מיקום לפי מרכז/היסט)
src/placement.js → מיקום אלמנט בחלל + ולידציית התאמה
src/elements.js  → פרימיטיבים לבניית החלל (קיר/פינה/פתח/שירות…)
src/space.js     → טרברס + גאומטריה
src/controls.js  → מנוע הבקרה + הודעות
src/render.js    → SVG של החלל
demo.js          → תרחיש תקין + שגיאה → out/control-report.html
gen-picker.js    → בורר אלמנטים → out/picker.html
```
