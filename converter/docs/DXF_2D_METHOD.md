# שיטת בניית DXF 2D (תכנית מדידה) — לימוד מקבצי-ייחוС מקצועיים

מסמך-לימוד לבניית ממיר **ORDX → DXF-2D** ברמת הייחוС. נחקרו קבצי-2D אמיתיים
משלוש התיקיות (מדידות-HD, פורמג'ו, אדור קונספט), עם **קורלציה ישירה ORDX↔DXF**
בתיקיית "אדור קונספט" (שם קיים ORDX וגם DXF לאותו פרויקט). מסמך זה משלים את
`DXF_REFERENCE_STUDY.md` — ההוא ניתח את קבצי ה-`_3D` (גאומטריית 3DFACE טהורה),
כאן מנותחת **תכנית ה-2D** (מבט-על + חזיתות), שהיא לב תכנית-המדידה: קווי-מידה,
סמלים, מקרא וטקסט.

> כל הקואורדינטות ב-**מ"מ**, ציר Y **הפוך** (ערכים שליליים כלפי מטה) — בדיוק כמו
> `placement.js` (`PDP_y = -py`). כל **המספרים בטקסט המידות** מוצגים ב-**ס"מ**
> (מ"מ מחולק ל-10): קיר 3609 מ"מ → הטקסט `"360.9"`.

הקובץ שנותח לעומק לקורלציה:
`אדור קונספט/…/מספרה קרית מוצקין/מטבחון/KITCHEN_Ktchn_ADORE-CONCEPT_Hen_DR1.dxf`
(+ ה-ORDX התואם באותה תיקייה). קבצי-אימות נוספים: HD (`gili-shaked…DR2`,
`Shohat-N8…DR1/DR2`), פורמג'ו (`guy-zada-kitchen…DR1`), אדור-בַּאת' (`BATH2…DR1`).

## 0. שני מבטי-2D: DR1 ו-DR2

לכל פרויקט יש עד שני קבצי-2D (אין להם `_3D` בשם):
- **`_DR1`** = **תכנית מבט-על** (plan / מבט מלמעלה) — קירות במבט-על, מיקום אביזרים,
  מידות-רוחב ומידות-מיקום אופקיות.
- **`_DR2`** = **חזית / פריסת-קיר** (elevation) — אותה אוצר-מילים של ישויות, אבל
  מדגישה **גבהים** (`H …`), רוחבי-חזית של ארונות וקווי-הנמכת-תקרה.

שניהם 2D ומשתמשים באותן שכבות/ישויות. הזיהוי בטקסטים: DR1 → "רוחב נמדד עד דלת";
DR2 → "רוחב חזית ארון", "גובה כללי בחזית ארונות". **המימוש הראשון צריך לכוון ל-DR1**
(מבט-על) — הוא הנגזר הישיר מגאומטריית ה-ORDX (קירות + מיקומי-אביזרים).

## 1. מבנה-על וגרסת-קובץ

**שני דיאלקטים של DXF** נצפו — לפי גרסת התוכנה שייצאה:

| מאפיין | R12 (אדור, פורמג'ו) | AutoCAD-2000+ (HD החדשים) |
|---|---|---|
| `$ACADVER` | `AC1009` | `AC1015`+ |
| סקשנים | `HEADER, TABLES, ENTITIES, BLOCKS` | `+CLASSES, OBJECTS, ACDSDATA` |
| קידוד עברית | `$DWGCODEPAGE = ansi_1255` (Windows-1255) | **UTF-8** (בלי code 1255) |
| שמות שכבות | `Const_Walls` / Portuguese | `CONST_WALLS` (UPPER) |
| INSERT | code 2 + 8 + 10/41/42/50 | + `100 AcDbBlockReference` |

> **קריטי לפרסינג/כתיבה:** בקבצי R12 הטקסט העברי ב-**cp1255** (בייט 0xE0–0xFA =
> א–ת). בקבצי 2000+ הטקסט ב-**UTF-8**. המייצא צריך לבחור קידוד לפי גרסת-היעד.
> ההמלצה: לייצא **R12 + ansi_1255** (הפורמט הפשוט והנפוץ בקבצי הייחוС של אדור/פורמג'ו).

### HEADER (R12, מקובץ אדור)
```
$ACADVER      AC1009
$INSBASE      0,0,0
$EXTMIN       2289.29 , -5482.98 , 0.0     ← תיבת-היקף אמיתית (חובה ל-ZOOM Extents)
$EXTMAX       10646.17 ,  2391.43 , 0.0
$DWGCODEPAGE  ansi_1255
$LTSCALE      10.0
$LIMMIN       0,0
$LIMMAX       2000,200
```
סדר הסקשנים ב-R12: **HEADER → TABLES → ENTITIES → BLOCKS** (שים לב: ENTITIES
לפני BLOCKS — הפוך מהסדר הנפוץ, אך תקין. הפרסר חייב לקרוא BLOCKS גם אם מוגדר אחרי).

### TABLES
- **VPORT** `*ACTIVE` — view ברירת-מחדל.
- **LTYPE** — `CONTINUOUS` (+`HIDDEN` בחלק מהקבצים).
- **LAYER** — 30–38 שכבות סמנטיות (ר' §2).
- **STYLE** `STANDARD` — `40=10.0 41=1.0 50=0.0 71=0`, פונט (בד"כ Arial/ריק).
  גובה-הטקסט בפועל נקבע בכל ישות TEXT (code 40), לא ב-STYLE.

## 3. מימוד — הלב של תכנית-המדידה  ⭐

**אין ישויות `DIMENSION`** בשום קובץ-ייחוС. **כל קו-מידה מורכב ידנית** מ-
`LINE` + `SOLID` + `TEXT`. זו התובנה הכי חשובה למייצא. אנטומיה של מידה-אופקית אחת:

```
מידה בודדת = 2× LINE (קווי-הארכה/extension)      ← אנכיים מפינות המדידה
           + 1× LINE (קו-המידה/dimension line)   ← אופקי, מחבר ביניהם
           + 2× SOLID (ראשי-חץ)                   ← משולשים מלאים בקצוות
           + 1× TEXT  (המספר בס"מ)                ← ממורכז מעל קו-המידה
```

היחס הנצפה בכל השכבות מאשר זאת: על `Dim_Wall` נספרו **30 LINE : 20 SOLID : 10 TEXT**
(≈ 3 קווים + 2 חצים + 1 טקסט לכל מידה). אותו יחס ב-`Electrical_DIM`
(18:12:6), `Plumbing_DIM`, `Dim_Overall` (6:4:2).

### דוגמה קונקרטית (קיר 1 בקובץ אדור, אורך 3609 מ"מ):
```
LINE  (8349,-2440)→(8349,-2050)   ← קו-הארכה מפינת-קיר, יוצא 390 מ"מ החוצה
LINE  (4740,-2440)→(4740,-2050)   ← קו-הארכה מהפינה השנייה
LINE  (8349,-2050)→(4740,-2050)   ← קו-המידה (המרחק הנמדד = 3609 מ"מ)
SOLID …×2                          ← ראש-חץ בכל קצה
TEXT  h=104.67 "360.9"            ← 3609/10, ממורכז
```
לקירות **אלכסוניים** קווי-ההארכה ניצבים לקיר (זוג משופע): למשל קיר-2 בזווית 271.5°
מקבל מידה `"250"` עם קווי-הארכה משופעים ל-(9413,-4913)/(9347,-2414).

### טקסט-מידה: גובה, סיבוב, ערך
- **גובה** (code 40): קבוע לכל המידות בקובץ (למשל `104.67` באדור, `34.71` ב-HD) —
  נגזר מקנה-המידה של השרטוט. הערות-טקסט חופשיות לרוב נמוכות יותר (78.5 / 72).
- **סיבוב** (code 50): `0`=אופקי, `90`=אנכי, וזווית-הקיר למידות אלכסוניות
  (למשל `-88`, `316`). הטקסט מיושר לאורך קו-המידה.
- **ערך**: מ"מ→ס"מ עם עד ספרה עשרונית (`"360.9"`, `"250"`, `"265"`, `"131"`).

### שכבות-מידה לפי דיסציפלינה
- `Dim_Wall` — **אורך + גובה קיר** (`"360.9"`, `"265"`).
- `Dim_Overall` — מידת-על מקצה-לקצה (`"367.4"`, `"249.9"`) — צבע שלילי = **כבויה**
  בברירת-מחדל (המודד מדליק לפי-צורך).
- `{discipline}_DIM` — **מיקום** האביזר לאורך הקיר (מרחק מפינה, בס"מ).
- `{discipline}_H` — **גובה-התקנה**, טקסט בפורמט `"H 62"`, `"H 110"`. ב-HD גם
  יחסי-datum: `"H 0-231"` (231 מתחת ל-0), `"H 0+332"` (332 מעל), ומחרוזות-מצטברות
  `"H 120+118.8+93.2"`.
- `Dim_Angles` / `_Auto` — זווית בין קירות, טקסט `"91.5°"` (התו ° = 0xB0).

## 4. קירות — קו-כפול + מילוי SOLID

קיר במבט-על = **שני קווים מקבילים** (פנים/חוץ) + **מילוי-poché** ביניהם:
```
LINE [Const_Walls]      (4740,-2440)→(8349,-2440)   ← פאה פנימית (צד-החדר)
LINE [Const_Walls_Ext]  (4740,-2340)→(8446,-2340)   ← פאה חיצונית (מוסטת בעובי 100)
SOLID [Const_Fill] 62=253  4 פינות                  ← מילוי אפור בין שתי הפאות
```
- **העובי** = המרחק בין שתי הפאות = `Dimensions/Thick` מה-ORDX (100 מ"מ בדוגמה).
- ה-`Const_Fill` SOLID הוא מרובע דק לאורך הקיר (poché). לקיר אלכסוני ה-SOLID עוקב
  אחרי הזווית (פינות (8446,-2340)/(8514,-4937)/(8349,-2440)/(8414,-4939)).
- **פתחי דלת/חלון**: לא "חותכים" בקיר במפורש — הם מוכנסים כ-INSERT (§5) על השכבה
  `Const_Doors`/`Const_Windows`, והקו נשבר סביבם.

## 5. סמלי-אביזרים — INSERT של בלוקי-2D

כל אביזר = **INSERT** להפניה לבלוק, על **שכבה סמנטית** (הקובעת צבע), עם מיקום/סיבוב.
הבלוקים הם **ציורי-קו/קשת 2D טהורים** (LINE+ARC) — **בלי TEXT מוטמע** (גם ב-`_HEB`;
הכיתוב העברי חי רק במקרא, §6).

### בלוקים נצפים (2D — שונים לגמרי מבלוקי-3DFACE של קבצי ה-3D!)
| בלוק | תוכן | שכבת-INSERT | תפקיד |
|---|---|---|---|
| `POWERLINE` | 6×LINE + 2×ARC | Electrical | קו-כוח / יציאת-חשמל |
| `SOCKET_HEB` / `DUPLEXSOCKET` | LINE+ARC | Electrical | שקע / שקע-כפול |
| `SWITCH_HEB` | 5×LINE + 4×ARC | Electrical | מפסק |
| `POWERBOX` | 15×LINE | Electrical | ארון/קופסת-חשמל |
| `WATERSUPPLY` | 16×LINE + 2×ARC | Plumbing | נקודת-מים |
| `FAUCET` | 10×LINE + 2×ARC | Plumbing | ברז |
| `SEWAGE` | 2×LINE + 2×ARC | Plumbing | ביוב/ניקוז |
| `GAS_HEB` | 21×LINE | Plumbing/HVAC | גז |
| `VENT` | 41×LINE | HVAC | פתח-איוורור |
| `BEAM` | 4×LINE | Misc | קורה |
| `WINDOW1` | 9×LINE | Const_Windows | חלון (יחידת 1×1) |
| `DOOR_HINGED_LEFT_OUT` | 3×LINE + 1×ARC | Const_Doors | דלת (קשת-פתיחה) |
| `SAFETYROOMENTRANCE` | 9×LINE + 4×ARC | Const_Doors | דלת ממ"ד |

### שני סוגי-הכנסה — ההבחנה הקריטית לקורלציה:
**(א) אביזר נקודתי (חשמל/מים/גז)** — סקאלה **אחידה קבועה**:
```
INSERT  8=Plumbing  2=Sewage
  10/20  8412.29 , -3529.58        ← מיקום (X , -Y) על הקיר
  41/42  9.086 , 9.086             ← סקאלה אחידה (גודל-סמל קבוע ~קטן)
  50     91.5                       ← סיבוב = זווית-הקיר
```
**(ב) פתח (דלת/חלון)** — בלוק-יחידה **מתוח לרוחב האמיתי**:
```
INSERT  8=CONST_WINDOWS  2=WINDOW1
  41   823.7    ← סקאלת-X = רוחב-החלון במ"מ (=82.37 ס"מ)
  42   25.0     ← סקאלת-Y = עובי-הקיר/החלון
  50   90.0     ← סיבוב = זווית-הקיר
```
כלומר **רוחב-הפתח מקודד בסקאלת-X (41)**, עובי-הקיר ב-Y (42), וזהות-הבלוק מקודדת
צד-ציר וכיוון-פתיחה (`DOOR_HINGED_LEFT_OUT`, `..._RIGHT_IN` וכו').

## 6. מקרא (Legend), טקסט וכותרת

### מקרא — `Text_Legend`
צמד של **סמל + שם עברי** לכל סוג-אביזר שמופיע בשרטוט. הסמל = ARC/LINE קטנים
(swatch), השם = TEXT לצדו. דוגמאות שנקראו: `ביוב`, `נקודת מים`, `צ חשמל`,
`ק חשמל`, `מפסק`, `גז`, `שקע כפול`, `קורה`, `פתח איוורור תקרה`. (ב-HD: 6–19 ARC +
עד 96 LINE במקרא — הוא מפורט.)

### הערות-שדה — `Text` (+ leader lines)
TEXT עברי חופשי + קווי-מוביל (LINE על אותה שכבה). זה הערך המקצועי של המדידה —
הערות כמו: "מטבחון ברוחב 170 ס\"מ", "רוחב כללי לצורכי שרטוט", "רוחב נמדד עד דלת",
"גובה לא סופי חסר פלטות גבס וגמר צבע בתקרה", "לא ניתן להגיע לצינורות", "בסמוך לניקוז
יש צינורות מים", "מרכזיית מים", "עומק עמוד חשוף - עמוד ממשיך פנימה". התוכנה **לא**
מייצרת אותן — המודד מוסיף ידנית. המייצא שלנו יכול לפחות לייצר את השכבות והמבנה.

### מספר-אזור — `Text_AreaNo`
טקסט קצר `"P.1"` — מזהה הקיר/אזור בתכנית.

### תוויות-קיר — `Text`
`"W 1.1"`, `"W 1.2"` — מספור קירות (Wall number מה-ORDX → `W {room}.{wall}`).

### עברית
R12: `$DWGCODEPAGE=ansi_1255` + פונט Arial. 2000+: UTF-8. אין `\U+` unicode-escapes
בקבצי ה-2D (בניגוד לחלק מקבצי ה-3D) — טקסט-בייטים ישיר בקידוד-הקובץ.

## 7. טבלת קורלציה  ORDX → DXF-2D  ⭐ (מאדור: KITCHEN_Ktchn_…_DR1)

ה-ORDX שנפרס (`src/parseOrdx.js`): 1 חדר, 2 קירות, 4 furnishings
(2×Power Line, 1×Water Supply, 1×Sewage). כך כל אלמנט התגלגל ל-DXF-2D:

| אלמנט ORDX | שדות-מקור | ייצוג ב-DXF-2D | שכבה / ישות |
|---|---|---|---|
| **קיר** | `Position.StartX/Y,EndX/Y` | קו-כפול פנים+חוץ + מילוי | `Const_Walls`+`_Ext` LINE, `Const_Fill` SOLID |
| עובי-קיר | `Dimensions.Thick`=100 | מרחק בין שתי הפאות (100 מ"מ) | היסט הפאה החיצונית |
| **אורך-קיר** | `\|End-Start\|`=3609 מ"מ | מידה `"360.9"` (2 ext + dim + 2 חץ) | `Dim_Wall` LINE/SOLID/TEXT |
| **גובה-קיר** | `Dimensions.Height`=2650 | מידה אנכית `"265"` | `Dim_Wall` |
| **זווית בין קירות** | `Position.Angle`=271.5° | מידת-זווית `"91.5°"` | `Dim_Angles(_Auto)` ARC+LINE+SOLID+TEXT |

## 8. שלושת הפערים הגדולים בין הפלט שלנו לייחוС

1. **מימוד מורכב-ידנית (הפער הכי גדול).** הייחוС **לא משתמש ב-`DIMENSION`** אלא
   בונה כל מידה מ-`2×LINE(ext)+1×LINE(dim)+2×SOLID(חץ)+1×TEXT`, על שכבת-דיסציפלינה
   נכונה (`Dim_Wall`/`{disc}_DIM`/`{disc}_H`), עם גובה-טקסט אחיד, סיבוב לפי-כיוון,
   ראשי-חץ SOLID אמיתיים, וערך בס"מ. המייצא שלנו צריך **מנוע-מימוד** שמייצר את חמש
   הישויות לכל מידה — כולל מידות-מיקום-אביזר (מרחק-מקצה) ומידות-גובה (`H …`).

2. **סמלי-2D אמיתיים + שיוך-שכבה-דיסציפלינרי.** צריך **ספריית בלוקי-2D** (POWERLINE,
   SWITCH_HEB, WATERSUPPLY, FAUCET, SEWAGE, WINDOW1, DOOR_HINGED_*…) כציורי-קו/קשת,
   הכנסתם ב-INSERT על השכבה הנכונה (Electrical=6 / Plumbing=150 / …), עם ההבחנה בין
   סקאלה-קבועה (נקודתי) לסקאלה-לפי-רוחב (פתחים: 41=Width). היום אין לנו סט-סמלי-2D
   תואם ולא את חוקי-הסקאלה.

3. **קירות-poché + מקרא + הערות עבריות.** קיר = **קו-כפול פנים/חוץ + `Const_Fill`
   SOLID** (לא קו-בודד); צריך לחשב את הפאה החיצונית מהעובי ולמלא ביניהן. בנוסף חסרים
   **בלוק-מקרא** (`Text_Legend`: סמל+שם עברי לכל אביזר-בשרטוט) ותשתית **הערות-שדה**
   (`Text` + leader) — הערך המקצועי של תכנית-מדידה. לכל הפחות יש לייצר את השכבות,
   המקרא האוטומטי, ותוויות-הקיר (`W r.w`) ומספר-האזור (`P.n`).

### נספח: קידוד ובחירת-פורמט למייצא
- ייצא **R12 (`AC1009`) + `$DWGCODEPAGE=ansi_1255`** — הפורמט של רוב קבצי-הייחוС
  (אדור, פורמג'ו). כתוב עברית כבייטי-cp1255 (א=0xE0 … ת=0xFA), ° = 0xB0.

- טבלת LAYER מלאה (הצבעים ב-§2 חובה — הם מה שנותן לתכנית את המראה המקצועי).
- גובה-טקסט אחיד למידות (נגזר מקנה-המידה; ~35 לתכניות קטנות, ~105 לגדולות).
