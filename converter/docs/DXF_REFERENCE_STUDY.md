# מחקר קבצי-ייחוס DXF מקצועיים (ELC_SND / Raumplan → TRIO)

מסמך זה מתעד את הפורמט של קבצי הייחוס `*_3D.dxf` (206 קבצים בתיקיית טריו), שהם
פלט מקצועי של מערכת Raumplan/ELC_SND. המטרה: להביא את מייצא ה-DXF של Soline
לאותה רמת איכות. הקובץ שנותח לעומק:
`רונן אוזן - 2829\ozan_Ktchn_TRIO_Nir_DR1_3D.dxf` (79 KB, 10,410 שורות), עם השוואה
דגמית ל-`.pdp` התואם ולעוד קבצי ייחוס.

> כל הקואורדינטות במילימטרים. ציר Y **הפוך** (ערכים שליליים: `$EXTMIN.Y=-10048`,
> `$EXTMAX.Y=-511`) — בדיוק כפי ש-`placement.js` עושה `PDP_y = -py`.

## 4. BLOCKS — 8 בלוקים לאלמנטים חוזרים

כל אלמנט-אביזר שחוזר מוגדר **פעם אחת** כ-`BLOCK` (גאומטריית 3DFACE בקואורדינטות
מקומיות סביב הראשית, על שכבה `0`), ומוכנס פעמים רבות כ-`INSERT`. שמות הבלוקים:

```
GAS  ·  CONTROLBOX  ·  FAUCET  ·  LIGHTING  ·  SEWAGE  ·  SOCKET  ·  SWITCH  ·  DUPLEXSWITCH
```

מבנה כותרת בלוק:
```
  0
BLOCK
  8
0                 ← שכבת הבלוק
  2
GAS               ← שם הבלוק
 70
0                 ← דגלי בלוק (0 = רגיל)
 10/20/30
0.0 0.0 0.0       ← נקודת בסיס הבלוק
  0
3DFACE …          ← גאומטריה מקומית (עשרות 3DFACE, קואורדינטות קטנות ~ -3..20)
  0
ENDBLK
```

הגאומטריה בתוך הבלוק היא **מודל 3D מלא** של האביזר (למשל SOCKET = ~30 פאות היוצרות
קופסה + פרטים). כל הפאות על שכבה `0` — כך שצבע האביזר נקבע מ**שכבת ה-INSERT**
(`Electrical`/`Plumbing`) ולא מהבלוק. זו מוסכמה חשובה: בלוק אגנוסטי-לצבע, שכבה קובעת.

## 5. ENTITIES

### 5.1 קירות — `3DFACE` על `Const_Walls` / `Const_Walls_Ext`
כל קיר = תיבה מאורכת (פריזמה) הבנויה מפאות `3DFACE` אנכיות. דוגמה (קיר על
`Const_Walls`, גובה 0→3117):
```
  0
3DFACE
  5
13E5              ← handle (hex)
  8
Const_Walls
 10/20/30   896.35 , -5275.25 , 0.00      ← פינה 1 (רצפה)
 11/21/31   896.35 , -5275.25 , 3117.00   ← פינה 2 (תקרה)
 12/22/32   896.95 , -8124.14 , 3117.00   ← פינה 3 (תקרה)
 13/23/33   896.95 , -8124.14 , 0.00      ← פינה 4 (רצפה)
 70
15                ← דגל קצוות-בלתי-נראים (edge visibility)
```
סדר הקדקודים: מסביב לפאה (רצפה→תקרה→תקרה→רצפה). קיר-חוץ זהה אך על
`Const_Walls_Ext`. גובה הקיר מ-`$EXTMIN.Z=0` עד גובה הקיר (`Dimensions/Height`).

### 5.2 אביזרים — `INSERT`
כל אביזר מוכנס כהפניה לבלוק, על שכבה סמנטית, במיקום/סיבוב/קנה-מידה:
```
  0
INSERT
  5
0                 ← handle
  8
Electrical        ← שכבה סמנטית (קובעת צבע)
  2
DuplexSwitch      ← שם הבלוק (case-insensitive)
 10/20/30   -4379.897 , -5986.253 , 1220.0   ← נקודת הכנסה (X, -Y, Z=גובה התקנה)
 41/42/43   1.0 , 1.0 , 1.0                   ← קנה-מידה X/Y/Z
 50         89.919962                          ← סיבוב (מעלות, בכיוון הקיר)
```
`Z` של נקודת ההכנסה = **גובה ההתקנה** (mount height); `50` = זווית הקיר (מכיוון
`orientation` ב-placement, מחולק ל-10). שיוך בלוק→שכבה שנצפה: כל אביזרי החשמל
(Socket/Switch/DuplexSwitch/ControlBox/Lighting) על `Electrical`; ברז/ביוב
(Faucet/Sewage) על `Plumbing`.

> **אין ישויות TEXT** בקובצי ה-3D של הייחוס — הם קבצי גאומטריה טהורים. הטקסט/מקרא/
> ממדים חיים בשכבות `Text_*`/`Dim_*` שקיימות בטבלה אך ריקות בקובצי 3D אלה (הם
> מאוכלסים בגרסת ה-2D/תוכנית). המייצא החדש שומר את השכבות ומוסיף TEXT עברי אופציונלי.

## 7. חוזה-קלט למייצא החדש

`export_dxf_pro.js` מקבל **סצנה** מנורמלת (או מודל `parseOrdx` והוא בונה אותה):
```js
scene = {
  walls: [ { x1,y1,x2,y2, thick, height, exterior } ],       // מ"מ, לפני היפוך Y
  items: [ { name, category, x, y, z, rotation_deg, width, depth, height } ],
}
```
נבנה מ-`parseOrdx` דרך `placement.placeOnWall` (X/Y/orientation) + `Dimensions`
של הקיר. `exportDXF3DPro` → פריזמות + בלוקי-3DFACE. `exportDXF2DPro` → תוכנית
(קווי-קיר כפולים + בלוקי-סמל 2D + TEXT עברי). שניהם מפיקים HEADER/TABLES/BLOCKS/
ENTITIES תואמי-ייחוס, ובדיקה עצמית משווה סוגי-ישויות ושכבות מול הייחוס.

**סטיות מכוונות (לא-פערים):**
- **עברית ב-`\U+` ולא cp1255-bytes**: השיטה ממליצה בייטי-cp1255; אנו שומרים `\U+XXXX`
  כדי שכל הזרם יישאר 7-bit-ASCII (עקבי עם קבצי ה-3D ועם בדיקת ה-ASCII). AutoCAD R12
  מרנדר `\U+` תקין דרך `ARIAL.TTF`.
- **פירוט בלוקי-3D**: הבלוקים שלנו הם קומפוזיציית-קופסאות מכוילות לספירת-הפאות של
  הייחוס (SOCKET 30≈31, DUPLEXSWITCH 60=60, SWITCH 30=30, GAS 30≈28, FAUCET 42≈40,
  SEWAGE 42≈40, LIGHTING 24≈20, CONTROLBOX 12≈11). קופסאות אקסיס-אליינד ולא מודלים
  אורגניים — מוכר וסמנטית-נכון, סה"כ **294 מול 319** (92%).
- `STYLE` קוד `40=0` (גובה לא-קבוע) מול `10.0` בייחוס, כדי לכבד את גובה ה-TEXT הפרטני.
- קודי-קבוצה מיושרים-ימין; ארטיפקט `LAYER1` של הייחוס לא שוחזר.

**מה נסגר בסבב זה (2026-08-14):**
- ✅ **פירוט 3DFACE**: בלוקי-3D הועשרו לרמת-הייחוס (186 → **294 פאות**); חלונות
  כקופסאות-מלאות עם זיגוג פנימי (6 → 12 פאות/חלון).
- ✅ **מידת-מיקום אביזר** (`{disc}_DIM`): כל אביזר מקבל קו-מידה (5 ישויות) מפינת-הקיר,
  מ-`wallStartX/Y` שנשמר ב-`sceneFromModel` (23 מידות ב-2918: 18 חשמל + 5 אינסטלציה).
- ✅ **ספריית בלוקי-2D אמיתית**: `BLOCKS_2D` ייעודית עם `ARC` אמיתי + `LINE` (בלי TEXT).

**מה עוד חסר כדי להשתוות מלאה (אופציונלי):**
- מודלי-3DFACE אורגניים (לא קופסאות) לסגירת 25 הפאות האחרונות מול 319.
- **הערות-שדה** (`Text` + leader) ותוויות-קיר `W r.w` / מספר-אזור `P.n` — מבנה קיים,
