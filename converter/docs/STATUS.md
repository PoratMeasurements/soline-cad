## מבנה PDP שפוענח
- **Header**: magic, שם עבודה, לקוח, טלפon, משתמש (offsets משתנים בין גרסאות; בקבצי TRIO השם ב-0x2e).
- **קירות**: מספר קירות ב-`0xd2`, טבלה ב-`0xd4`, רשומה 14B `[x1,y1,x2,y2,thick,height,pad]` int16 מ"מ.
  (בפורמט int32 החדש — רשומה 22B, קואורדינטות int32.)
- **מספר אביזרים**: השדה מיד אחרי הקירות = `0xd4 + מספר_קירות×14`. = מספר רשומות "אינודרו".
- **רשומת אביזר (MEP)**: 173B. מידות = 3×int16 (W,depth,H) ב-offset יחסי 127/129/131.
- **טרנספורם קואורדינטות**: `PDP_x = ORDX_x + offX`, `PDP_y = −ORDX_y + offY` (ציר Y הפוך).
- **פורמט רציף (sequential)** — שינוי count בלי לעדכן את שאר הטבלאות ⇒ Raumplan "שגיאה 921".

## ✅ פוענח (2026-08-13): שדות המיקום ב-7 הבלוקים
**כל המיקום יושב ב-MEP record (block#0) בלבד. אין wall-index — אביזר נקשר לקיר לפי קרבה גאומטרית של X/Y לקו הקיר.**

מבנה רשומת MEP (173B, לשקע "שקע בודד"):
| offset | טיפוס | תוכן |
|---|---|---|
| +0x00 | int16 | **X בתכנית** (מ"מ). `PDP_x = ORDX_x + offX` |
| +0x02 | int16 | **Y בתכנית** (מ"מ). `PDP_y = −ORDX_y + offY` |
| +0x04 | int16 | **גובה התקנה (Z)**: `height_mm = value + 19960` (corr 1.000 על 11 שקעים/4 קירות). לא עוגן! |
| +0x0a | int16 | **קוד אוריינטציה** (0=קיר אופקי-ימין, 1797=אופקי-שמאל, 2697=קירות אנכיים) |
| +0x0c | byte | וריאנט/היפוך (2/3/5/6, משתנה גם באותו קיר) |
| +0x0e | int16 | **קוד סוג/קטלוג** (18=שקע; 11008=תאורה; 4107=חלון/דלת) |
| +0x28.. | CP1255 | "אינודרו" (@+0x28), שם (@+0x31), תיאור (@+0x5b) |
| +0xa1 | 3×int16 ×2 | **מידות אלמנט (W,depth,H) מ"מ**, פעמיים (+0xa1,+0xa7). ✅ **שולט בגודל האמיתי** ב-Raumplan (אומת: 400→40ס"מ). כרגע קטלוג 150/10/120; יש לכתוב מ-ORDX. |

**טרנספורם קואורדינטות** (נגזר מהתאמת אורכי קירות; הקירות מסודרים אחרת ב-PDP!):
לקובץ 2918: `offX=−22876, offY=−9480`. offX/offY לכל קובץ מטבלת הקירות (0xd4).

**מפתח חשוב לאסמבלר:**
- **block#1 (סמל 2D)** = תבנית מקומית 0..150, מופרדת ב-`ff ff 00 00` (pen-up). מאומת: כל 12 סמלי-השקע ב-DR1 **זהים בייט-בבייט** → אין מיקום בסמל; ממוקם ע"י MEP record.
- **block#2 (מש 3D)** = QUADER/HALBKREIS כ-float32 במסגרת מקומית (cm) → תבנית.
- **blocks 3/4/5** = טבלאות אינדקס/טופולוגיה (קישוריות), לא מיקום.
- **מתכון הזרקה פרמטרי**: העתק 7 בלוקים מ"פריט-זהב" מאותו סוג, וטלא רק MEP +0x00/+0x02 (מיקום), +0x0a (אוריינטציה), +0x04 (עוגן). תקן count + 5 עדכוני אינדקס.

**5 עדכוני sub — פוענחו חלקית (2026-08-13, `analysis/index_diff.js`):**
בדיוק 11 בייטים משתנים ב-5 ריצות (alignment לפי 7 נקודות ההוספה, מהימן):
- **RUN1 @0x11a (1B)**: ✅ **count אביזרים** 25↔24 (= 0xd4 + 5קירות×14). דלתא +1.
- **RUN2 @0x1613 (1B)**: ✅ **מונה סגמנטים 2D גלובלי**. דלתא **+14** = 14 הסגמנטים בסמל-השקע (28 קדקודים / 14 מפרידי `ff ff 00 00`, אומת ב-`count_verts.js`).
- **RUN3/4/5 @0x3c33/0x3d91/0x4651 (3B כ"א)**: ⚠️ **ידיות טופולוגיית 3D (BREP)** — לא פוענח.
  - מבנה: `[int16][byte flag]`. ה-int16 זז בקבוע **−18104** בשתי הרשומות שהשתנו; ה-flag byte עולה +8 (סיבית 0x08: 0x81→0x89).
  - רק 2-3 רשומות מסוג זה קיימות; **3 נקודות-מידע לא מספיקות** לפתרון עיוור. צריך **עוד זוגות-זהב** (מהאורקל) או קביעה אמפירית אם Raumplan בכלל צריך אותן.

**ניסוי מכריע שנבנה (`analysis/build_tests.js` → `analysis/out/`):**
הזרקת השקע ל-DR2 עם תת-קבוצות של העדכונים, לבדיקה איזה שדה קריטי לטעינה:

- `2918_VnoTopo.pdp` — רק count+segments; **דילוג על 3 ידיות הטופולוגיה**.
- `2918_VcountOnly.pdp` — רק count.
→ **צעד הבא: Michael פותח את 3 הקבצים ב-Raumplan.** אם VnoTopo נטען ומרנדר — הידיות מיותרות (Raumplan מחדש 3D) והאסמבלר פתיר עכשיו. אם שגיאה 921 — צריך אורקל לעוד זוגות.

## ✅ חוק המיקום הפרמטרי — פוענח ואומת (2026-08-13)
מקודד ב-`src/placement.js`. אומת מול golden 2918: **20/25 אביזרים מדויקים למ"מ** (X,Y,אוריינטציה זהים בייט-בבייט). כל אביזרי החשמל על קיר (שקעים, קופסאות, גז, ברזים) + חלונות = 0 שגיאה.

**החוק לאביזר צמוד-קיר:**
- ORDX `<Position><X>` = מרחק **לאורך הקיר** מנקודת ההתחלה; `<Y>` = גובה התקנה (Z), לא רלוונטי לתכנית.
- עוגן לפי class:
  - `Fixture` → X = **הקצה השמאלי** ⇒ מרכז `s = X + Width/2`.
  - `Decorative` (חלון/דלת) → X = **המרכז** כבר ⇒ `s = X`.
- נקודת התכנית על קו-מרכז הקיר: `(px,py) = wallStart + s·û`.
- טרנספורם: `PDP_x = px + offX ; PDP_y = −py + offY` (אותם offX/offY כמו הקירות).
- **קוד אוריינטציה** (+0x0a) `= round(10 × זווית_הקיר_מעלות)` במסגרת PDP (עם היפוך Y): `atan2(−dy, dx)`, נורמל ל-[0,3600).
- `<Width>` נקרא ישירות מ-`<General>` לאביזרים, מ-`<Size>` לחלונות (תוקן ב-parseOrdx).

**קצוות פתוחים (5 אביזרים חריגים ב-2918):**
- **תאורת תקרה** ("Can Light") — floating, לא צמוד-קיר. מצב מיקום נפרד (קואורדינטות חדר?) — לא פוענח.
- **Sewage** — היסט ניצב ~116מ"מ מקו-הקיר (ניקוז ברצפה).
- **שקע בודד על wall5** — edge case בהתאמה, לבדוק.
