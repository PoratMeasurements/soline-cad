> **טרנספורם קירות DR מאומת בית-בבית (mimran-5):** סדר-קירות הפוך · `x_pdp=x+Cx` · `y_pdp=-y+Cy` · מרכז-קו (בלי היסט-200) · טבלה @0xd4 int16 stride14, count@0xd2. אביזרים: מ-`.rpi` (טקסט). "DR/ELC" = שם למבנה-הבתים בלבד — **לא** קשור לתוכנת ELC; אנחנו רק ORDX→PDP+DXF.

# פורמט Raumplan-native PDP — ממצאי RE (מעודכן 2026-08-14)

מטרה: **ORDX → PDP אמיתי מאפס** בפורמט Raumplan for Windows IV (header `ffffff7f 44000000`).
זה שונה מפורמט DR/ELC_SND (int16, header אפסים) שפוצח קודם.

## קבצי-ייחוס (analysis/out/)
| קובץ | תוכן | תפקיד |
|---|---|---|
| `1.pdp` = `A.pdp` | קיר בודד 4000×100 (4817B) | בסיס נקי, טמפלייט-קיר |
| `2.pdp` | קיר בודד 3000×100 (4817B) | זוג-בקרה מול 1 (רק רוחב שונה) |
| `B.pdp` | 1.pdp + שקע בודד (13287B) | טמפלייט-שקע |
| `C.pdp` | 1.pdp + 2 שקעים (21514B) | אישור שכפול-שקע |
| `wall_6000.pdp` | 1.pdp ששוכתב ל-6000 | **עבד בראומפלן! הראה 6000** |
| `L2.pdp` | ראומפלן טען+שמר-מחדש את wall_6000 | הוכחה שהסינתזה תקינה |

## מבנה הקובץ
```
[0x000..0x14d]  header (ffffff7f 44000000 ...)
[0x14d..]       wall TABLE — int32, stride 22: x1,y1,x2,y2(int32) thick,height(int16) +2b
                ⚠ הטבלה לבדה לא מציירת את החדר! התצוגה מגיעה מגוף-הקובץ.
[0x1bb..]       body geometry (per-wall + per-item records, views)
[tail ~2141B]   catalog: GENERAL / DKP60 / DLB60 + GUIDs
```

## ✅ קירות — מה פוצח (רוחב, בית-בבית)
מבחן `1.pdp`(4000) → `2.pdp`(3000): 30 בתים שונים בלבד. שדות-הרוחב (לקיר בודד):
- **טבלת-קירות** x-coords (int32): `0x155, 0x163, 0x16b, 0x179`
- **extent** int32: `0x1ad`
- **body float32**: `0x638`
- **ASCII dim string**: `0x641` (4 תווים, למשל "4000")
- **0x7e4**: בית-תצוגה יחיד (delta קטן)

שחזור בית-בבית של 2.pdp מ-1.pdp אושר (0 בתים חורגים אחרי פאטצ' הסקלרים + העתקת GUID).

## ✅ ה-GUID לא-קריטי (מכריע!)
`0x1dc..0x1eb` = 16 בתים. `A` ו-`1` **זהים בגאומטריה** (שניהם 4000×100) אבל ה-16 בתים **שונים** → זה **GUID אקראי לכל-שמירה, לא checksum**. ראומפלן **לא מאמת** אותו. אפשר להשאיר ישן. (יש עוד בלוקי-GUID: 0xf0c, 0x122e, וליד קודי-הקטלוג.)

## ✅ ראומפלן מקבל קבצים מפוברקים
טען את `wall_6000` (ששוכתב ידנית), הציג 6000 נכון, ושמר-מחדש (`L2`). ההבדלים בשמירה-מחדש = GUIDs + נורמליזציית-view בלבד. **הסינתזה שלנו תקפה.**

## 🔑✅ רשומת-קיר 42 בתים — פוצחה במלואה (2026-08-15)
כל קיר מצויר = **רשומה 42 בתים** במערך רצוף בגוף (`חדר ריק`: 6 רשומות @0xad0 stride 42).

**מבנה הרשומה (offset יחסי לתחילת הרשומה):**
```
+0..15   prefix/flags: 49 00 7f 00 | 01 00 00 00 | ff ff ff ff | 00 00 01 00   (העתק מטמפלייט)
+16..19  float32 x1     ← נקודת-קצה 1, x
+20..23  float32 y1     ← נקודת-קצה 1, y
+24..27  float32 x2     ← נקודת-קצה 2, x
+28..31  float32 y2     ← נקודת-קצה 2, y
+32      00
+33..36  ASCII אורך (4 תווים, מיושר-שמאל, למשל "3000")
+37..41  00 00 00 00 00
```
**חוק ההיסט (קריטי):** נקודות-הקצה מוסטות ב-**200 מ"מ לכיוון הנורמל-השמאלי** של כיוון-הקיר:
`off = (-dy/L, dx/L) * 200`, ואז `x1'=x1+off.x, y1'=y1+off.y` וכו׳. אומת על כל 6 הקירות של `חדר ריק`:
- wall1 (0,4000)→(3000,4000): floats `[0, 4200, 3000, 4200]` (y+200)
- wall3 (3000,9000)→(9000,9000): `[3000, 9200, 9000, 9200]` (y+200)
- wall0 (0,0)→(0,4000): `[-200, 0, -200, 4000]` (x−200)
- wall2/4/5 — כולם תואמים לחוק הנורמל-השמאלי.

**buildWallRecord(x1,y1,x2,y2)** מיושם; יצר את `room_4x3.pdp` — **נטען והציג מלבן 4000×3000 אמיתי בראומפלן!** ✅

### מתכון בניית-חדר (מאומת) — בסיס `חדר ריק`
מיקומי-מפתח: טבלה @**0x1a5** (6×th100 stride22), רשומות-גוף @**0xad0** (stride42).
1. **winding = CW** (הפוך): מלבן `(0,0)→(0,H)→(W,H)→(W,0)→(0,0)` → נותן **זווית-חיבור 90** + חזית פנימה. (CCW נתן 270 + חזית החוצה.)
2. **היסט-חזית = right-normal**: `off=(dy/L, -dx/L)*200` → חזית פנימה. (הערה: בקנה-מידה זה ההבדל left/right-normal כמעט לא-נראה — ה-winding הוא הקובע העיקרי.)
3. קירות עודפים (4,5) → לכווץ ל-(0,0), dim "0".
4. **⚠ אין extent write!** ה-`0x1ad` ששימש ב-1.pdp הוא `endX` של קיר0 בבסיס הזה (טבלה @0x1a5) — כתיבה שם יוצרת קיר-אלכסון. base-specific.
5. GUID @0x1dc — להשאיר.

פתוח: איפה שדה-ספירת-הקירות (6)? עובד עם 2 מכווצים, אבל כדאי למצוא כדי לתמוך ב-N קירות שרירותי.

## 🔩 אביזרים (שקעים) — טמפלייט מוכן
- שקע = **~8.2KB** מפוזרים על **9 קטעים** (431B רשומת-SUPP_FR + 4968B סמל-2D + 5624B גאומ-3D + פירורים).
- רשומת-SUPP_FR: `SUPP_FR`@+0, שם(cp1255)@+9,+51, **מיקום X/Y int32 @+133/+137**, "בלי העדפות"@+206.
- **C−B מוכיח: שקע 2 = העתק-בתים של שקע 1** (רק מיקום שונה) → שקעים ניתנים לשכפול.
- ב-`תשתיות`: 22 תשתיות כרשומות 431B רצופות @0x261 stride 431 (מרקר SUPP_FR).

## המשך מחר (לפי סדר)
1. **לפענח את רשומת-הקיר 42B במלואה** — אילו floats = אילו קואורדינטות (endpoints/normal). לבנות פונקציה `buildWallRecord(x1,y1,x2,y2)`.
2. **לבנות חדר מרובע מ-1.pdp**: לכתוב N רשומות-42B + טבלת-קירות + extent + לוודא ספירת-קירות. מבחן-טעינה אצל Michael.
3. **עומק (depth)**: הזוג 1/2 שינה רק רוחב. או להסיק עומק מרשומת-42B (יש בה את שני הקצוות) או לבקש זוג-עומק.
4. **להוסיף שקעים**: להזריק את בלוק-השקע (9 קטעים) + מיקום מ-ORDX.
5. **לחבר לממיר**: `soline_convert.js` → מסלול PDP אמיתי במקום הזרקת-2918.
