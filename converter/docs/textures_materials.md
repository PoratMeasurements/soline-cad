## 0. תקציר מנהלים

* **מלאי:** ~**10,881 קבצי-תמונה**, מתוכם **10,876 BMP** (99.95%), 3 PNG, 2 JPG.
  זו הספרייה הנייטיבית של מנוע ה-RPW32 של Raumplan — נפרדת מ-386 ה-JPG של צינור
  ה-Blender שתועדו ב-`rendering_design.md`.
* **סוג הספרייה:** כמעט כולה **albedo / diffuse בלבד** (מפת-צבע). אין מפות
  roughness/metalness/normal נפרדות. יש רק **7 מפות-Bump** בתיקיית `bump\`.
  זו ספריית-חומרים "שטוחה" — כל שאר תכונות-החומר (ברק, חספוס, מתכתיות) מוזרקות
  ברמת-ה-shader בזמן-רינדור, לא נשמרות בקובץ.
* **עומק-סיביות:** רובם **24-bit RGB** (~95% מהמדגם), מיעוט **32-bit**, בודדים 8-bit.
* **מנגנון-השיוך:** קובץ-אינדקס טקסטואלי `ini\GENERAL.ini` (קידוד **Windows-1255**)
  ממפה **~2,512 כינויי-חומר** → נתיב-BMP יחסי, בסקציה `[Textures]`. סקציה `[Geometries]`
  מקשרת רכיב (דלת / צד / מגירה) לגיאומטריית-KDT ולסוג-הציפוי.
* **צבעים חלקים (flat colors):** מקודדים כקובץ-זעיר `RGB_00RRGGBB.bmp` — 1×1 פיקסל,
  32-bit, כשה-hex בשם-הקובץ = הצבע. נוצרים לפי-דרישה, לא בקטלוג.

**המלצה (§6):** ל-Soline לבנות ספריית-חומרים דקה בפורמט **PBR/glTF** (map + roughness +
metalness + normal), עם מניפסט JSON אחד שממפה `materialId → {maps, params}`, בהשראת
מבנה ה-`[Textures]`/`[Geometries]` אך מודרני. שלושת הצעדים לרינדור מוחשי ב-§7.

## 1. מלאי החומרים

### 1.1 פורמטים, רזולוציות ועומק-סיביות

| מדד | ערך |
|---|---|
| סה"כ קבצים | 10,881 |
| BMP | 10,876 (99.95%) · PNG 3 · JPG 2 |
| עומק-סיביות (מדגם 200) | 24-bit ~95% · 32-bit ~5% · 8-bit נדיר |
| דחיסה | ללא (BI_RGB) — BMP לא-דחוס |

**רזולוציות** נגזרות מגודל-הקובץ (BMP לא-דחוס: `רוחב×גובה×בתים + 54` header). המשפחות
הנפוצות:

| גודל-קובץ (bytes) | רזולוציה | ~כמות |
|---|---|---|
| 49,206 | **128×128** 24-bit | ~1,437 |
| 196,662 | **256×256** 24-bit | ~1,010 |
| 786,486 | **512×512** 24-bit | ~758 |
| 262,198 | 256×256 32-bit / 512×512 8-bit | ~384 |
| 58 | **1×1** 32-bit (`RGB_*` swatch) | swatches |
| 70 | 1–2px זעיר | ~191 |

מסקנה: רזולוציות **צנועות** (128–512px), מתאימות לטַיילינג על משטחים אך לא ל-close-up
פוטוריאליסטי. אימות-header לדוגמה (`בלורן2021\...GF949.bmp`): רוחב `0x80=128`, גובה
`0x80=128`, `0x18=24 bit`, compression 0.

### 1.2 משפחות-חומר (תיקיות עליונות)

הספרייה מאורגנת לפי **משפחת-חומר בעברית**. הגדולות ביותר (ספירה רקורסיבית):

| תיקייה | משמעות | ~קבצים בענף | סוג-PBR רלוונטי |
|---|---|---|---|
| `נירלט`, `צבעים` (RAL/NCS/…) | צבעי-לכה, מניפות RAL 1320 + NCS 339 | ~2,000+ | flat color, roughness גבוה |
| `פורמיקות` (ARPA, דורופל, MAZONIT, לבידי-לביא, א.פ) | פורמייקות עץ + צבעים חלקים | ~800+ | map עץ, roughness בינוני |
| `משטחי עבודה` (קיסר / קיסרסטון, שונות) | משטחי-שיש/קוורץ | ~530+ | map אבן, roughness נמוך, ברק |
| `מכשירים` (BLANCO כיורים, תנורים, מקררים) | מיפוי-תמונה של מכשירי-חשמל | ~400+ | map מכשיר / נירוסטה metalness |
| `קיר`, `ריצפה`, `אריחים` (מרצפות/שיש) | קרמיקה, ריצוף | ~550+ | map, roughness בינוני-נמוך |
| `עץ` (אלון…), `אורצרד 2020`, `פורמקס2020` | פורניר/עץ | ~350+ | map עץ + bump, aniso |
| `מתכתי` | מתכת/נירוסטה/כרום | ~61 | metalness גבוה, roughness נמוך |
| `זכוכיות`, `נילסן\זכוכיות` | זכוכית (מסורתית/מודרנית) | ~180 | transmission, IOR≈1.2 |
| `אינפיניטי פורצלן`, `בלורן2021`, `מאור` | פורצלן, יצרני-חזיתות | ~40 | map, ברק משתנה |
| `bump\` | **7 מפות-Bump בלבד** | 7 | normal/bump |
| `המחשות` | רקעים/דקור סביבתי (ראה §1.3) | ~600 | לא-חומר: תפאורה |

### 1.3 `המחשות` — תפאורה סביבתית (זהירות-PII)

תת-התיקיות: `נוף`, `צמחים`, `בדים`, `דלתות`, `חלונות`, `שטיחים`, `קרמיקה`, `T.V`,
`תמונות`, `תויות`. אלו **תמונות-רקע / דקור** (billboards לצמחים, נוף לחלון, תמונות-קיר)
ולא חומרי-משטח. **חלקן עשויות להיות תצלומים אישיים** → לא הועתקו, לא נאגרו; ל-Soline
מומלץ להשתמש בנכסים חופשיים משלנו, לא לייבא מכאן.

### 1.4 מוסכמות-שמות

* **קטלוג-יצרן לפי מק"ט:** שם-הקובץ = קוד-הגוון של היצרן (`0200`, `GF949`, `0214 PIXEL`).
* **סיומת-גימור בשם:** `מבריק` (glossy) / `מט` (matte) / `TF` / `היי גלוס` — הברק מקודד
  בשם/בתיקייה, לא בקובץ.
* **צבע-שטוח:** `RGB_00RRGGBB.bmp` (למשל `RGB_00F69C9C.bmp` = צבע `#F69C9C`). קובץ 1×1,
  32-bit BGRA; בתי-הפיקסל = ה-hex בשם. מנגנון "חומר-צבע-אחיד" ללא טקסטורה.
* **מפת-Bump:** `<שם>_Bump.bmp` (למשל `sirius_Bump.bmp`, `kreta_Bump.bmp`) בתיקיית `bump\`.

## 2. מבנה, ארגון וקבצי-אינדקס

* **אין** קובץ-אינדקס בתוך `Textures\` עצמו (לא `.ini`/`.mat`/`.lst`). התיקיות הן
  ההיררכיה היחידה בדיסק.
* **האינדקס האמיתי הוא `ini\GENERAL.ini`** (וגרסאות-יצרן: `Bluran2020.ini`, `Nielsen.ini`,
  `ORCHARD20.ini`, `elkincho.ini`, `Rpw.ini`), בקידוד **Windows-1255**. שלוש סקציות מפתח:
  * `[PathTextures]` → `0=C:\raumplan\textures` (נתיב-הבסיס).
  * `[Textures]` → קטלוג-החומרים (~2,512 שורות).
  * `[Geometries]` → קטלוג-רכיבי-גיאומטריה (KDT).
  * `[Fliesenfuge.Textures]` → חומר-רובה בין-אריחים (grout).

### 2.1 מבנה שורת-חומר ב-`[Textures]`

```
<כינוי-חומר> = <נתיב-BMP-יחסי-מתחת-ל-Textures> [ ,,,,,,,,, <scale> ]
```

דוגמאות:
```
0200 מבריק = פורמיקות\ARPA\צבעים חלקים\0200 מבריק
0214 PIXEL = פורמיקות\ARPA\חדש\0214 PIXEL
0010TF(AVR) = אברבוך\0010TF ,,,,,,,,, 0.10000
```
* השדה מימין = **סדרת-פסיקים (עד 10 שדות)**; השדה האחרון שנצפה בשימוש = **scale/tiling**
  (`0.10000` = טַיילינג ×0.1). שאר-השדות שמורים (offset/rotation/mirror — ריקים ברוב).
* הסיומת `.bmp` מרומזת; ההרחבה מתווספת מהנתיב.

### 2.2 מבנה שורת-גיאומטריה ב-`[Geometries]`

```
<שם-רכיב> = <נתיב-KDT-יחסי> , <תווית-וריאנט> , <סוג-רכיב>
```
דוגמאות:
```
_פורמיקה = ציפויים\uni_PNFM , , SIDE_IN     ; ציפוי-פורמייקה על משטח-צד
_פורניר  = ציפויים\uni_PNFN , , SIDE_IN     ; ציפוי-פורניר
_צבע     = ציפויים\uni_PNZV , , SIDE_IN     ; ציפוי-צבע/לכה
BLACK_ALUM = Elkincho\elk_albk , , TUER      ; דלת אלומיניום שחור
DRFACET4 = חזיתות\עם-מילואה\DRFACET4 , מסגרת גרונג , TUER
```
**התפלגות סוגי-הרכיב (`[Geometries]`):** `TUER` (דלת) ×185, `HZ` ×68, `GRLO` ×40,
`H_IDRWR` ×10, `SIDE_R/SIDE_IN/SIDEU` (משטחי-צד) ×3 כ"א, `DRAWER` (מגירה) ×2,
`VIT_GLS` (זכוכית-ויטרינה) ×2, `BAMA` ×3.

## 3. איך חומר משתייך לאלמנט (המנגנון המלא)

Raumplan מפריד בין **גיאומטריה** ל**חומר**, ומחבר בשתי הפניות-בשם:

```
   אלמנט/ארון (KDT/PDP)
        │
        ├── רכיב-גיאומטריה ──► [Geometries] ──► KDT + סוג (TUER/DRAWER/SIDE_IN…)
        │        (דלת/מגירה/צד)
        │
        └── כינוי-חומר ──────► [Textures] ──► נתיב-BMP + scale
                                    │
                          C:\raumplan\textures\<path>.bmp
```

* **דלת** (`TUER`) מקבלת גיאומטריה מ-`[Geometries]` **וכן** כינוי-חומר מ-`[Textures]`.
  אותה גיאומטריית-דלת + חומרים שונים = וריאציות-מוצר.
* **מושג ה"ציפוי" (`ציפויים\uni_*`)**: `_פורמיקה / _פורניר / _צבע` הם משטחי-`SIDE_IN`
  שמקבלים את חומר-גוף-הארון — כך צד-ארון "יורש" את הפורמייקה/פורניר/צבע.
* **הברק/הגימור** אינו בקובץ אלא ב**שם** (`מבריק`/`מט`) ומיושם ברמת-shader (ראה
  `rendering_design.md` §1.2: `Glossy BSDF roughness=0.18`, `Diffuse BSDF`).
* **קבצי-KDT הם בינריים** (`data`) — הגיאומטריה נשמרת בהם; ההפניה-לחומר עוברת דרך
  שם-הכינוי ב-INI, לא כמחרוזת בתוך ה-KDT.

**זו התובנה המרכזית ל-Soline:** *גיאומטריה וחומר הם שתי הפניות-בשם נפרדות שמתאחדות
בזמן-רינדור.* בדיוק המודל שצריך למציג three.js/glTF (mesh + materialId).

## 4. פערים מול PBR (מה חסר בספרייה הזו)

| רכיב-PBR | קיים ב-Raumplan? | הערה |
|---|---|---|
| **base color / albedo** | ✅ 10,876 BMP | הליבה קיימת |
| **roughness map** | ❌ | ערך-סקלר מוזרק ב-shader |
| **metalness map** | ❌ | נגזר ממשפחת-החומר (`מתכתי`) |
| **normal map** | ⚠️ 7 bump בלבד | דל מאוד; רוב-המשטחים שטוחים |
| **tiling/scale** | ✅ שדה ב-INI | `0.10000` וכו' |
| **transmission/IOR** (זכוכית) | ⚠️ ב-shader בלבד | `IOR≈1.2` ב-Blender |

מסקנה: הספרייה נותנת **albedo + טַיילינג + טקסונומיית-משפחה** — מספיק ל"מוחשי-בסיסי".
ל-PBR מלא צריך להוסיף roughness/metalness/normal (או להסיק אותם ממשפחת-החומר, ראה §7).

## 5. חיבור למציג-ה-3D ולספריית-האלמנטים

**עם `rendering_design.md` (מציג three.js / glTF):**
* מיפוי ישיר: `[Textures].path.bmp` → `THREE.MeshStandardMaterial.map`; שדה-scale →
  `map.repeat` (+`wrapS/wrapT = RepeatWrapping`); משפחת-החומר → קביעת
  `roughness`/`metalness` דיפולטיים (ראה טבלת-§7.2).
* BMP אינו נתמך נייטיב ב-WebGL — **להמיר ל-KTX2/WebP/PNG** בזמן-בנייה (build-time),
  כפי ש-glTF ממילא דורש. את `RGB_*` swatch להמיר ל-`material.color` (hex) בלי map כלל.
* עולה יפה על ה-POC הקיים `analysis/out/soline_3d_viewer_poc.html` ועל חוזה
  `sceneFromModel()` המתואר שם.

**עם `library_requirements.md` / `elements_catalog.md` (ספריית-האלמנטים):**
* כל אלמנט/ארון בקטלוג-Soline יחזיק **`materialId`** (או ברירת-מחדל למשפחה) בנוסף
  ל-geometry — בדיוק ההפרדה של `[Geometries]` מול `[Textures]`.
* סוגי-הרכיב של Raumplan (`TUER`/`DRAWER`/`SIDE_IN`) ממופים ל-slots-החומר של אלמנט-Soline
  (חזית / גוף / משטח-עבודה / ידית), כך שדלת ומשטח מקבלים חומרים שונים על אותו ארון.

## 6. המלצה: ספריית-חומרים ל-Soline

**מבנה מוצע (offline-first, מבוסס-קבצים):**
```
assets/materials/
  manifest.json                 ← אינדקס יחיד (מחליף את [Textures]/[Geometries])
  wood/oak_natural/
     albedo.webp  normal.webp  (roughness.webp)
  stone/quartz_calacatta/…
  metal/stainless_brushed/…
  glass/clear/…                 ← אין map; params בלבד
  flat/                         ← צבעים אחידים = hex ב-manifest, בלי קובץ
```
**`manifest.json` — סכמת-חומר (PBR/glTF-תואם):**
```jsonc
{
  "oak_natural": {
    "family": "wood",
    "maps":   { "albedo": "wood/oak_natural/albedo.webp",
                "normal": "wood/oak_natural/normal.webp" },
    "params": { "roughness": 0.55, "metalness": 0.0,
                "tiling": [0.5, 0.5], "color": null },
    "source": "raumplan:עץ\\אלון\\..."   // עקיבות למקור
  },
  "quartz_calacatta": { "family":"stone",
    "params": { "roughness":0.15, "metalness":0.0, "clearcoat":0.3 } },
  "flat_F69C9C": { "family":"paint",
    "params": { "color":"#F69C9C", "roughness":0.7 } }   // מחליף RGB_*
}
```
* **`family` → ברירות-מחדל PBR** (טבלת-§7.2) כדי שלא נצטרך לצייר roughness/metalness ידנית.
* **`materialId` יחיד** שאלמנט מפנה אליו — מקביל לכינוי ב-`[Textures]`.
* **תואם-glTF**: `map`→baseColorTexture, `roughness/metalness`→metallicRoughness,
  `normal`→normalTexture. חוזה-אחד לשני-יעדים (three.js עכשיו, Blender בהמשך) — כמדיניות
  ב-`rendering_design.md`.
* **המרה מ-Raumplan**: סקריפט build שקורא `GENERAL.ini` (cp1255) → מייצר manifest,
  ממיר BMP→WebP, וממפה משפחת-תיקייה→`family`. שימוש-חוזר במלאי בלי לאגור אותו ב-repo.

## 7. שלושה צעדים לרינדור מוחשי

**צעד 1 — שכבת-חומרים דקה מונחית-משפחה.** לממש `MaterialLibrary.get(materialId)` שמחזיר
`MeshStandardMaterial`/`MeshPhysicalMaterial` מוכן. אם אין map — ליפול חזרה ל-color+family.
זהו החיווט ל-slot-החומר של כל אלמנט (חזית/גוף/משטח).

**צעד 2 — טבלת ברירות-מחדל PBR לפי-משפחה** (מסירה את הצורך במפות שחסרות בספריית-Raumplan):

| family | roughness | metalness | תוספת |
|---|---|---|---|
| wood / veneer / formica | 0.5–0.6 | 0.0 | anisotropy קל; normal אם קיים |
| stone / quartz (משטחים) | 0.1–0.2 | 0.0 | `clearcoat 0.2–0.4` לברק |
| metal / stainless / chrome | 0.15–0.3 | 1.0 | envMap חובה להשתקפות |
| glass | 0.0–0.05 | 0.0 | `transmission 1`, `ior 1.2`, `thickness` |
| paint / lacquer (RGB_/RAL) | 0.4 (מט) / 0.1 (מבריק) | 0.0 | color בלבד |

**צעד 3 — תאורת-סביבה מבוססת-תמונה (IBL) + AO**, בדיוק כמו `SkyDome`+`AmbientOcclusion`
של Raumplan (`rendering_design.md` §1.1). ב-three.js: `RoomEnvironment`/HDRI כ-`scene.environment`,
`ACESFilmicToneMapping`, ו-AO (SSAO/`aoMap`). **זה הצעד שהופך "צבע-שטוח" ל"מוחשי"** — בלי IBL,
מתכת וזכוכית נראות מתות; איתן הן משתקפות ונראות אמיתיות.
