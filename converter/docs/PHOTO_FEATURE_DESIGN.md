# פיצ'ר-תמונות — צילום-פר-חזית → .sol → דוח-HTML

> מסמך-אב + חוזה-נתונים משותף לשני-המסלולים (אפליקציה + ממיר). תאריך: 2026-08-25.
> עיקרון: **הפורמט כבר מוכן** — ל-`.sol` יש שכבת `annotations.photos:[]` (ריקה ב-v1). אנחנו רק ממלאים אותה + מטמיעים את קבצי-התמונה ב-ZIP. אין שינוי-פורמט שובר-תאימות.

---

## 1. מה מיכאל ביקש (חובה)
1. **צילום-תמונות פר-חזית** — לכל קיר/חזית אפשר לצלם תמונות במהלך-המדידה.
2. **שם-התמונה נשמר כחלק מהייצוא** — שמות-הקבצים נכתבים ל-`.sol` (ולכל הפורמטים הרלוונטיים).
3. **מצטרף לדוח-HTML** — גלריה בדוח.
4. **מוסכמת-שמות:** `לפי-החזית-שנמדדה + מספר-עוקב באותה-חזית` → למשל `חזית-1_01`, `חזית-1_02`, `חזית-2_01`.
5. **ייצוא-תמונות מהדוח** — כפתור בדוח-HTML להורדת-התמונות.
6. **ניתוח-נגר** — מה עוד כדאי להוסיף בנושא-התמונות (למטה §4).

## 2. חוזה-הנתונים (מחייב את שני-המסלולים)

### 2.1 מוסכמת-שם-הקובץ
```
חזית-{wallIdx1}_{seq2}.jpg
```
- `wallIdx1` = אינדקס-הקיר **1-based** (קיר-ראשון=1) — תואם לתצוגת-המשתמש.
- `seq2` = מספר-עוקב 2-ספרתי **בתוך אותה-חזית** (01, 02…), מתאפס לכל קיר.
- סיומת `.jpg` (JPEG, איכות ~85, orientation-normalized).
- דוגמה: `חזית-1_01.jpg`, `חזית-1_02.jpg`, `חזית-3_01.jpg`.
- תמונות **ברמת-החדר** (סקירה כללית, לא-משויכות-לקיר): `חדר_{seq2}.jpg`.
- תמונות **מוצמדות-לאלמנט** (§4): `חזית-{wallIdx1}_{seq2}_{elementType}.jpg` (הסיומת-התיאורית אופציונלית).

### 2.2 מבנה-ה-ZIP ב-.sol (הרחבה של SolWriter)
```
project.sol (ZIP)
├─ manifest.json          ← layers.photos → present:true, entry "photos/"
├─ annotations.json       ← photos:[ {meta} … ]   (במקום המערך-הריק)
├─ photos/
│  ├─ חזית-1_01.jpg
│  ├─ חזית-1_02.jpg
│  └─ …
└─ … (measured/ etc — ללא-שינוי)
```

### 2.3 סכמת-רשומת-תמונה ב-`annotations.json.photos[]`
```json
{
  "file": "photos/חזית-1_01.jpg",
  "name": "חזית-1_01",
  "scope": "wall",                 // "wall" | "room" | "element"
  "wallIdx": 0,                    // 0-based (תואם measured/); null אם room
  "wallLabel": "חזית 1",
  "seq": 1,                        // עוקב בתוך-החזית
  "elementId": null,               // אם scope=element → id-האביזר
  "caption": "",                   // הערת-המודד (אופציונלי)
  "kind": "context",               // context | detail | obstacle | junction | ceiling | floor | overview
  "takenAt": "2026-08-25T09:12:00Z",
  "w": 3000, "h": 4000,            // פיקסלים (לגלריה)
  "bytes": 812345
}
```
- **מקור-האמת של המטא = `annotations.json`.** קבצי-ה-JPEG חיים תחת `photos/`.
- `wallIdx` נשמר **0-based** ב-JSON (עקבי עם `measured/`), אבל **שם-הקובץ 1-based** (עקבי עם ה-UI). הממיר ממפה ביניהם.

## 3. חלוקת-עבודה בין-המסלולים

### מסלול-אפליקציה (Kotlin) — סוכן #1
- **PhotoEntity** חדש (Room DB v12→**v13**): `id, roomId, wallId(nullable), seq, scope, kind, fileName, absPath, caption, takenAt, w, h, bytes`. FK+cascade כמו-האחרים.
- **מסך-צילום פר-חזית**: בעורך-הקיר כפתור "📷 צלם חזית" → מצלמה (ACTION_IMAGE_CAPTURE דרך ה-FileProvider הקיים `il.co.soline.measure.fileprovider`, או CameraX אם צריך רצף-מהיר) → שומר תחת `filesDir/photos/`, ממספר-אוטומטית `seq` פר-קיר, שם-קובץ `חזית-{idx+1}_{NN}.jpg`.
- **הרשאת-CAMERA** ב-AndroidManifest + בקשת-runtime.
- **תצוגה**: רשימת-תמונות-ממוזערות בעורך-הקיר, מחיקה/כיתוב.
- **SolWriter**: להטמיע `photos/*.jpg` כ-ZIP-entries בינאריים + למלא `annotations.json.photos[]` (במקום `buildAnnotations()` הריק) + `manifest.layers.photos.present=true`.
- לשמור על מסלול-אפליקציה מסודרתי (agent אחד-בכל-פעם).

### מסלול-ממיר (Node.js) — סוכן #2 (**מחכה לסיום סוכן-הסמלים** כדי לא להתנגש ב-viz_engine/export_html)
- **readSol.js**: לחלץ את `annotations.photos[]` + לחשוף את בייטי-ה-JPEG (buffer) לכל תמונה.
- **דוח-HTML** (`export_html.js`/`viz_engine.js`): גלריה **מקובצת-לפי-חזית**, ממוזערות→lightbox-זום, כיתוב=`name`+kind, ממוקמת ליד שרטוט-החזית של אותו-קיר. תמונות מוטמעות כ-data-URI (HTML עצמאי) עם דחיסה.
- **ייצוא-תמונות מהדוח**: כפתור "⬇️ הורד תמונות" — ZIP של כל-התמונות (JSZip client-side) + הורדה-פר-חזית.
- להשאיר את חוזה-השמות בדיוק כמו §2.

## 4. ניתוח-נגר — מה עוד כדאי (מעבר-לבסיס-שמיכאל-ביקש)
חשיבה כנגר-שמגיע-לשטח: התמונה היא **הזיכרון-הויזואלי** של המדידה. מה שנגר-מקצועי ירצה לתעד:

| # | סוג-תמונה (`kind`) | למה נגר צריך את זה |
|---|---|---|
| 1 | **context** — חזית שלמה חזיתית | ההקשר-הכללי; הבסיס-שביקשת. |
| 2 | **detail** — תקריב מוצמד-לאלמנט (שקע/ברז/גז/מפסק) | לראות את הסוג-המדויק (סוג-פלטה, כיוון, מצב) — קריטי לתכנון-חיתוכים. משויך ל-`elementId`. |
| 3 | **obstacle** — צנרת-בולטת, קורה, רדיאטור, ארון-קיים-לפירוק, טיח-לא-ישר, נישה | מכשולים שהורגים תכנון אם לא-נראו מראש. |
| 4 | **junction** — מפגש-קירות (זווית-לא-90°), מעבר-קיר↔תקרה, מעבר-קיר↔רצפה (פנל/גובה-ריצוף) | הנגר צריך לדעת אם הפינה מרובעת ואיפה הפנלים. |
| 5 | **ceiling / floor** — תקרה+רצפה | משלים את סקר-המישוריות (X6); איפה גופי-תאורה/נקודות. |
| 6 | **overview** — כל-החדר מהכניסה | תיק-לקוח + חומר לפני/אחרי לשיווק (מתחבר ל-soline-social). |
| 7 | **scale-ref** — סרט-מדידה/חפץ-ידוע בפריים | קנה-מידה ויזואלי לאימות. |
| 8 | **annotation-on-photo** — לסמן חץ/מידה על-התמונה ("שקע כאן 110") | הנגר מסמן ידנית; מגיע לדוח. |

**המלצות-מימוש נוספות (לאישורך):**
- **הצמדה-לאלמנט**: בעורך-האביזר (שקע/ברז/פתח) כפתור-מצלמה ייעודי → `scope:"element"`, מקשר תמונה לאלמנט-הספציפי; בדוח התמונה מופיעה ליד שורת-האלמנט.
- **דגל-kind** בזמן-הצילום (בורר-מהיר: הקשר/תקריב/מכשול/…): מסדר את הגלריה בדוח לפי-משמעות.
- **תמונת-לפני-ואחרי**: `overview` מסומן אוטומטית ל-pipeline-השיווק (סוכן soline-social) — ערך-עסקי, לא-רק-הנדסי.
- **סימון-על-התמונה** (canvas-פשוט): המודד מצייר חץ+טקסט; נשמר כשכבת-annotation נפרדת כדי לא-להרוס את-המקור.
- **חותמת**: `takenAt` + מיקום-בהסכמה (אם-הופעל) לתיעוד-provenance.

בסיס-החובה (§1) מיושם תמיד; פריטי-§4 הם שדרוגים שמיכאל מאשר פר-פריט.

## 5. רשימת-משימות-מדיה של המודד — שער-סגירת-חדר (2026-08-25, הוראת-מיכאל)
מיכאל: *"הנגר קודם-כל צריך תמונות כלליות, סרטון/תמונות גישה, סרטון-הסבר על-העבודה, תמונות לכל-חזית, תמונות לפרטים-מיוחדים עם מטר-פתוח, תמונות רחוקות ותקריבים — זה מתקשר לצד-המודד כי אלו חלק מהמשימות שהמודד צריך לסגור לפני שהוא יכול לסיים ולסגור מדידת-חדר."*

**מסקנה:** המדיה הופכת ל**רשימת-משימות-חובה** עם **שער-סגירה** — חדר לא-נסגר עד שכל-הפריטים-הנדרשים בוצעו (או דולגו-עם-סיבה).

### 5.1 קטגוריות-המדיה — **שתי-רמות: פרויקט + חדר** (תיקון-מיכאל 2026-08-25)
**גישה (`access`) = ברמת-הפרויקט (פתיחה+סגירה), לא ברמת-חדר!** מופיעה בזרימת-הפרויקט.

**רמת-פרויקט** (פעם-אחת לכל-פרויקט, `scope:"project"`, `phase:"opening"|"closing"`):
| key | label (עברית) | mediaType | חובה? | מתי |
|---|---|---|---|---|
| `access` | סרטון/תמונות גישה לאתר | photo\|video | ✔ | **פתיחת-פרויקט** (איך-מגיעים) **+ סגירת-פרויקט** |

**רמת-חדר** (פר-חדר, `scope:"room"|"wall"|"element"`):
| key | label (עברית) | mediaType | חובה? | ספירה-נדרשת |
|---|---|---|---|---|
| `overview` | תמונות כלליות של-החדר | photo | ✔ | ≥2 |
| `explainer` | סרטון-הסבר על-העבודה (בחדר) | video | ✔ | =1 |
| `elevation` | תמונה לכל-חזית | photo | ✔ | =מס'-הקירות (1 לכל-קיר) |
| `detail_tape` | פרטים-מיוחדים עם מטר-פתוח | photo | ✔ | ≥1 |
| `far` | תמונות רחוקות | photo | ○ | ≥1 |
| `closeup` | תקריבים | photo | ○ | ≥1 |

(✔=חובה לשער · ○=מומלץ. הספירות ניתנות-לכוונון.)
**שני-שערים:** (א) שער-סגירת-**חדר** = כל-חובת-החדר · (ב) שער-סגירת-**פרויקט** = access-פתיחה+סגירה **וגם** כל-החדרים-הושלמו.
*(הערה: `explainer` נשאר ברמת-חדר = הסבר-על-עבודת-החדר. אם מיכאל ירצה אותו ברמת-פרויקט → העברה קלה.)*

### 5.2 וידאו — הרחבת-החוזה
- **מקום-אחסון:** `filesDir/videos/`; שם-קובץ `{kind}_{NN}.mp4` (למשל `גישה_01.mp4`, `הסבר_01.mp4`) או פר-חזית כמו תמונות.
- **ב-.sol:** מערך-**נפרד** `annotations.videos[]` (לא-שובר את `photos[]` שכבר-נבנה). כניסות-ZIP בינאריות תחת `videos/`. שדות: `{ file, name, scope, wallIdx, kind, seq, caption, takenAt, durationSec, bytes }`.
- **גודל:** וידאו כבד. **ברירת-מחדל: מוטמע ב-.sol (מקור-אמת אחד) עם דחיסה** (רזולוציה≤720p, ביטרייט-סביר). בדוח-HTML: **לא** data-URI ענק — אלא תג-`<video>` עם קובץ-מצורף/קישור-הורדה + poster-ממוזער. (שדרוג-עתידי: העלאה-נפרדת אם קבצים גדולים-מדי.)

### 5.3 מודל + שער-סגירה (אפליקציה)
- **`RoomChecklistEntity`** (או שדה-JSON ברמת-החדר): לכל-חדר מפת-קטגוריות → {satisfiedCount, done, skippedReason}. הספירה מתעדכנת-אוטומטית מ-PhotoEntity/VideoEntity לפי-`kind`.
- **מסך "סגירת-חדר"**: רשימת-משימות עם ✓/✗ פר-קטגוריה, כפתור-צילום/וידאו-מהיר לכל-שורה, ופס-התקדמות ("5/6 משימות").
- **שער-קשיח + מוצא-שדה:** לא-ניתן לסמן חדר "הושלם/נסגר" עד שכל-החובה בוצע — **אבל** כל-פריט ניתן ל**"דלג עם-סיבה"** (טקסט-חופשי, נשמר ל-`skippedReason`) כדי לא-לתקוע מודד-בשטח שבאמת-לא-יכול. (הבחירה: שער-קשיח-עם-מוצא, לא-רך — תואם "חייב-לסגור" של-מיכאל, אבל מציאותי-לשדה.)
- **וידאו-קפצ'ר:** `ACTION_VIDEO_CAPTURE` דרך אותו-FileProvider; נירמול/דחיסה; VideoEntity מקביל-ל-PhotoEntity.
- **`kind` מורחב** ב-PhotoEntity: overview/access/explainer/elevation(=context)/detail_tape/far/closeup/obstacle/junction/ceiling/floor.

### 5.4 בדוח-HTML (ממיר)
- הגלריה מקובצת עכשיו **לפי-קטגוריית-משימה** (כללי/גישה/הסבר/חזיתות/פרטים-עם-מטר/רחוק/תקריב), לא-רק-לפי-חזית.
- **וידאו:** תג-`<video controls>` עם poster + כפתור-הורדה (לא-מוטמע-כ-data-URI-ענק).
- **דוח-שלמות:** באנר "מדידה-הושלמה: 6/6 משימות" או רשימת-החוסרים (כולל סיבות-דילוג) — כדי שהנגר/אדריכל יראה מה-תועד ומה-לא.
