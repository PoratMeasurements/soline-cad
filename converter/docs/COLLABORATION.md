# שיתוף פעולה בפרויקט Soline — מדריך למצטרפים

מסמך זה נועד למי שמצטרף לפרויקט (למשל ה-CEO) **ולקלוד שלו**. קרא אותי קודם.

## מה הפרויקט
בונים את **Soline** — תוכנה עצמאית (ממשק + exe) שממירה קובצי מדידה **ORDX** (מ-InnoDraw) לקובצי **PDP** (פרויקט Raumplan for Windows IV), עם **ספריית אלמנטים עצמאית משלנו** (לא InnoDraw). המטרה: להחליף את הזרימה הידנית ולייצר תכניות תשתית/חשמל אוטומטית.

## מקור האמת (קרא לפי הסדר)
1. **`STATUS.md`** — מצב הפרויקט המלא, מה פוענח, מה עובד, ומה הצעד הבא. **תמיד המקור המעודכן.**
2. **`elements.json` + `elements_catalog.md`** — ספריית האלמנטים.
3. **`library_requirements.md`** — דרישות שחולצו מ-1,882 PDF של לקוחות (מילון מונחים, קונבנציות, דקדוק ה"שפה").
4. **`pdf_notes_corpus.md`** — הערות אמיתיות מצוטטות מהשטח.
5. **`src/`** — הקוד (Node.js): `parseOrdx`, `placement`, `inject`, `symbol`, `assemble`. נקודת כניסה: `soline.js`.

## איך תורמים נתונים (מה שהכי חשוב)
כל תרומת ידע/קבצים → תיקיית **`inbox/`**:
- **קבצים גולמיים** (PDF, תכניות, מפרטים, דוגמאות): שים ב-`inbox/` עם שם ברור.
- **ידע/הערות/דרישות**: כתוב ב-`inbox/notes-<שם>.md`.
- **תיקוני ספרייה** (אלמנטים חסרים, מידות, גבהים, סמלים): כתוב ב-`inbox/library-feedback.md`.

בכל סשן, הקלוד הראשי סורק את `inbox/`, מטמיע את מה שרלוונטי לתוך הספרייה/הקוד, ומעדכן את `STATUS.md`.
