# דלתות וחלונות — מדריך תצוגה מקצועי בתוכניות CAD (כולל כיווני-פתיחה)

> מסמך-מפרט קריא-לאדם ולמכונה. מגדיר **איך** לצייר דלת/חלון בתוכנית (מבט-על) ובחזית
> (elevation) כך שנגר/אדריכל יקרא את כיוון-הפתיחה **מיידית**, וממפה כל מוסכמה
> לגאומטריית-הפרימיטיב של `src/element_symbols_soline.js` (תיבת-יחידה מנורמלת
> [0..1]×[0..1], y כלפי-מטה, קיר על הקצה התחתון y=1.0, החדר כלפי מעלה y→0).
>
> מקורות-אמת בקוד: `src/element_symbols_soline.js` (סמלי-2D), `src/element_catalog.js`
> (מיפוי-ORDX), `app-measure/.../catalog/ElementCatalog.kt` (קטלוג-האפליקציה).
> לשון זכר, יחידות מ״מ. תאריך: 2026-08-21.

## 0. עקרונות-יסוד של השפה הגרפית

שני מבטים שונים לחלוטין, וכל אחד מספר חלק אחר מהסיפור:

| מבט | מה הוא מראה על דלת/חלון | כיוון-פתיחה נקרא מ… |
|-----|------------------------|--------------------|
| **תוכנית (מבט-על / plan)** | מיקום לאורך הקיר, רוחב-הפתח, עובי-הקיר, **קשת-הסיבוב** של הכנף | הקשת + מיקום-הציר |
| **חזית (elevation)** | גובה-הפתח, חלוקת-שמשות, סף/משקוף, **קווי-V מקווקווים** | קודקוד-ה-V = ציר הציר |

**כלל-הזהב** (מוסכמה בין-לאומית, ISO 128 / חוזר בכל מקורות-הענף): *כל* פתח נפתח
מצויר בתוכנית כ**קו-כנף ישר** (הכנף במצב פתוח ~90°) + **קשת-רבע-עיגול** שמחברת את
קצה-הכנף חזרה למישור-הקיר. **הציר יושב תמיד בקצה שבו קו-הכנף נוגע בקיר; הקשת תמיד
נמשכת מקצה-הכנף אל הקצה-החופשי של הפתח.** מכאן שלושה מובנים חד-משמעיים בבת-אחת:
צד-הציר (שמאל/ימין), כיוון-הבליטה (פנימה/החוצה), ורוחב-הפתח (=מיתר-הקשת).
([Coohom — קריאת כיוון-פתיחה](https://www.coohom.com/article/symbol-for-a-door-on-a-floor-plan), [Engineer Fix](https://engineerfix.com/how-to-show-windows-on-a-floor-plan/))

## 1. דלתות — תוכנית (מבט-על)

### 1.1 אנטומיית הסמל (דלת-ציר בודדת)

שלושה פרימיטיבים בלבד, ותמיד אותם שלושה:

1. **קו-משקוף/פתח** — פער בקיר ברוחב הפתח (הקיר נקטע; אין קו-קיר בתוך הפתח).
2. **קו-כנף** — קו-ישר אחד מן ה**ציר** בניצב לקיר, באורך = רוחב-הפתח (הכנף פתוחה 90°).
3. **קשת-סיבוב** — רבע-עיגול (רדיוס = רוחב-הפתח) מקצה-הכנף החופשי אל הקצה-הרחוק של הפתח.

הציר = הנקודה שבה קו-הכנף פוגש את הקיר. הצד החופשי = הקצה השני של הפתח.

### 1.2 ארבעת כיווני-הפתיחה — הטבלה הקנונית

זהו בדיוק אוצר-המילים של InnoDraw/ORDX שכבר מקודד ב-`element_catalog.js`
(`Hinged Left In / Right In / Left Out / Right Out`) וב-`ElementCatalog.kt`
(`DOOR_IN_LEFT/RIGHT`, `DOOR_OUT_LEFT/RIGHT`). "צד" = צד-הציר בהסתכלות מתוך החדר
אל הקיר; "כיוון" = לאן נפתחת הכנף ביחס לחדר.

| מפתח-ORDX | עברית | ציר (hx) | בליטת-כנף | קשת בתיבת-היחידה |
|-----------|-------|----------|-----------|-------------------|
| `Hinged Left In` (`DOOR_IN_LEFT`) | דלת פנימה שמאל | שמאל (x≈0.04) | פנימה (y↓, אל 0) | מ-(0.04, top) אל הקצה הימני של הפתח, קמורה אל תוך החדר |
| `Hinged Right In` (`DOOR_IN_RIGHT`) | דלת פנימה ימין | ימין (x≈0.96) | פנימה (y↓, אל 0) | מ-(0.96, top) אל הקצה השמאלי, קמורה אל תוך החדר |
| `Hinged Left Out` (`DOOR_OUT_LEFT`) | דלת החוצה שמאל | שמאל | החוצה (y↑, מעבר ל-1) | הכנף והקשת מצוירות **מעבר לקיר** (y>1) |
| `Hinged Right Out` (`DOOR_OUT_RIGHT`) | דלת החוצה ימין | ימין | החוצה (y↑) | כנף+קשת מעבר לקיר, ציר בימין |

**איך קוראים זאת בשנייה אחת:** מאתרים את הציר (איפה קו-הכנף נוגע בקיר) → זהו הצד.
מסתכלים לאיזה חצי-מרחב הקשת בולטת → פנימה (לתוך החדר, y<1) או החוצה (y>1). זהו.

### 1.3 מימוש בפרימיטיבים (מתאים ל-`element_symbols_soline.js`)

הקוד הקיים כבר מכיל את הבסיס (`door_hinged_l`, `door_hinged_r`) — הרחבה ל-4 הכיוונים:

```js
// hinge='L'|'R' ; swing='in'|'out'. leafTop=0.06 בפנימה, ~1.94 בהחוצה.
function doorPlan(hinge, swing) {
  const hx = hinge === 'L' ? 0.04 : 0.96;   // צד-הציר
  const fx = hinge === 'L' ? 0.96 : 0.04;   // הקצה החופשי של הפתח
  const ty = swing === 'in' ? 0.08 : 1.92;  // קצה-הכנף: פנימה y→0, החוצה y→2
  const leaf = line(hx, 1.0, hx, ty);       // כנף פתוחה 90°, אנכית לקיר
  // רבע-קשת: bbox של עיגול רדיוס=1 סביב הציר; זווית-התחלה+כיוון לפי הרביע
  const bx0 = hx - 1, bx1 = hx + 1, by0 = 1.0 - 1, by1 = 1.0 + 1;
  const a0    = (hinge==='L') ? (swing==='in' ? 270 : 90 ) : (swing==='in' ? 180 : 180);
  const sweep = (hinge==='L') ? (swing==='in' ? 90  : -90) : (swing==='in' ? 90  : -90);
  const arcQ  = arc(bx0, by0, bx1, by1, a0, sweep);
  return [ line(0, 1, hx, 1), line(fx, 1, 1, 1), leaf, arcQ ]; // קצוות-פתח + כנף + קשת
}
```

> הערכים המדויקים ל-`a0/sweep` נגזרים מהרביע: הקשת חייבת לצאת מקצה-הכנף (hx,ty)
> ולהסתיים בקצה-החופשי (fx,1). זהו בדיוק הדפוס של `door_hinged_l/​_r` הקיימים —
> יש רק לשקף אנכית עבור `out` (ty מעל 1) ולהחליף צד עבור `R`.

### 1.4 טיפוסי-דלת מיוחדים — כל אחד וסימנו החד-משמעי

| טיפוס | עברית | סימן-התוכנית (המוסכמה שהנגר מזהה) | פרימיטיבים |
|-------|-------|-----------------------------------|-------------|
| **דלת-ציר** | דלת רגילה | קו-כנף + קשת-רבע (§1.2) | `line`+`arc` |
| **דלת כפולה** | דו-כנפית | שתי כנפיים+שתי קשתות נפגשות במרכז-הפתח | `door_double` (קיים) |
| **דלת הזזה** | דלת הזזה | פאנל-מלבן על מסילה מקווקוות + חץ-כיוון-החלקה; **אין קשת** | `door_sliding` (קיים) |
| **דלת-כיס** | Pocket | פאנל שנסוג לתוך מלבן-עבה בתוך הקיר (הכיס), קו מקווקו; אין קשת | מלבן-כיס בתוך הקיר + פאנל חלקי |
| **דלת מתקפלת** | אקורדיון/Bi-fold | שרשרת משולשים/זיגזג בין המשקופים; אין קשת רציפה | `door_folding` (קיים, poly-זיגזג) |
| **דלת נסתרת** | Concealed | אותה קשת אך **בקו מקווקו** (פתח נסתר בקיר) | `door_concealed` (dash) |
| **דלת ממ״ד** | דלת-פלדה ממ״ד | קשת רגילה + קו-כנף **עבה** (wt) + תווית `ממ״ד` | `door_mamad` (קיים) |
| **דלת-כניסה/פלדלת** | דלת-חוץ ביטחונית | קו-כנף עבה (wt≈1.6) + קשת; קו-סף עבה על הפתח | `door_entrance` (קיים) |
| **מפתח עם משקוף** | Doorway w/ Frame | שני קווי-משקוף קצרים בשני צדי-הפתח, **בלי כנף ובלי קשת** | `doorway_frame` |
| **מפתח בלי משקוף / מעבר** | Passage | רק פער בקיר עם שני קווי-קצה קצרים; אין כנף/קשת | `passage` (קיים) |

**הבחנות שהנגר קורא מיידית:**
- **קשת = מסתובבת** ; **חץ ישר = מחליקה** ; **זיגזג = מתקפלת** ; **מלבן-בתוך-קיר = נכנסת לכיס**.
- **קו-מלא = פנימה** (הכנף בתוך החדר) ; **קו-מקווקו על הקשת = פתח נסתר/מעל-הראש**.
- **פאנל עבה = דלת-חוץ/ביטחון** ; **תווית = ייעוד** (ממ״ד/כניסה).

מקורות: [Coohom — כיוון-דלת](https://www.coohom.com/article/decoding-the-door-symbol-in-floor-plans-what-my-remodel-taught-me),
[RoomSketcher — סמלי-תוכנית](https://www.roomsketcher.com/blog/floor-plan-symbols/),
[DOZR — קיר/דלת/חלון](https://dozr.com/blog/floor-plan-symbols),
[EdrawMax — סמלי-דלתות](https://edrawmax.wondershare.com/templates/door-symbols.html).

## 2. דלתות — חזית (elevation)

בחזית **אין קשת-סיבוב**; במקומה **קווי-V מקווקווים** (dashed) על פני הכנף:
שני קווים אלכסוניים שמתכנסים לקודקוד אחד. **הקודקוד = מיקום הציר (הצירים).**
([Casement/opening V-lines, Doorwin](https://www.doorwinwindows.com/casement-window/casement-window-opening-symbols-a-comprehensive-guide))

- דלת-ציר בחזית: מלבן-הכנף + שני אלכסונים מקווקווים מהפינות אל אמצע-הצד שבו הציר.
  אם הקודקוד בצד-שמאל של המלבן → צירים משמאל; אם בימין → מימין.
- **פנימה מול החוצה בחזית:** מוסכמה נפוצה — **קו-מלא = נפתח לעברך (החוצה, מהצד שאתה
  עומד בו) ; קו-מקווקו = נפתח ממך (פנימה)**. יש לקבוע מוסכמה אחת עקבית ולתעד במקרא.
- דלת-הזזה בחזית: שני מלבנים חופפים + חץ אופקי.

## 3. חלונות — תוכנית (מבט-על)

### 3.1 ייצוג-הבסיס (הפרוסה בגובה-החתך)

חלון נחתך בקיר, ולכן בתוכנית רואים **פרוסה** בתוך עובי-הקיר:

1. **שתי קווי-מסגרת** מקבילים לקיר (הפנים-והחוץ של המשקוף) — בקוד: `rect(0, 0.36, 1, 0.64)`
   בתוך רצועת-הקיר.
2. **קו-זכוכית** אחד (או שניים) באמצע הרצועה — `line(0, 0.5, 1, 0.5)` — מייצג את השמשה.
3. הקצוות סגורים (הפתח מוקף מסגרת, בשונה מדלת שבה הפתח "פתוח").

זהו `window` הקיים. הבחנה חשובה: **דלת קוטעת את הקיר לגמרי ; חלון משאיר "פרוסת-זכוכית"
בתוך עובי-הקיר** — כך מבחינים ביניהם במבט-על. ([Engineer Fix](https://engineerfix.com/how-to-show-windows-on-a-floor-plan/), [Cedreo](https://cedreo.com/blog/floor-plan-symbols/))

### 3.2 סוגי-חלון וסימונם בתוכנית

| טיפוס | עברית | סימן-תוכנית | פרימיטיבים (קיים/מוצע) |
|-------|-------|--------------|-------------------------|
| **קבוע** | אשנב/קבוע | שתי קווי-מסגרת + קו-זכוכית יחיד; **בלי חץ/קשת** | `window` |
| **מדף (casement)** | ציר-צד | קו-זכוכית + **קשת-רבע מקווקוות** אל תוך/מחוץ לחדר (כמו דלת קטנה בתוך הקיר) | `window_casement` (קיים) |
| **הזזה** | הזזה אופקית | שתי מלבנים חופפים/מוסטים + **שני חצים אופקיים** מנוגדים | `window_sliding` (קיים) |
| **נטוי (awning/hopper)** | ציריות עליונה/תחתונה | קו-זכוכית + **משולש/V** שקודקודו בצד-הציר | `window_tilt` (קיים, poly-משולש) |
| **קיפ-דרeh (tilt-turn)** | קיפ | **גם משולש-נטייה וגם קשת-סיבוב** על אותו פתח (שני מצבי-פתיחה) | הרכבה: `window_tilt`+`window_casement` |
| **פינתי** | חלון-פינה | שתי רצועות-זכוכית בזווית בשתי קירות נפגשות בפינה | `window_corner` (קיים) |
| **ראווה/ויטרינה** | Storefront | רצועה רחבה מחולקת ל-2–3 שדות בקווי-חלוקה אנכיים | `window_storefront` (קיים) |
| **צוהר** | Porthole | עיגול עם צלב-מרכז | `window_porthole` (קיים) |
| **לבני-זכוכית** | Glass block | רשת ריבועים בתוך הרצועה | `window_glassblock` (קיים) |
| **קטן/גבוה** | חלונית | רצועה מקוצרת (רוחב חלקי) | `window_small` (קיים) |

### 3.3 סימון כיוון-הפתיחה של חלון בתוכנית

חלון-מדף (casement) הוא היחיד שמראה כיוון-פתיחה בתוכנית, בדיוק כמו דלת מוקטנת:
**קשת-רבע מקווקוות** מקצה-השמשה. הקשת **אל תוך החדר (y<0.5) = נפתח פנימה** ;
**אל מחוץ לחדר (y>0.5) = נפתח החוצה**. צד-הקשת = צד-הציר. חלון-הזזה מסומן בחצים
במקום קשת; חלון קבוע — ללא כל סימן. ([EdrawMax — סמלי-חלון](https://edrawmax.wondershare.com/templates/window-symbols.html), [PlanSnapper](https://plansnapper.com/symbols/window))

## 4. חלונות — חזית (elevation): כאן נקרא כיוון-הפתיחה במלואו

החזית היא המבט שבו **כל** סוגי-החלון מראים כיוון-פתיחה, דרך **קווי-V/משולש מקווקווים**.
**הקודקוד של ה-V = צד-הציר. פתיחת-ה-V (הבסיס הרחב) = הצד שנפתח (זז).**
זו המוסכמה הבין-לאומית: קווים מקווקווים המתכנסים לקצה — הקצה הוא הציר התאורטי.
([Doorwin — V-symbol](https://www.doorwinwindows.com/casement-window/casement-window-opening-symbols-a-comprehensive-guide), [Wikipedia — Casement](https://en.wikipedia.org/wiki/Casement_window))

| טיפוס | סימן-חזית (V/משולש מקווקו) | קריאה |
|-------|----------------------------|-------|
| **קבוע** | ללא כל קו | לא נפתח |
| **casement שמאל** | V שקודקודו ב**שמאל**; פתיחה מימין | ציר בשמאל, נפתח לצד |
| **casement ימין** | V שקודקודו ב**ימין** | ציר בימין |
| **awning (מדף-עליון)** | משולש שקודקודו ב**מעלה** (בסיס למטה) | ציר למעלה, נפתח החוצה מהתחתית |
| **hopper (מדף-תחתון)** | משולש שקודקודו ב**מטה** (בסיס למעלה) | ציר למטה, נפתח פנימה מהחלק העליון |
| **tilt-turn (קיפ)** | **גם** V-צד **וגם** משולש-קודקוד-למטה על אותה שמשה | שני מצבים: סיבוב-צד + הטיה-קיפ |
| **הזזה** | חץ אופקי על השמשה הנעה (בלי V) | מחליק אופקית |
| **double-hung (גליון)** | חץ אנכי על הכנף הנעה | מחליק אנכית |

**מוסכמת קו-מלא מול מקווקו (מומלץ לאמץ ולתעד במקרא):**
בחלק מהתקנים **פתיחה-החוצה = קו-מלא, פתיחה-פנימה = קו-מקווקו**; באחרים כל קווי-הפתיחה
מקווקווים וההבחנה נעשית בסכמת-מקרא. Soline תאמץ מוסכמה אחת: **קווי-פתיחה תמיד
מקווקווים, קודקוד-ה-V מציין ציר, ותווית-ייעוד (`קיפ`/`הזזה`) ליד הפתח למקרי-קצה.**
([מקורות בין-לאומיים על פנים/חוץ = מקווקו/מלא](https://en.wikipedia.org/wiki/Casement_window))

## 5. מקרא (Legend) — חובה בכל גיליון

תוכנית מקצועית כוללת **מקרא-פתחים** בפינת-הגיליון, כדי שהמוסכמה תהיה חד-משמעית
גם ללקוח שאינו אדריכל. מינימום נדרש:

- דוגמת דלת-ציר עם ציון: *קשת = כיוון-פתיחה, מיתר-הקשת = רוחב-פתח, ציר = בקצה-הכנף*.
- ארבעת כיווני-הדלת (In/Out × L/R) בזעיר.
- דוגמאות חלון: קבוע / casement (קשת) / הזזה (חצים) / קיפ (V+משולש).
- הבחנת קו-מלא מול מקווקו אם משתמשים בה.

בנוסף — **טבלת-פתחים (schedule)**: לכל פתח מזהה (D1, W1…), טיפוס, רוחב×גובה, כיוון-פתיחה.
זו הדרך התקנית להעביר את גובה-הפתח (שאינו נראה בתוכנית) ואת הפרטים ללקוח/ליצרן.
([BigRentz — schedule](https://www.bigrentz.com/blog/floor-plan-symbols), [RoomSketcher](https://www.roomsketcher.com/blog/floor-plan-symbols/))

## 6. שכבות-CAD ייעודיות (כבר קיים באפליקציה)

מדריך-CVSM מגדיר שכבת-תצוגה נפרדת **"כיוון פתיחת דלתות"** שניתן להדליק/לכבות
ולצבוע בנפרד מ"קירות" ו"אביזרים" (`ops/docs/cvsm_reference/CVSM_guide_he.html`,
מסך "הגדרות תצוגה"). המלצה ל-Soline: להחזיק שכבות נפרדות —
`OPENINGS_FRAME` (משקוף/פתח), `DOOR_SWING` (קשתות+כנפיים), `WINDOW_GLAZING`
(מסגרת+זכוכית), `OPENING_TAGS` (מזהים+טבלה) — כדי שכיווני-הפתיחה יודלקו/יכובו וייצבעו
בלי לגעת בשאר השרטוט. חלוקה זו גם מתיישרת ל-`discipline: door|window|opening`
שכבר קיים ב-`element_symbols_soline.js`.

## 7. תמצית-יישום ל-DXF/PDF (חוזה למייצאים — הם מבצעים)

1. **ציר בקצה-הכנף:** בכל דלת, נקודת-החיבור כנף↔קיר = הציר. סוב `hinge` קובע צד.
2. **קשת = רבע-עיגול, רדיוס = רוחב-הפתח, מרכז = הציר.** בליטה פנימה (y<1) או החוצה (y>1)
   לפי `swing`. זהו הפלט של `symbolFor(item).plan` → `toDxf2dGlyph`.
3. **חלון = מסגרת+זכוכית בתוך עובי-הקיר** (`z=-100` בקטלוג = שקוע); casement מוסיף קשת.
4. **חזית:** קווי-V מקווקווים; קודקוד=ציר. ל-awning/hopper משולש אנכי; ל-קיפ שניהם.
5. **תמיד** לצרף מקרא + טבלת-פתחים; גובה-הפתח נמסר בטבלה, לא בתוכנית.
6. כל הסמלים כבר במערכת-הקואורדינטות של `element_symbols_soline.js` — אין צורך בהמרה
   ידנית; המייצא קורא `plan[]`/`elev[]` ומצייר.
