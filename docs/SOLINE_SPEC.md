# SOLINE — מפרט-בנייה מקיף (Clean-Room Specification)

> **מטרת המסמך:** מפרט **עצמאי ומלא** לבניית אפליקציית-המדידה של Soline **מאפס**, נקי לחלוטין
> מכל ביטוי, שם, מבנה-קוד או פורמט של תוכנה אחרת. המסמך מתאר **מה** התוכנה עושה ו**איך** —
> ברמת רעיונות, עובדות-דומיין ותקנים (בלתי-מוגנים) + החלטות-העיצוב המקוריות של Soline.
>
> ⚖️ **אילוץ חדר-נקי (מחייב את המממש):** בונים אך-ורק מהמסמך הזה. **אין** להתייחס, לפתוח,
> להנדס-לאחור או לשכפל שום תוכנה אחרת (CVSM/RoomMeasure, InnoDraw/eLCad/Raumplan, Cabinet
> Vision או כל מוצר). **אין** להשתמש בשמותיהם, במספרי-סעיפים שלהם, בשמות-פונקציות/שדות
> שלהם, או בפורמטי-הקבצים הקנייניים שלהם. הליבה מייצאת רק פורמטים **שבבעלות Soline** (‏.sol‏)
> ותקנים **פתוחים** (DXF, PDF). כל התאמה לפורמט-צד-שלישי היא מודול-אופציונלי נפרד (§14).

---

## 0. עקרונות-על

1. **המשתמש = מודד-בשטח.** כל החלטת-UX משרתת מדידה מהירה, יד-אחת, אור-שמש, לחץ-זמן.
2. **Offline-first.** הכל עובד בלי רשת; סנכרון/גיבוי הם שכבה-עליונה אופציונלית.
3. **מקור-אמת יחיד לכל דבר.** מבנה-נתונים אחד, פונקציית-גאומטריה אחת, שרטוט-אחד.
4. **עברית, RTL, לשון-זכר.** יחידות מ"מ פנימית; תצוגה בס"מ/מ' לפי-העדפה.
5. **שמרנות-נתונים.** מיגרציות-DB תוספתיות בלבד (ALTER/CREATE), אף-פעם לא מוחקות מדידות.
6. **שער-איכות לפני-ייצוא.** לא מייצאים מדידה חסרה/לא-תקינה בלי שהמודד ידע.

---

## 1. חזון והיקף

**Soline** היא אפליקציית-אנדרואיד למודד-מטבחים/נגרות: המודד נכנס לבית, מודד חדר בעזרת
מדי-לייזר (BLE), משרטט את החדר חי על המסך, מוסיף אלמנטים (שקעים/דלתות/חלונות/מכשירים),
מצלם, בודק את עצמו, וסוגר — ומפיק **קובץ-מדידה** שממנו המשרד/הנגר עובד.

**רכיבי-המערכת:**
- **אפליקציית-המדידה** (Android/Kotlin/Compose) — המוצר המרכזי, נושא מסמך זה.
- **פורמט `.sol`** — מיכל-המדידה של Soline (§10).
- **ממיר-ייצוא** — `.sol` → DXF/PDF (תקנים-פתוחים) (§11). *(אינטרופ לפורמט-צד-שלישי = §14, מחוץ-לליבה.)*

---

## 2. ארכיטקטורה

- **פלטפורמה:** Android (minSdk 26, targetSdk 35), Kotlin, **Jetpack Compose** + Material 3.
- **מסד:** **Room** (SQLite), offline-first, מיגרציות מפורשות + `exportSchema`.
- **BLE:** Android BluetoothLE (GATT).
- **ניווט:** Navigation-Compose (route-based).
- **מבנה-חבילות** (`app/src/main/kotlin/<domain>/`):
  - `data/` — ישויות-Room, DAO, Repo (שכבת-גישה), Prefs, מאגרי-עזר (לקוחות, סמלים-מותאמים).
  - `geometry/` — מנוע-הגאומטריה (בונה-קירות, פותר-עמדה, טרילטרציה, פרופיל-קיר).
  - `device/` — הפשטת-לייזר-BLE + מנהלי-מכשיר.
  - `catalog/` — קטלוג-האלמנטים + הסמלים.
  - `export/` — כותב/קורא `.sol`.
  - `ui/` — מסכי-Compose (בית, מנוע-מדידה, אלמנט, חזית, אימות, סגירה, הגדרות, באגים).
  - `fit/` — שער-אימות (ולידציה) + התאמת-אלמנטים.

## 3. תזרים-השדה של המודד (הליבה — 13 שלבים)

זהו **הצפון של המוצר** (מקורי-Soline). המנוע חייב להוביל את המודד לאורכו:

1. יוצא מהאוטו; הפרויקט כבר-מוקם במערכת (הקמה-מראש — פיתוח-עתידי).
2. בדרך-לבית סוקר **דרכי-גישה** וממלא (גודל-מעלית בלייזר, גישת-מנוף, מעברים-צרים).
3. נכנס לבית ולחדר-הראשון.
4. מסתכל על החלל ובוחר **שיטת-מדידה**.
5. עובר עם **לייזר-קטן (D2/בוש)** ונותן כמה **מדידות-גובה** + פיצ'ר **מין/מקס-גובה** (שיפוע-תקרה).
6. עומד עם **X6** ועובר על הקירות **P2P** מעמדה-אחת → בונה את הקירות.
7. במידת-הצורך מודד את **החזית** עצמה עם ה-X6 (ירי-נקודות → גאומטריית-קיר-אמיתית).
8. **או** מצייר את **צורת-החדר באצבע** על המסך ואז **מזריק את המידות** עם הלייזר.
9. מוסיף **אלמנטים** לפי מרכזים/היסטים (בחירתו) וממלא נתונים.
10. מוסיף **הערות per-אלמנט** (מה שהנגר צריך לדעת).
11. אחרי כל-חזית, **מצלם** את איזור-המדידה.
12. **בודק את עצמו ב-3D** — כל מה שרואה-בעין קיים-בשרטוט.
13. עובר **צ'קליסט סגירת-חדר**, סוגר, ועובר לחדר-הבא.

## 4. מנוע-המדידה המאוחד (מסך-אחד)

**עיקרון-הליבה (מקורי, מחייב):** מסך-אחד עם **קנבס-מתאר אחד ומתמיד** שמציג תמיד את אותם קירות
מה-DB. השיטות רק **מזינות/עורכות** את אותו מתאר — **מעבר-שיטה לעולם לא-מוחק ולא-מחליף את
השרטוט**. הקנבס תומך **זום (צביטה) + הזזה + double-tap-איפוס**.

**מבנה-המסך:**
- סרגל-עליון: יציאה · שם-חדר · תחנה N/סה"כ · חיווי-חיבור-לייזר · קריאה-חיה (ס"מ).
- **סרגל-תחנות אופקי** (ניווט-ראשי, עמיד לאורך+לרוחב): גישה → שיטה → קירות → חזיתות → אלמנטים → תמונות → 3D → סגירה. ✓ מגובה-בנתונים.
- **קנבס-מתמיד** (מרכז): מבט-על 2D, קירות ראש-לזנב, מידות+זוויות בעברית, בליטות, שכבות-תצוגה נדלקות/כבות.
- **פאנל-תחנה** (תחתון): תוכן משתנה לפי-התחנה.

**שיטת-המדידה = "שרטוט" אחד מאוחד** (מקורי, מחייב): כל שיטות-הקלט מתאחדות למסך-שרטוט אחד —
לייזר (כל-מכשיר) **וגם** מטר-ידני, **הזרקה פר-קטע**:
- המודד מקיש **פינות** → מתאר-גס.
- בוחר קטע → **מזריק אורך** (ירי-לייזר או הקלדה).
- זוויות נגזרות מהסקיצה (מוצמדות ל-0/45/90/135), אורכים מהמדידה.
- ברירת-מחדל 90°; אפשר זווית-ידנית; **שרטוט-פתוח מותר** (אין חובת מצולע-סגור).
- הסקיצה **מוסיפה לקירות-הקיימים** (לא-מוחקת).
- שיטה-משלימה: **P2P מעמדה-אחת** (X6) — בונה מתאר-מלא מעמדה קבועה.

## 5. חיבור-מכשירים (BLE)

- הפשטה `LaserDevice` עם StateFlow: `connected: String?`, `lastReading: Reading?` (מרחק-מ"מ + זווית-אנכית + מונה), `status`.
- מד-לייזר מדבר לפי **פרוטוקול-ה-GATT הציבורי של היצרן** (Leica DISTO / Bosch GLM) — UUIDs + מבני-פריים המוכתבים ע"י החומרה (אין המצאה; זהה לכל אפליקציה שמדברת עם אותם-לייזרים).
- סריקה → חיבור → subscribe ל-notify/indicate → פענוח-פריים (float32-LE מרחק) → StateFlow.
- X6/DST-360: פקודת-הפעלת-מדידה-P2P לפי פרוטוקול-המכשיר; זווית-אופקית מה-DST.
- **הערה:** כל פרטי-הפרוטוקול נלמדים מ**לכידת-BLE-חיה** מול המכשיר או ממפרט-היצרן — לא מתוכנה אחרת.

## 6. גאומטריה (מתמטיקה-סטנדרטית)

כל הפונקציות = מתמטיקה-ידועה (רעיונות/שיטות בלתי-מוגנים), ביטוי-Kotlin מקורי:
- **בונה-קירות (`WallBuilder`):** פורס רשימת-קירות (אורך + זווית-פנייה) ל-polyline. מוסכמה: זווית-הקיר = הפנייה **אחריו** אל הבא (heading += angle, חיובי = CCW). כלים: פער-סגירה, זיהוי-סגירה, זווית-סוגרת, חיבור-T (הצמדת-קצה-ניצב), הזזה-ניצבת (עומק פנים/חוץ), בונה-חדר-90°.
- **פותר-עמדה (P2P):** נקודות-מישור מ-(מרחק, זווית): `x=r·cosφ, y=r·sinφ`. זווית-פינה מ-3-אורכי-צלעות (**חוק-הקוסינוסים**: `acos((a²+b²−c²)/2ab)`). כיוון-קיר מ-`atan2`.
- **טרילטרציה:** חיתוך שני-מעגלים; מיקום-פינה משני-מרחקים; היסטים-מ-datum.
- **פרופיל-קיר / חזית:** נקודות-מבט-על → מתאר-בטן; קשת-מ-3-נקודות; פרופיל-ראש-קיר (ישר/משופע/גמלון).

## 7. מודל-האלמנטים (אלמנטי-אמת)

**עובדות-דומיין** (בלתי-מוגנות): רשימת אלמנטי-בנייה אמיתיים + מידות-סטנדרט (ממקורות-שלכם/תקנים).
קבוצות: חשמל · אינסטלציה · מוצרי-חשמל · סניטרי · דלתות · חלונות · מיזוג-ואיוורור · מבנה-ותקרה · מטבח-חוץ · הערות · סימון.

**`ElementDef`** (הגדרת-אלמנט): מזהה-יציב (key), שם-עברי, קבוצה, עומק-בליטה ברירת-מחדל, עגול?, יש-עומק?, ומידות-סטנדרט אופציונליות (רוחב/גובה קבועים-אך-ניתנים-לעריכה — מקרר/תנור/שקע). אלמנט "מידות-קבועות" מגיע ממולא-מראש; "מידות-משתנות" נמדד-מאפס.

**פתחים פרמטריים** (`OpeningSpec`, דלת/חלון/מיזוג): רוחב/גובה/סף/עובי-קיר/עובי-משקוף/חשפה/עובי-כנף/מנגנון-פתיחה/צד-ציר/כיוון/מספר-כנפיים/זיגוג — **מידות-יצרן כברירת-מחדל בלבד**, שהמודד דורס במידת-שטח. מקורות-מידה: תקני-ת"י/פיקוד-העורף/קטלוגי-יצרן פומביים (עובדות).

**`AccessoryEntity`** (אלמנט-מדוד על-קיר): type, שם, עומק, fromLeft, רוחב, גובה-מהרצפה, גובה, פינת-מדידה (start/end), שדות-פתח, `measured` (נמדד-מול-ברירת-מחדל), **`notes` (הערת-מודד)**. מיקום נמדד מ**מרכז** (מיקום+רוחב) או **היסטים-מפינות** (רוחב-מחושב); מיקום-אנכי **מהרצפה או מהתקרה**.

> **מיפוי-ייצוא:** ה-key/type הם **מקוריים-שלכם**. מיפוי לפורמט-צד-שלישי (מזהי-מחלקה/סוג) שייך למודול-האינטרופ (§14), לא לליבה.

## 8. מודל-נתונים (סכמת-DB)

מודל-דומיין **מקורי** המוכתב מהבעיה: `Project → Room → Wall → Accessory`, + טבלאות-משנה.

- **Project:** id, name, client, createdAt, lastExportedAt, closedAt?, jobId (קישור-אינטייק).
- **Room:** id, projectId, name, כיוון-כניסה (bearing/wallIdx/טקסט), **heightSweepMm** (CSV גבהי-תקרה; מחייב=מינימום), **futureChanges** (הערות-שינויים), mediaSkips, closedAt.
- **Wall:** id, roomId, idx, length, height, **angle** (לקיר-הבא), framePointsJson (מתאר-חזית), wallProfileJson (בטן+מסגור), headStyle/ridge/peak (ראש-קיר), **heightMeasured** (נמדד-מול-defaulted), soffitHeightMm? (קו-סימון).
- **Accessory:** כמפורט §7 (כולל notes, opening-params).
- טבלאות-נוספות: Cabinet (ארונות), Carpenter (נגר), Job (אינטייק: כתובת/גישה/איש-קשר), LevelPoint (סקר-מישוריות), CustomSymbol, Photo, Video, (+ טבלאות-מדדים-תפעוליים צד-משרד, בהסכמה).
- **מיגרציות:** תוספתיות בלבד, נשמרות בבקרת-גרסאות (schema JSON פר-גרסה), נבדקות ב-MigrationTest.

## 9. פורמט `.sol` (מיכל-המדידה של Soline — מקורי)

**ZIP (deflate) של JSON + מדיה.** מקורי-לחלוטין. מבנה:
- `manifest.json` — `format:"sol"`, `magic:"SOL1"`, `schemaVersion`, `units:"mm"`, מפת-שכבות (present/path), coordinateSystem, revision, encryption-hook.
- `meta.json` — projectId, name, client, createdAt, ownership.
- `measured/room-<id>.json` — חדר → קירות (length_mm/height_mm/angleToNext_deg/soffit/heightMeasured/framePoints/head) → אלמנטים (type/name/dims/fromLeft/measured/notes + בלוק-opening פרמטרי) → ארונות. + בלוק-סקר (גבהים/שינויים).
- `annotations.json` — מטא-תמונות/וידאו + צ'קליסט.
- `revisions.json` — היסטוריית-גרסאות (stub).
- `photos/`, `videos/` — בייטים.
- שכבות-עתיד (design/fit/catalog/bom/3d) — דגלי present=false.

**קורא-`.sol` (`SolReader`):** ההופכי — קורא ZIP, מפענח meta + rooms, משחזר פרויקט-חדש ל-DB.

## 10. ייצוא ודו"חות (ליבה = פורמטים-שלכם + תקנים-פתוחים)

- **`.sol`** — הפורמט-שלכם (§9). מקור-האמת להעברה למשרד.
- **DXF** — תקן-CAD **פתוח ומתועד-פומבית** (AutoCAD DXF). Soline מייצר DXF **משלו**: שכבות בשמות-Soline, גיאומטריה-מקורית, סמלים-מקוריים. (ספריית-בלוקים נבנית ב**חדר-נקי** — §13.)
- **PDF** — דו"ח-מדידה מעוצב (טקסט/מידות/תמונות).
- **גיבוי-אוטומטי:** בהגשה, `.sol` → תיקיית-Drive `[לקוח]/[פרויקט]/project.sol` (SAF).
- ⚠️ **מחוץ-לליבה:** ייצוא לפורמט-קנייני-של-צד-שלישי (למשל ORDX/PDP) — **לא חלק מהמפרט הזה** (§14).

---

## 11. שער-אימות + סגירת-חדר

- **שער-אימות (Verify):** לפני-ייצוא רץ ולידציה: לכל-קיר אורך>0 (חוסם) + גובה-מדוד (מתריע), רוחב-לאלמנט, עומק-היכן-שנדרש, גובה-מינימלי-סביר (מתריע), אורכים-בטווח-שפיות. **שרטוט-פתוח מותר** (מין-קירות/מצולע-סגור = מידע, לא-חוסם). ממצאים: חסימה/אזהרה/מידע. ייצוא נדלק רק ללא-חסימות.
- **בדיקת-התאמה (Fit):** בשלב-הייצוא/הדו"ח — מאחד חשיבת-מודד+נגר (אלמנט-חורג-מקיר, מפלס-רצפה↔צוקל, וכו').
- **סגירת-חדר:** צ'קליסט-מדיה קשיח-עם-מוצא ("דלג עם-סיבה"); סגירה מסמנת closedAt.

## 12. מערכות-תומכות

- **מרכז-באגים דו-כיווני:** המודד מדווח 🐞 מכל-מסך (צילום-מסך + הערה) → SAF-אוטומטי לתיקיית-Drive. סטטוסים + תור-בדיקות-חוזרות מסונכרנים דרך JSON ב-Drive. "הבאגים שלי" מציג את כל-הבאגים מכל-המכשירים המקושרים. כלל-קבע: **כל תיקון עובר אימות** לפני-סגירה.
- **גיבוי + מאגר-לקוחות:** מאגר-לקוחות (אדמין) עם תיקיית-Drive פר-לקוח; גיבוי-אוטומטי + שחזור-מ-Drive (בורר `.sol`).
- **אינטייק:** טופס-פתיחת-פרויקט (מפעל מרשימה, כתובת-מובנית, מידות-מעלית-בלייזר, נוכחות-לקוח, הערות).
