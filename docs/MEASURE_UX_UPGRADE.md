# מסך-מדידה מאוחד — שדרוג-UX (Invested UX/UI Upgrade Spec)

> משדרג את `MEASURE_SCREEN_MOCKUP.html` (v1, מאושר) ל-**V2** (`MEASURE_SCREEN_MOCKUP_V2.html`).
> נאמן ל-`UNIFIED_MEASURE_ARCHITECTURE.md` (מתאר-אחד · כלים כותבים אליו · מעבר-כלי לא-מוחק),
> ל-`MEASURE_ENGINE_SPEC.md` (3 שיטות · פרובננס · לכידה-ענקית) ול-`FIELD_WORKFLOW_QA.md` (צ'קליסט-פתח · שער-שלמות).
> רפרנס-סגנון: elcad — קנבס-מרכזי נקי, מסך-מדידה-אחד — "כמו זה, אבל הרבה יותר מושקע ב-UX/UI".

## 0. עקרון-מנחה
**הקנבס הוא הגיבור.** כל כרום (chrome) — סרגל, קריאה, לכידה, פאנלים — משרת את המתאר ואף-פעם לא-מתחרה בו על תשומת-הלב. מדידה-בשמש עם כפפות ביד-אחת: כל יעד-מגע ≥56px, ניגודיות-גבוהה, קריאה-חיה קריאה ממטר.

## 1. מבנה-הפריסה (Landscape-first, Portrait-safe)
טאבלט **שוכב על השולחן** ליד הקיר הנמדד → V2 מתוכנן לרוחב, עם grid בן 3-שורות:

```
┌──────────────────────────────────────────────┬──────┐
│  soline · מטבח   [X6 מחובר] 🔋   ⟨ 234.5 cm ⟩ │      │  שורה 1 — סרגל-עליון (משתרע על הכל)
├──────────────────────────────────────────────┤ סרגל │
│  ┌ מידות ┐                       ┌ הוספת ┐    │ כלים │  שורה 2 — קנבס | rail
│  │ פאנל  │      קנבס-מתאר         │ אלמנט │    │ (צד  │
│  └───────┘      L-shaped          └───────┘    │ ימין)│
│  [＋/－]                   ✋מצב-כלי            │      │
├──────────────────────────────────────────────┴──────┤
│  ↩  ●●●◉○○ קיר 4/6   [ ◉ קלוט מדידה ]  💡 רמז  📷   │  שורה 3 — סרגל-לכידה (משתרע)
└──────────────────────────────────────────────────────┘
```

- **סרגל-עליון + סרגל-לכידה משתרעים על-כל-הרוחב** (כולל מעל/מתחת ל-rail) — נותן לקנבס את מלוא-הגובה בין שתי-רצועות-עוגן קבועות. הפריסה הזו נותנת **קנבס גדול ב-~30%** מ-v1.
- **סרגל-הכלים בצד-ההתחלה של RTL (ימין)** — נגיש לאגודל-ימין כשמחזיקים טאבלט ביד-אחת, ולא-חוסם את הקנבס.
- **פאנלים צפים בפינות-הקנבס** (מידות משמאל-למעלה, הוספת-אלמנט מימין) במקום סרגל-תחתון-קבוע כמו ב-`ARCHITECTURE §1` — שומר על קנבס-רציף ומאפשר להזיז/לסגור.

## 2. סרגל-הכלים (Tool Rail)
- **8 כלים, מקובצים לפי-כוונה** עם `railsep` בין קבוצת-המדידה לקבוצת-האלמנטים:
  קבוצת-שיטה: 📡 לייזר · ✏️ שרטוט · ✍️ מטר · 🎯 P2P · ▭ תבנית — כולם כותבים לאותו-מתאר (`ARCHITECTURE §2`).
  קבוצת-בנייה: 🚪 אלמנט.
  קבוצת-פעולה (מוצמדת לתחתית עם `spacer`): ↩ בטל · ✓ סיום.
- **הכלי-הפעיל בטיל (teal) מלא + צל** — הדגשה חד-משמעית, לא-רק צבע-טקסט (נגישות בשמש).
- **✓ סיום בירוק-OK** — צבע-מצב שונה מהכלים, כי זו פעולת-שער (`QA §4`).
- כל טיל 60×56 עם אייקון+תווית — glove-friendly, וקריא בלי-לזכור-אייקונים.

## 3. הקריאה-החיה (Live Readout) — הגיבור-המשני
- **מלבן-כתום מודגש** (accent-soft על גבול-accent) בפינת-סרגל-עליון — לא-רק טקסט-צף כמו ב-v1. הופך את הקריאה ל"תג-חי" שהעין קופצת אליו.
- מספר ב-Poppins 38px + יחידה `cm` נפרדת + תווית-הקשר `קיר 4 · לייזר` → המודד רואה **ערך + לאן-הוא-הולך + מקור** בלי-להסיט-מבט.
- **מקור-המדידה (פרובננס)** מוצג תמיד (`ENGINE §1`): לייזר/מטר/P2P — כי אמון-הנתון תלוי-מקור.

## 4. אפשרות-הלכידה (Capture Affordance)
- **כפתור ◉ "קלוט מדידה" ענק (58px, כתום, טבעת-מצלמה)** תופס את-מרכז-סרגל-התחתון — יעד-אגודל ברור בשמש.
- **מחוון-קיר-פעיל (wall-slot)** משמאלו: נקודות `●●●◉○○` שמראות התקדמות 4/6 + הקיר-הנוכחי בכתום → תחליף-ויזואלי ל-auto-advance (`ENGINE §2`), המודד יודע כמה-נשאר בלי-לספור.
- **רמז-הקשר** ("כפתור-הלייזר קולט אוטומטית") ליד-הכפתור — מזכיר את טריגר-המכשיר (יד-אחת, החלטה #2 ב-`ENGINE §4`).
- **בטל-ענק + צילום** בקצוות כ-mini-כפתורים (58px) — undo תמיד-בהישג-אגודל (`ENGINE Field-UX`), צילום פר-אלמנט (`QA §3`).

## 5. שמירת-המתאר במעבר-שיטות (Persistence)
- **המתאר צבוע פעם-אחת ב-SVG-משותף** — החלפת כלי משנה **רק** את הפאנל-הצף ואת הקריאה, לא-את-המתאר. זו הבטחת-הליבה של `ARCHITECTURE §0/§2`, ומשוקפת בכך שה-canvas SVG יושב בשכבה-נפרדת מכל-הכרום.
- **הקיר-הפעיל תמיד מודגש בכתום** (`wall-active`, קו-עבה 7px) בכל-שיטה — אז אחרי מעבר לייזר→P2P המודד רואה מיד היכן-הוא-אוחז.
- **פאנל-מידות** מציג את כל-6 הקירות + הפתחים בכל-רגע — מקור-אמת אחד גלוי, מתעדכן חי מכל-כלי.

## 6. הוספת-אלמנטים (Tap-Wall → Element)
זרימה: **בוחרים 🚪 אלמנט → מקישים על קיר → מופיע callout-כתום צמוד-לקיר עם 3-שדות** (רוחב · גובה · סף) → "הוסף פתח ✓".
- ה-callout מעוגן-לקיר-הנבחר (בקנבס V2 הוא על קיר-2) — הקשר-מרחבי ברור.
- **אלמנט-בתהליך-הצבה מוצג כרפאים (dashed כתום) על-הקיר** עם ידית-גרירה — המודד רואה איפה-זה-ייפול לפני-אישור, וגורר למיקום.
- **סמלים תקניים לפי-סוג:** דלת=קשת-אדומה, חלון=מלבן-כפול-כחול, פתח/גומחה=כתום. תואם `ENGINE Advanced·פתחים`.
- כל-פתח נושא W×H×סף בתווית-על-הקנבס — ממלא את צ'קליסט-3-הערכים-פר-פתח (`QA §3`).

## 7. מודל-המחוות (Gesture Model, ממותג-לפי-מצב)
הסיכון-המרכזי מ-`ARCHITECTURE §5`: אצבע-מציירת ↔ pan/zoom. פתרון-V2:
- **פּיל-מצב תמידי בתחתית-הקנבס** ("✋ מצב: הזרקת-לייזר · הקנבס נעול-לגרירה") — המודד תמיד יודע מה-אצבע-תעשה.
- **מצבי-קלט:** בכלי-שרטוט (✏️) → tap=קודקוד, שתי-אצבעות=pan/zoom. בכל-שאר-הכלים → אצבע-אחת=pan, צביטה=zoom, tap=בחירת-קיר/פתח. `detectTapGestures` רק ב-FINGER_DRAW.
- **כפתורי zoom ＋/－ מפורשים** בפינה — גיבוי-לצביטה בשמש/כפפות, וזום-מדויק.
- **נעילת-קנבס** מרומזת ע"י הפּיל — מונע-הזזה-בטעות בזמן-מדידה (`ENGINE Field-UX`).

## 8. טיפול-בלרוחב (Landscape Handling)
- Grid 3-שורות (`auto 1fr auto`) → הקנבס תמיד-`1fr`, נמתח-לגובה-הזמין; שתי-הרצועות קבועות-גובה.
- הפאנלים-הצפים `position:absolute` בפינות → לא-דוחפים-פריסה, ואם-הקנבס-קטן הם `overflow`-ניתן-לגלילה בתוכם, לא-חותכים תוכן.
- ה-rail `overflow-y:auto` → אם יתווספו-כלים עתידיים (`ARCHITECTURE §3` — כלי=מימוש-חוזה+שורה), הוא נגלל בלי-לשבור-פריסה.
- **Portrait-safe:** אותו-grid מתקפל אנכית; הפאנלים-הצפים נשארים-בפינות. (ה-mockup ממוקד-לרוחב לפי-הבריף).
