# תור-פיצ'רים לאפליקציה — מצטבר ל-APK-של-סוף-סשן

> הבעלים ביקש **לא-להתקין פר-תיקון** — הכל מצטבר בקוד, ובסוף-סשן APK-אחד למודד. מסמך-זה = הרשימה-המלאה כדי שכלום לא-יאבד. (2026-08-26, מהשטח)

## ✅ בקוד (הושלם, build-ירוק, ממתין ל-APK-הסופי — batch-2)
- **תיקון-הערות-על-תמונה** — שדה-ההערות התחתון נצרב כפס-כיתוב על ה-PNG (התיקון-הקודם בנה פס-לבן ריק; עכשיו הטקסט מצויר).
- **תיקון-שינויים-עתידיים** — טקסט-שהוקלד-ולא-נלחץ-"הוסף" נצרב אוטומטית ב"שמור" (לא-אבד). ריבוי-הערות פר-חדר/פר-חזית כבר-נתמך.
- **מהלך-גבהים חכם** — קליטת-לייזר רציפה (כל ירייה אוטומטית ומדלגת-לבאה) + סינון-חריגה >2ס"מ מהחציון → אדום → המודד משאיר/מוחק. הגובה-המחייב=מינימום, הדוח מציג מינ'+מקס'.
- **X6/BLE** — אבחון-לייזר חי במסך-מכשירים (פריימים/פענוח/hex/Reading) + poll-זווית-אופקית (DST 360-X → פותח P2P) + `onCharacteristicRead`. (סוכן a2cc5c83)
- **לייזר re-arm רציף** — הזרקה-שנייה נקלטת; הקש 📡 לדריכה, ירה שוב-ושוב.
- **מהירות-BLE** — `CONNECTION_PRIORITY_HIGH`.
- **P2P** — StationSolver+ירי-כל-פינה + הכוונה למסלול-ידני בלי-מכשיר.
- **חוגת-כניסה** — כיוון-כניסה כחוגת-שעון + יחס-לחזית + נקודת-מבט. DB v19.

## 🔄 בבנייה (batch-2, עכשיו)
- **סרגל-לייזר צף ונשלף** — כפתור-קטן נגיש כמו כפתור-הבאג; נשלף בהחלקה, מציג מצב-חיבור + בחירת-לייזר (D2/X6/Bosch) + סרוק/נתק. (מכסה חלקית את "בורר-מכשיר-לייזר".)

## 🆕 בקשות-שדה חדשות (2026-08-26 — לבנות, batch-3)
- **#0★ הפעלת-DST 360 תוכנתית (מ-CVSM) — ההמלצה החמה ביותר:** להוסיף characteristic `3ab10120` ל-`LaserBle.kt` ולכתוב `raiseEvent 100\r\n` (16 בתים) אחרי `enableAllNotifyIndicate`. CVSM עושה בדיוק את זה כדי להפעיל P2P של ה-DST — כנראה הסיבה שהאזימוט שלנו אפס. סיכון-נמוך, ערך-עצום. (מ-`ops/docs/CVSM_ANALYSIS.md`.)
- **#0 שער-פילוס P2P ל-X6** — **מאוחד לתוך עבודת סוכן-ה-X6** (`docs/X6_LEVELLING_P2P.md`): על-חיבור-X6-ל-P2P, לחייב פילוס-במסך-המכשיר לפני פתיחת-ה-P2P. לא פריט-נפרד — נבנה כחלק ממנוע-ה-X6.
- **#כפתור-כלים מאוחד** — כפתור-צף **אחד** שנפתח (speed-dial) לאייקונים: 🐞 באג · 📡 לייזר · וכל אייקון-עתידי. מחליף את כפתורי-הצף הנפרדים (שכיסו תוכן-לחיץ בשטח). ✅ נבנה.
- **#verdict-בדיווח-באג (לחזרה)** — בעורך-הבאג להוסיף **בורר-הערכה: טוב / לשפר / לשדרג** — המודד מסמן כל דיווח. נצרב על התמונה + ב-JSON. בבדיקה-חוזרת המודד **מחויב לשלוח צילום-מסך חדש** עם ההערכה + טקסט/סמלים להמחשה. (מקשר את לולאת-הבדיקה-החוזרת בדו"ח-המודד לכלי-הסימון.)
- **#5 רוחב-קיר מינ/מקס** — כמו הגבהים, אבל בעריכת-קיר: קליטה-אוטומטית של כמה מדידות-רוחב, סטייה **>5 מ"מ** → אדום → המודד משאיר/מוחק. התוכנה קובעת את הקיר ב**מינימום**, והדוח מציג מינ'+מקס'. (דורש DB: `widthSweepMm` פר-קיר + migration; UI בעריכת-קיר; דוח.)
- **#6 ייצוא מינ/מקס** — בהגדרות-ייצוא: בורר "הפק לפי מינימום / מקסימום". לפי-בחירת-המודד הקובץ מופק עם מידות-גובה+רוחב אלו — **רק** גובה/רוחב מתעדכנים, בלי-לדרוס שום מידה-אחרת (אביזרים/היסטים). **החלטת-ארכיטקטורה פתוחה:** היכן מופק הקובץ — באפליקציה (.sol נושא את הבחירה) או בממיר-ה-PC.

6. **הגדרות-חדר** — להעביר כיוון-כניסה(חוגה)/מהלך-גבהים/שינויים-עתידיים/ברירות-מחדל מ**מסך-המדידה** ל**"⚙️ הגדרות-חדר"** נגיש-מהחדר. מסך-המדידה נשאר נקי (קנבס+סרגל). (בעלים אישר.)

8. **דוח-HTML באפליקציה** (נעצר — להשלים) — "צפה בדוח" + WebView + שיתוף, HTML-בלבד למודד (`export/HtmlReport.kt` כבר-קיים חלקית).
