# צ'קליסט אימות טרום-ייצוא — אפיון (Pre-Export Verify Checklist Spec)

> נכתב כמודד-מוסמך + מוביל-QA. **מטרה-על אחת: אפס-חזרה-שנייה-לאתר.** כל פריט כאן קיים כי חוסרו = נסיעה חוזרת.
> המסך: "אימות" — השער האחרון לפני שהמודד עוזב את השטח ומייצא חדר. מתחבר ל-CloseRoomScreen/CloseProjectScreen ולתחנה-4 ב-`FIELD_WORKFLOW_QA.md`.
> **מודע-לסוג-חדר:** מטבח · אמבטיה · ארונות · כללי. הצ'קליסט האוניברסלי תמיד רץ; מעליו נערמות שאלות פר-סוג.

## מקרא סטטוסים
- **חוסם (BLOCK)** — לא ניתן לייצא עד שהתנאי מתקיים או שהמודד דורס עם נימוק מתועד (override מתועד ב-.sol).
- **מזהיר (WARN)** — מותר לייצא, אבל מסומן צהוב בדו"ח + נרשם ל-.sol כ"נבדק ואושר חסר".
- **טולרנס-ברירת-מחדל:** סגירה ≤2ס"מ או ≤0.5% מההיקף (Bowditch); חריגת-ירי >2ס"מ; פער-רוחב-קיר >5מ"מ→מינ/מקס.

## חלק 3 · מודל "מנוע-השאלות" (Questions Engine)

### 3.1 עקרון
מסך-האימות בונה **רשימת-שאלות דינמית** = [שאלות-אוניברסליות] + [שאלות-הסוג לפי D1]. כל שאלה היא אובייקט:

```
Question {
  id, roomTypes[],          // באילו סוגי-חדר מופיעה (או "all")
  type,                     // BOOL | NUMERIC | NUMERIC_SET | PHOTO
  prompt,                   // הטקסט למודד
  blocking,                 // BLOCK | WARN
  linkedElement,            // איזה אלמנט/מדידה מאמת (opening/height/level/photo)
  answer, answeredBy, ts,   // תשובה + פרובננס
  overrideReason?           // אם BLOCK נדרס — נימוק-חובה
}
```

### 3.2 סוגי-שאלה והתנהגות
| סוג | קלט | ולידציה | דוגמה |
|---|---|---|---|
| BOOL | כן/לא | "לא" בפריט-חוסם → BLOCK עד תיקון או override | O2, D5, K1 |
| NUMERIC | ערך יחיד + יחידה | טווח-סבירות (0.05–80מ'); ריק בחוסם→BLOCK | B1 גובה-איטום |
| NUMERIC_SET | קבוצת-ערכים | סופר כמות (למשל ≥5 גבהים, ≥3 מפלסים) | H1, L1 |
| PHOTO | לכידת/בחירת-תמונה | ספירה מול-אלמנטים (חזית/קיר-רטוב) | M1, B4 |

### 3.3 לוגיקת-שער
1. בכניסה למסך: הרכב-שאלות → הרץ בדיקות-אוטו שכבר יש נתונים עבורן (G1–G4, H1–H2, O1) וסמן מראש ✔/✖.
2. הצג רק את מה-שנכשל/חסר + השאלות-הידניות (BOOL/PHOTO).
3. **כפתור "ייצא" נעול** כל-עוד יש פריט-BLOCK פתוח. מונה "N חסמים · M אזהרות".
4. דריסת-חוסם: דורש `overrideReason` (טקסט) → נרשם ל-.sol, מסומן אדום בדו"ח.
5. WARN לא-נועל אך נכנס לדו"ח כצהוב "נבדק, אושר חסר".

### 3.4 הזנה ל-.sol ולדו"ח
- כל תשובה נשמרת ב-.sol תחת `verify.answers[]` עם `id/answer/blocking/answeredBy/ts/overrideReason`.
- **ציון-ביטחון-חדר** = f(חסמים=0, אחוז-WARN-שנסגרו, פרובננס). מוצג בכותרת-הדו"ח.
- דו"ח-החוסרים (station-4) נגזר ישירות מכל פריט שאינו ✔ ירוק.
- override-ים מרוכזים בסעיף "חריגות מאושרות" בדו"ח — שקיפות למתכנן.

## חלק 4 · סדר-מימוש (P0/P1/P2)

### P0 — חובה למניעת-חזרה (בונים ראשון)
1. **מנוע-שאלות + שער-נעילת-ייצוא** (חלק 3) — התשתית שהכל תלוי בה.
2. **G1–G4** (סגירה/טולרנס/dead-zone/חצייה) — קיים חלקית במנוע; לחבר לשער.
3. **H1–H2** (≥5 גבהים + מינ/מקס) — שינוי-ספֶק Q6.
4. **O1–O2** (כל-פתח W/H/סף + אישור-ספירה).
5. **D1 + D5** (סוג-חדר + אישור-3D Q7) — D1 מפעיל את-כל השאר.
6. תוספי-חובה קריטיים: **K3/K5** (מטבח), **B2/B3** (אמבטיה), **W1/W2** (ארונות).

### P1 — מונע-חזרה בתדירות-נמוכה
1. **L1–L2** שיפועי-רצפה/תקרה (Q5) + הפיכתם לחוסמים במטבח/ארונות.
2. **M1** צילומי-חזית (Q9) + חוסם בקירות-רטובים (B4).
