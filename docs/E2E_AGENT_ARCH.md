# סוכן-בדיקות E2E אוטונומי — ארכיטקטורה (Soline · אנדרואיד)

> הבקשה נוסחה ל-web; **Soline = אנדרואיד נייטיב (Compose, offline-first, BLE)**. אין DOM/React/HTTP. הותאם בהתאם.

## 1. הסטאק
- **מנוע-הרצה:** **Maestro** — זרימות-YAML שמריצות על הטאבלט האמיתי (R5GL60ZDP5N) דרך adb. (בחירה: פשוט, יציב, מריץ על מכשיר-אמיתי כולל BLE. חלופות: Espresso/UI-Automator/Appium.)
- **התקנה:** Maestro CLI (`maestro test flows/`). אין צורך בשינוי-קוד לאפליקציה.

## 2. מנגנון-הסריקה
- **מיפוי-מסכים:** מהניווט ב-`AppUi.kt` (home · rooms · room · measure · draw · unified · p2p · semiauto · template · elevation · level · settings · devices · schedule · measurements · closeroom/project · bug). כל route = flow.
- **לכל מסך:** להיכנס → לצלם `hierarchy` → ללחוץ כל כפתור/פריט → להזין קלט (מספרים/טקסט) → לוודא שאין קריסה + שהמסך-הבא נטען.
- **זרימות-E2E מלאות:** פתיחת-פרויקט(נגר→לקוח) · יצירת-חדר · מדידה (צייר/לייזר/P2P) · מהלך-גבהים · חזית+אביזרים · שער-סגירה · ייצוא/דו"ח · הגדרות (יחידות/תיקיית-באגים) · חיבור-לייזר.

## 3. איתור-כשלים (מקביל להרצה)
- **logcat:** `adb logcat -b crash *:E` — `FATAL EXCEPTION`, `ANR`, `AndroidRuntime`, StackTrace.
- **ANR/קפיאה:** timeout על פעולה (>Xשׁנ') → כשל.
- **UI:** אלמנט צפוי חסר / כפתור לא-מגיב / מסך-לבן (hierarchy ריק).
- **ראיות:** `adb exec-out screencap` בעת-כשל + חיתוך-logcat + צעדים-לשחזור (מה-YAML).

## 4. פתיחת-באגים — לתוך המערכת הקיימת (מפתח!)
כל כשל → כותב **`bug_YYYYMMDD_HHMMSS.png` + `.json`** לתיקיית-הבאגים
(`G:\My Drive\קבצים ללמידת מכונה\באגים מסוליין`) **בדיוק בפורמט של כפתור-🐞** →
נקלט אוטומטית ל**דו"ח-המודד** כ"באג-חדש" (אותו צינור SAF שכבר בנינו). מבנה ה-JSON:
```json
{ "id":"bug_...", "createdAt":"...", "screen":"<מסך>", "severity":"Critical|High|Medium",
  "title":"[E2E Bug] <מסך> - <תקלה>", "steps":["1. ...","2. ..."],
  "expected":"...", "actual":"...", "logcat":"<stacktrace>", "e2e":true }
```
כותרת: `[E2E Bug] <מסך> - <תיאור>`. חומרה: Critical(קריסה/קיפאון) · High(פונקציה-מרכזית) · Medium(ויזואלי/משני).

## 5. דו"ח-סיכום-הרצה
טבלה: מסכים-נבדקו · Passed · Failed · קישור לכל-טיקט (בדו"ח-המודד). נכתב ל-`docs/E2E_RUN_<date>.md` + מוצף בצ'אט.

## 6. שלבי-הפעלה
1. התקנת Maestro CLI (חד-פעמי).
2. יצירת `flows/` — flow לכל-מסך + זרימות-E2E (מיוצר מהניווט).
3. הרצה: `maestro test flows/ --format junit` + logcat-מקביל + סקריפט-לכידה→JSON-באג.
4. סוכן שמפעיל, אוסף כשלים, כותב טיקטים לתיקייה, ומפיק דו"ח-סיכום.

## ⚠️ עלות
הרצה-אוטונומית מלאה = **כבדה בטוקנים** (עשרות מסכים × לחיצות × לכידות). מומלץ **סשן-ייעודי** עם תקציב-טוקנים מלא (לא בסוף-סשן). הארכיטקטורה כאן מוכנה-להפעלה.
