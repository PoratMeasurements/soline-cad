איך נעדכן את אפליקציית-המדידה מרחוק

רוצים שהמודד יעדכן את האפליקציה בלחיצת-כפתור — בלי מחשב, בלי כבל. המנגנון כבר בנוי; נותרה החלטה אחת: איך האפליקציה מושכת גרסה חדשה מהמאגר הפרטי של פורת.

מה כבר עשינו. קוד-האפליקציה עבר למאגר GitHub הפרטי של פורת (soline-cad), עם היגיינת-פרודקשן מלאה. בנינו באפליקציה מסך "בדוק עדכון גרסה" שיודע להוריד ולהתקין גרסה חדשה לבד.

מה חסום. כדי שהאפליקציה תמשוך את הגרסה ממאגר פרטי, היא צריכה להזדהות. זו נקודת-ההחלטה היחידה — ויש לה השלכת-אבטחה שדורשת את אישורכם.

אין דרך שאפליקציה תמשוך ממאגר-פרטי בלי אחד מהשניים. השאלה היא רק איזו דרך — וכל דרך היא איזון בין פשטות, אבטחה, ועלות.

03 ההמלצה שלנו

אפשרות א — טוקן קריאה-בלבד מוטמע

זהו כלי פנימי המותקן על מכשיר אחד-בודד של עובד-פורת. במצב כזה, טוקן fine-grained עם הרשאת קריאה-בלבד, מוגבל למאגר-אחד ולקטע ה-Releases בלבד — הוא איזון סביר לחלוטין. גם אם מישהו יפרק את ה-APK, כל מה שיוכל לעשות הוא לקרוא את קבצי-ההתקנה של אותו מאגר (לא את הקוד, ולא לכתוב דבר).

הטוקן אינו נשמר בקוד ואינו עולה ל-GitHub — הוא מוזרק לאפליקציה רק ברגע-הבנייה. פורת מפיקה את הטוקן (שליטה מלאה, ניתן לביטול בכל רגע); אנחנו רק מחברים אותו למנגנון.

04 מה צריך שתחליטו

1. איזו אפשרות — א / ב / ג?

ההמלצה: א (טוקן מוטמע). אם רמת-האבטחה של "טוקן ניתן-לחילוץ" לא-מקובלת עליכם — ב (Firebase).

2. אם א — מי מפיק את הטוקן?

‏PAT מסוג fine-grained, הרשאת Contents=Read בלבד, מוגבל למאגר soline-cad. מומלץ שפורת תפיק ותחזיק אותו (ולא הפיתוח).

3. מי מאשר שחרור-גרסה חדשה?

כל build → Release ב-GitHub (מדיניות שכבר סוכמה). האם כל שחרור דורש אישור-מנהל-מוצר, או שחרור-חופשי לפיתוח?

4. שם המכשירים המורשים לעדכון

כרגע מודד-אחד. אם צפויים מודדים נוספים — נשקול מראש הפצה רחבה יותר (משנה מעט את הבחירה).

05 מה קורה אחרי שתחליטו

ברגע שנקבל את ההנחיה (ובאפשרות א — את הטוקן מפורת), תוך שעה המנגנון חי: כל גרסה חדשה שנשחרר ל-GitHub תופיע למודד ככפתור "עדכן" באפליקציה — הורדה והתקנה בשטח, בלי מחשב ובלי כבל. עדכון-גרסה הופך מ"להביא את הטאבלט למשרד" ל"לחיצה אחת בשטח".
