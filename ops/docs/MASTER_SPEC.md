# Soline — אפיון-אב (Master Specification)

> **מסמך הכניסה למתכנתים.** מאחד את כל מסמכי האפיון של Soline למסמך אחד עם תוכן עניינים, מספור דרישות,
> מודל נתונים ושלבי פיתוח. הפירוט המלא של כל נושא חי במסמך-הבן שמצוין ליד כל סעיף.
> גרסה 1.0 · 2026-08-15 · בעברית · פנייה בלשון זכר.

## 0. על המסמך
- **מטרה:** לתת לצוות הפיתוח תמונה מלאה ומסודרת של המוצר — מה בונים, למי, ובאיזה סדר.
- **מעמד:** זהו מסמך-אב מאחד. הוא מסכם ומפנה; הפירוט המחייב חי במסמכי-הבן (§2).
- **איך לקרוא:** §1 לתמונה, §2 למפת המסמכים, §6 לדרישות הפונקציונליות הממוספרות, §7 למודל הנתונים, §14 לסדר הבנייה.
- **סטטוס:** אפיון ברמה גבוהה. **אין עדיין קוד מוצר** (נקודת התחלה בלבד ב-`www/` — מוקפאת). זהו שלב האפיון.

## 1. תמצית מנהלים — מה בונים
Soline היא **פלטפורמת שירות + עיצוב + מדידה + ייצור** לנגרים/יצרני מטבחים בישראל.
- **היום:** נגר מזמין מדידה → אנחנו מודדים בשטח (InnoDraw→ORDX + DISTO) → ממירים ל-DXF/PDP → מחזירים.
- **החזון (הנחת יסוד: שליטה בשוק, רמת חברה נסחרת ב-NASDAQ):** לולאה סגורה שבה הנגר **מעצב** תכנון ראשוני בתוכנת Soline → אנחנו **מודדים** → **מעמידים ומתאימים** את התכנון למציאות → מחזירים קובץ **`.sol`** שהנגר **ממשיך לעבוד עליו** אצלנו → ומשם **לייצור**.
- **הנכסים האסטרטגיים:** (1) הממיר ORDX→PDP (IP ייחודי), (2) פורמט **`.sol`** כסטנדרט התעשייה (חפיר בסגנון DWG/Autodesk), (3) לולאת דאטה שמשתפרת עם כל מדידה.
- **התובנה המרכזת:** המדידה נראית כמו העסק, אבל היא בעצם **ערוץ הרכישה הזול** לעסק ה-SaaS/marketplace עתיר-השוליים שמעליה — "land with measurement, expand across the stack".

## 3. היקף המוצר — ארבע תצוגות, אפליקציה אחת
אותו בסיס (web + Capacitor APK), התצוגה וההרשאות נגזרות מהתפקיד:
- **פורטל נגר** (web) — הזמנות, מעקב, הורדה, **+תוכנת עיצוב וכלי אקוסיסטם**.
- **אפליקציית מודד** (סמארטפון/טאבלט, offline) — העבודות שלי + **Soline Measure** (מדידה בתוכנה של סוליין, לא InnoDraw) + GPS למנוע.
- **קונסולת מתאם** (מחשב) — תור, כל העבודות, בירור, שיבוץ, תמחור, בדיקה, מסירה.
- **דאשבורד מנהל** (מחשב) — KPI, מנוע מדדים, קטלוג/מחירונים, משתמשים, הגדרות.

## 4. התהליך המלא (11 שלבים) — `WORKFLOW.md`
`submitted → accepted → assessment → scheduled → in_field → measured(DR1) → processing → review(DR2) → delivered → approved → closed`
5 לולאות תיקון (הזמנה חסרה / בירור לא מספק / בעיית עיבוד / חסר מידע שטח / בקשת שינויים). מיפוי מלא ל-`job.stage` וסטטוס-מפושט-לנגר ב-`WORKFLOW.md`.

## 5. תפקידים והרשאות — `ROLES_PERMISSIONS.md`
`carpenter` (חיצוני, רק שלו) · `surveyor` (רק שהוקצה לו) · `coordinator` (כל העבודות) · `manager` (הכול + אדמין).
**בידוד דייר** נאכף בשכבת הנתונים. מנוע המדדים והדאשבורד — **אדמין בלבד**.

## 6. דרישות פונקציונליות מרוכזות (Functional Requirements)

- **FR-CARP-04** כרטיס הזמנה: מעקב סטטוס, הצעת מחיר + **אישור**, הורדת קבצים, **בקשת שינויים**, יומן.

### 6.2 אפליקציית מודד — `SPEC.md §6.2`, `METRICS_ENGINE.md`

- **FR-FIELD-03** אינטגרציית DISTO (Bluetooth) — מידה ישירה לאלמנט נבחר.
- **FR-FIELD-04** **צ'קליסט שלמות חוסם-יציאה** (מניעת חזרות — פער שזוהה ב-`OWNER_ANALYSIS`).

### 6.8 גבייה — `OWNER_ANALYSIS.md §5` (החלטה 2026-08-15)
Soline **אינה מפיקה מסמכי-מס בעצמה**. היא מרכזת חיובים ומחוללת דו״חות, וההנפקה החשבונאית נעשית במערכת חיצונית מאושרת מס הכנסה.
- **FR-BILL-01** צבירת חיובים לכל עבודה (`pricing.total`) לאורך החודש.
- **FR-BILL-02** **דו״ח גבייה בסוף חודש** לכל נגר (עבודות, סכומים, סטטוס).
- **FR-BILL-03** **אינטגרציה ל-iCount** (מערכת הנה״ח מאושרת מס הכנסה) להפקת מסמכים חשבונאיים (חשבונית/קבלה) — דרך API.
- **FR-BILL-04** מעקב תשלומים + גיל חוב (aging) + תנאי אשראי + חסימת הזמנות לנגר בחוב.

## 7. מודל נתונים מאוחד — `SPEC.md §9`, `SOL_FORMAT.md`
ישויות תפעול: `users`, `carpenters`, `catalog`, `carpenterRates`, `jobs`, `measurements`, `deliverables`, `metrics`.
ישות-על: **`.sol`** — קונטיינר פרויקט (8 שכבות: design/measured/fit/catalog/bom/3d/annotations/meta+revisions). מודל-האובייקט של הממיר הוא סכמת-הליבה של `.sol`. פירוט מלא + סכמות מדגמיות ב-`SOL_FORMAT.md`.

## 8. פורמט `.sol` — `SOL_FORMAT.md`
קונטיינר עם `manifest.json` + שכבות + נכסים בינאריים. פורמט-הַאב: ORDX/DXF/PDP/glTF נכנסים; **תוצרי-ייצור בלבד יוצאים** (DXF/PDF/CNC). הבידול = שכבת `fit/` (ידע ההתאמה כדאטה). **פורמט סגור ומאובטח ללא-העתקה** (החלטה): הצפנה פר-שכבה + קשירת-רישיון (מפתח לא בקובץ, אימות מול שרת) → קובץ מועתק חסר-ערך מחוץ ל-Soline. חתימה + tamper-evidence לאחריות משפטית. פירוט: `SOL_FORMAT.md §2.3/§6`.

## 9. תוכנת העיצוב — `DESIGN_TOOL_SPEC.md`
משולש זוויות: אדריכל (מה לראות: 2D/חזיתות/3D/חומרים/שכבת-מדידה), CAD (כלים/snapping/פרמטרי/אילוצים), מתכנת (רינדור/kernel/CRDT/.sol). הייחוד: התכנון מונח על המציאות הנמדדת + auto-fit + R1–R10.

## 10. אסטרטגיה ומודל עסקי — `PLATFORM_VISION.md`, `STRATEGY.md`
- **כלכלת יחידה:** שיבוץ גאוגרפי מקפיץ שוליים מ~13% ל~44% ותפוקה +55% (`STRATEGY §2`).
- **מודל הכנסות:** SaaS recurring (ARR/NRR) + marketplace + per-measurement; שוליי SaaS 80-90% מול מדידה 13-44%.
- **חפיר:** IP הממיר + לולאת דיוק + switching cost של `.sol` + יתרון צפיפות גאוגרפי.
- **מה חסר לרמת NASDAQ:** ארכיטקטורת SaaS ענן רב-דיירת, SOC2/ISO27001, SLA, observability, CI/CD, בקרות פיננסיות, ממשל דאטה, הגנת IP, ארגון הנדסה/מכירות/CS.

## 11. ערכי המוצר (מומחשים בתוכנה) — `PLATFORM_VISION.md`
אמון ואמינות · בעלות הנגר על הדאטה · אינטרופרביליות (ייצוא פתוח) · שקיפות · דיוק/מלאכת-מחשבת · מהירות · פשטות · המשכיות. כל ערך ממופה לביטוי מוצר קונקרטי במסמך-הבן.

## 12. דרישות לא-פונקציונליות — `SPEC.md §11`
offline-first · אבטחה+פרטיות (הרשאות בשכבת נתונים, בידוד דייר) · ביצועים · רב-דיירות · עברית/RTL מלא · גיבוי ושחזור. ברמת חברה נסחרת: SLA/uptime, observability, DR, תאימות.

## 13. אינטגרציות — `SPEC.md §10`, `INTERFACE.md`
ממיר ORDX→PDP (חבילת `job-<code>/` → הופכת ל-`.sol` יחיד) · DISTO (Bluetooth) · מפות/ניווט · עתידי: וואטסאפ/SMS, הנהלת חשבונות, אחסון ענן, ספקי CNC/marketplace.

## 14. שלבי פיתוח (Roadmap)
- **H1 · 0–3 ח׳ — ליבה ואמת:** פלטפורמה (נגר+מתאם+שטח, 11 שלבים), צ'קליסט שטח, מנוע+דאשבורד בסיסי, גבייה בסיסית. **מתחילים מפורטל הנגר.**
- **H2 · 3–9 ח׳ — יעילות ושימור:** שיבוץ גאוגרפי, התראות וואטסאפ, SLA, גבייה+אשראי, חיבור חי לממיר + DISTO.
- **H3 · 9–18 ח׳ — עיצוב וחפיר:** תוכנת העיצוב + `.sol` מלא, כלי אקוסיסטם, תמחור מונחה-דאטה.
- **H4–H5 (חברה נסחרת):** marketplace ספקים, BI מתקדם, הרחבה, SaaS-ify. פירוט ב-`PLATFORM_VISION.md`.

**עדיפויות ROI מיידיות (חוצות בעלי עניין):** (1) מנוע מדדים+דאשבורד, (2) צ'קליסט שטח, (3) התראות אוטומטיות, (4) גבייה. פירוט ב-`OWNER_ANALYSIS.md` + `STAKEHOLDERS.md`.

## 15. החלטות
**הוכרעו (2026-08-15):**
1. ✅ **שליטה בקטלוג/מחירים** — אדמין בלבד בהתחלה, יורחב למנהל תפעול (COO).
2. ✅ **גבייה** — דו״חות גבייה סוף-חודש + אינטגרציה למערכת הנה״ח מאושרת מס הכנסה (Soline לא מפיקה מסמכי-מס בעצמה).
3. ✅ **תמחור** — מודל היברידי: מחיר בסיס קבוע + תוספות אוטומטיות (מרחק/קומה/מורכבות/דחיפות).
4. ✅ **`.sol`** — פורמט סגור ומאובטח ללא-העתקה (הצפנה + קשירת-רישיון). תוצרי-ייצור בלבד יוצאים.
5. ✅ **תוכנת העיצוב** — web-first רספונסיבי חוצה-מכשירים (PWA + Capacitor): טלפון (צפייה/סיור/שינויים קלים), טאבלט (עיצוב מגע), מחשב (עיצוב מלא).
6. ✅ **ערוץ התראות** — **וואטסאפ** (WhatsApp Business API).
7. ✅ **מערכת הנה״ח** — **iCount** (אינטגרציה דרך API להפקת מסמכים חשבונאיים).
