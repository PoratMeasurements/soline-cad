# שיתוף פעולה — Soline (מדריך למצטרפים)

מסמך זה נועד למי שמצטרף לעבודה על Soline (למשל **יותם, המנכ"ל**) **ולקלוד שלו**. קרא אותי קודם.

## מה זה Soline
Soline היא **חברת-בת של פורת מדידות בע"מ**.
- **פורת (האם)** מודדת **שיש** — קהל: מפעלי שיש.
- **Soline (הבת)** מודדת **ארונות — לפני השיש** — קהל: **נגרים**.
- שרשרת מטבח: מדידת חלל/ארונות (Soline·לנגר) ← בניית ארונות ← מדידת שיש (פורת·למפעל) ← ייצור השיש.
- השתיים **משלימות** — יחד מחזיקות את שני שלבי-המדידה של כל מטבח.

מעבר למדידה, Soline בונה **פלטפורמת עיצוב+מדידה+ייצור** לנגר, סביב פורמט קנייני **`.sol`**.

## איך הסינרגיה נשמרת (חשוב)
המוח המשותף הוא **הקבצים**, לא הצ'אט. כל צ'אט (של מיכאל או של יותם) הוא סשן שקורא וכותב לאותם קבצים.
- **הזיכרון של קלוד הוא אישי לכל משתמש** — הצ'אט שלך לא יראה את זיכרון הצ'אט של מיכאל. לכן **כל הידע חייב לחיות בקבצים** (וזה המצב).
- מקור-האמת: **`../STATUS.md`** — קרא אותו קודם; יש בו את המיצוב המתוקן ואינדקס כל המסמכים.

## מקור האמת (קרא לפי הסדר)
1. **`../STATUS.md`** — מצב הפרויקט + אינדקס כל התוצרים. תמיד המעודכן ביותר.
2. **`Soline_Yotam.html`** — המסמך המרכזי: חזון + מוצר (מאחד תמצית-מנהלים ואפיון).
3. **`MASTER_SPEC.md`** — אפיון-אב לצוות הפיתוח (דרישות ממוספרות, מודל נתונים).
4. **מסלול המדידה:** `MEASURE_TOOL_SPEC.md` · **העיצוב:** `DESIGN_TOOL_SPEC.md` · **הפורמט:** `SOL_FORMAT.md`.
5. **אסטרטגיה:** `STRATEGY.md` · `OWNER_ANALYSIS.md` · `STAKEHOLDERS.md`.
6. **סקר שטח:** `FIELD_SURVEY_KIT.md`.

## אנחנו על Claude Teams (בתשלום) — מה זה נותן במדויק
**מה שלא אפשר:** אין שיחת Claude Code חיה משותפת לשני אנשים בו-זמנית (לא CLI, לא web). אין הובלה/הקלדה משותפת באותה שיחה.

**מה שכן — והשילוב המומלץ:**
1. **תיקיית Drive משותפת** = הבסיס. שניכם מכוונים את Claude Code לאותה תיקייה → עובדים על אותם קבצים. זה הסנכרון האמיתי.
2. **cross-session-messaging** — העברת הודעות תיאום בין שתי השיחות הנפרדות ("סיימתי §9, תעבור עליו").
3. **שיתוף web-session ל-צפייה** (claude.ai/code, סימון "Team") — השני רואה קוד/diffs/היסטוריה כתמונת-מצב (לא בזמן אמת; אחד מוביל בכל רגע). טוב לסקירה.
4. **שיתוף artifacts** עם חברי-הצוות — דרך תפריט השיתוף של כל artifact.

> העבודה המשותפת היא **אסינכרונית**: אותם קבצים + תיאום בהודעות + שיתוף סשנים לצפייה. מוח אחד משותף — לא שני אנשים בשיחה חיה אחת.

## איך מצטרפים (טכני)
1. מיכאל משתף את התיקייה `G:\My Drive\claude` עם חשבון ה-Google Drive של המצטרף.
2. המצטרף פותח את **Claude Code** שלו (Teams) ומפנה אותו לאותה תיקייה משותפת (אותו נתיב ב-Drive שלו).
3. הקלוד של המצטרף קורא את `COLLABORATION.md` + `../STATUS.md` → מבין את הפרויקט מיד.

## איך תורמים ומעדכנים
- **כל עדכון מהותי** — כותבים אותו חזרה לקובץ ב-`docs/`, **ומעדכנים את `../STATUS.md`**. כך הצד השני רואה.
- **מסירת ידע/קבצים** → תיקיית **`../inbox/`**: קובץ גולמי עם שם ברור, או `inbox/notes-<שם>.md` לידע/הערות.
- **מסמך יותם** (`Soline_Yotam.html`): קובץ HTML ניתן-לעריכה — פותחים בדפדפן, עורכים על המסך, "שומרים כקובץ חדש", ומעלים לקלוד להמשך.

## כללי תיאום (למניעת התנגשויות)
- **`../STATUS.md` הוא מקור-האמת** — עדכנו אחרי כל שינוי מהותי.
- **אל תערכו את אותו קובץ בשני סשנים במקביל.** חלוקה: ידע → דרך `inbox/`; קבצים → מתואם דרך מיכאל.
- **עברית תקינה, לשון זכר.** תוצרים סופיים — בעברית מוקפדת.
- אל תמסגרו את Soline כ"מתחרה בשירותי מדידה" — היא הזרוע של פורת בשלב הארונות, לנגר.
