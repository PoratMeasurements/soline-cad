# תפקידים והרשאות

מקור־האמת של **מי רואה מה ומי יכול לעשות מה**. האפליקציה אוכפת את זה בכל מסך.

## ארבעה תפקידים
| קוד | תפקיד | סוג | תיאור |
|---|---|---|---|
| `carpenter` | נגר | חיצוני | הלקוח המזמין. חשבון לכל עסק־נגרות. רואה **רק את שלו**. |
| `surveyor` | מודד | פנימי | צוות שטח. רואה **רק עבודות שהוקצו לו**. |
| `coordinator` | מתאם | פנימי | תפעול Soline. רואה ומנהל **את כל העבודות**. |
| `manager` | מנהל | פנימי | Michael. **הכול** + ניהול משתמשים והגדרות. |

> ¹ **ניהול קטלוג/מחירים:** אדמין בלבד בהתחלה; בהמשך יורחב לתפקיד עתידי **מנהל תפעול (`ops_manager`/COO)**. (החלטה 2026-08-15.)

## עיקרון בידוד (רב־נגרים)
- כל נגר הוא **דייר נפרד (tenant)**. נגר א׳ לעולם לא רואה עבודות של נגר ב׳.
- כל עבודה נושאת `carpenterId`. שאילתות של תפקיד `carpenter` מסוננות תמיד ל-`carpenterId` שלו.
- מודד רואה רק עבודות עם `surveyorId === userId` שלו.

## מסך הבית לפי תפקיד
- **נגר** → "ההזמנות שלי": כרטיסי הזמנות עם סטטוס מפושט + כפתור "הזמנה חדשה". בהזמנה מוכנה — כפתור הורדה/אישור.
- **מודד** → "העבודות שלי היום": רשימת שיבוצים + כפתור קליטת מדידה. בלי קונסולת ניהול.
- **מתאם** → קונסולה מלאה: תור הזמנות חדשות, לוח כל העבודות, לו״ז, בדיקה, מסירה.
- **מנהל** → **דאשבורד ניהולי + KPI** כמסך בית (חדר בקרה), + כל קונסולת המתאם, + ניהול משתמשים/הרשאות/קטלוג/הגדרות. פירוט: `docs/ADMIN_DASHBOARD.md`.

## סטטוס מפושט לנגר (לא חושפים את הפנימי)
| job.stage פנימי | מה הנגר רואה |
|---|---|
| `submitted` | נשלחה — ממתינה לאישור |
| `accepted`, `assessment` | התקבלה — בבירור פרטים |
| `scheduled` | בתיאום מועד |
| `in_field`, `measured` | במדידה |
| `processing`, `review` | בעיבוד ובדיקה |
| `delivered` | ✅ מוכן — נא לאשר ולהוריד |
| `approved`, `closed` | הושלם |

## מודל נתונים — תוספות לתמיכה בהרשאות
```
users:      id, name, role, phone, carpenterId?(רק לנגר), active
carpenters: id, businessName, contactName, phone, email
jobs:       + carpenterId, + endClient{name,phone,address},
            + order{type, deliverables[], notes, deadline, attachments[], items[]},
            + stage(11 שלבים), surveyorId, ...
            + assessment{workNature, siteVerified, estMinutes, assessNotes}
            + pricing{subtotal, discount, total, currency, quotedAt, approvedByCarpenterAt}
catalog:        sku, name, category, unit, basePrice, active   (מנוהל ע״י אדמין)
carpenterRates: carpenterId, sku, price                        (מחירון מיוחד, אדמין)
metrics:        jobId, office{}, travel{}, measure{}, events[] (נסתר, אדמין בלבד)
```
> `clients` הישן מתפצל: **carpenter** = בעל החשבון (מזמין); **endClient** = לקוח־הקצה (בעל הבית) בשדה על העבודה.

## אימות (שלבים)
- **שלב 1 (עכשיו):** בורר תפקיד מקומי לפיתוח (מתחלפים בין תפקידים לבדיקה). בלי סיסמאות.
- **שלב 2:** התחברות אמיתית (טלפון+OTP או משתמש/סיסמה) כשיהיה backend.
- הרשאות נאכפות בשכבת הנתונים (`db.js`), לא רק בהסתרת כפתורים.
