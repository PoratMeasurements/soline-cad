# גשר אל הממיר — CONVERTER_BRIDGE

> איך **Soline Measure** מוסר עבודה אל פרויקט **ordx-pdp-converter**, מה הממיר יודע לייצא, ומה בדיוק אפליקציית המדידה חייבת לשים ב-`.sol`/ORDX כדי שהממיר יצליח לצרוך אותה.
>
> מקורות: `ordx-pdp-converter/docs/{STATUS,elements_catalog,DXF_2D_METHOD,ordx_item_dictionary}.md/json`, `ordx-pdp-converter/src/{placement,inject,assemble,export_*}.js`, וכן `soline-ops-app/docs/{INTERFACE,ORDX_BRIDGE,SOL_FORMAT}.md`. יחידות במ"מ אלא אם צוין. עודכן: 2026-08-17. פנייה בלשון זכר.

## 0. תמונת-על — צינור-היעד של Michael

```
Soline Measure  ──►  .sol  ──►  ordx-pdp-converter  ──►  ORDX + PDP + DXF-2D + DXF-3D
   (מקור-אמת)      (source        (מחולל-אובייקטים,
                    of truth)      4 מייצאים)
```

- **`.sol` הוא מקור-האמת היחיד.** אפליקציית המדידה מייצרת אותו; הממיר צורך אותו ומוציא ממנו את כל הפורמטים.
- הממיר **כבר בנוי כ"מחולל-אובייקטים"**: מודל-אובייקט קנוני אחד (`OBJECT_MODEL.md`) → 4 מייצאים נפרדים. `.sol` מאמץ **ישירות** את אותו מודל-אובייקט (ראה `SOL_FORMAT.md` §"אובייקט — תשתית/אלמנט"), כך שאין המרה-מחדש — יש מיפוי שכבה-לשכבה.
- **פער-האינטגרציה המרכזי (היום):** הממיר קורא **ORDX**, לא `.sol`. עד שנכתב קורא-`.sol` ייעודי, הגשר עובר דרך `measured/source.ordx` שמוטמע בתוך ה-`.sol` (ראה §4).

**סיכום בשלוּת:** ORDX ו-DXF-2D/3D **מוכנים לייצור**. PDP עובד למקרה הנפוץ (שקעים/אביזרים צמודי-קיר על בסיס קיים) אך אינו ממיר-מלא-כללי עדיין.

### 2.1 חוק-המיקום שהממיר מיישם (`placement.js`)
כל המיקום יושב ב-**MEP record** (173B) של ה-PDP; אין wall-index — האלמנט נקשר לקיר לפי קרבה גאומטרית. החוק:
- ORDX `Position/X` = מרחק **לאורך הקיר** מנקודת ההתחלה; `Y` = גובה-התקנה (Z אמיתי).
- עוגן לפי `Class`: **`Fixture`** → X = הקצה השמאלי (מרכז = `X + Width/2`); **`Decorative`** (חלון/דלת) → X = כבר המרכז.
- נקודת-תכנית = `wallStart + s·û` על קו-מרכז הקיר; טרנספורם `PDP_x = px + offX`, `PDP_y = −py + offY`.
- **קוד-אוריינטציה** = `round(10 × זווית_הקיר_מעלות)` במסגרת ה-Y-ההפוכה (דצי-מעלות 0–3599).

## 3. חוזה-המסירה — מה אפליקציית המדידה חייבת לספק

כדי שהממיר יצליח לצרוך עבודה, ה-`.sol` (או ה-ORDX שבתוכו) **חייב** להכיל את המינימום הבא. כל שדה כאן הוא תנאי לפעולת `placement.js`/המייצאים.

### 3.1 גיאומטריית-חדר (חובה לכל פורמט)
לכל **קיר**: `StartX, StartY, EndX, EndY` (קואורדינטות תכנית מוחלטות במ"מ), `Height`, `Thick`. `Angle` נגזר מהגאומטריה. בלי לולאת-קירות סגורה אין מסגרת-פרויקט, אין `offX/offY`, ואי-אפשר לחשב מיקום אף אלמנט.

### 3.2 כל אלמנט מוצב (חובה)
| שדה .sol / ORDX | חובה? | תפקיד אצל הממיר |
|---|:--:|---|
| `en` / `Name` | ✔ | מפתח למיפוי קטלוג → קוד-סוג PDP (§1) ולבחירת סמל. |
| `Class` (Fixture \| Decorative) | ✔ | קובע את **עוגן ה-X** (קצה-שמאל מול מרכז) — טעות כאן מזיזה את האלמנט בחצי-רוחב. |
| `Type` (Miscellaneous/Part/Window/Door…) | ✔ | טקסונומיית ORDX. |
| `placement.x` (`Position/X`) | ✔ | מרחק לאורך הקיר מנקודת ההתחלה. |
| `placement.y` (`Position/Y`) | ✔ | גובה-התקנה על הקיר (Z אמיתי). |
| `placement.z` (`Position/Z`) | לפריטים צפים | היסט מחוץ-למישור (תקרה/תאורה צפה). ⚠️ הפרסר הנוכחי `parseOrdx.js` **זורק את Z** — צריך תיקון. |
| `placement.wall_id` | ✔ | לאימות; אם חסר, נקשר בקרבה גאומטרית. |
| `dimensions_mm.W/D/H` | ✔ | נכתב ל-MEP `+0xa1/+0xa7` — שולט בגודל האמיתי ב-Raumplan; וגם לתיבת ה-DXF-3D. |

### 3.3 שכבות .sol שהממיר יצרוך בעתיד (לא-ORDX)
`.sol` מחזיק מה ש-ORDX **לא יכול** להחזיק, ואלה יזרימו את הצינור-המלא (נגרות, לא רק תשתית):
- **`status`** לכל אלמנט: `existing/new/cancelled/prep/future/hidden` — לב עבודת-ההתאמה; **אין לו ביטוי ב-ORDX-הליבה** (עובר ב-`<Ext>` או `Description`).
- **`measure_ref`** (`center`/offset) ו-**`protrusion_mm`** (עומק-בליטה — "אויב מס' 1 של הנגרות").
- **`design/cabinets.json`** — ארונות. ל-ORDX **אין ישות ארון כלל**; ערוץ נפרד ב-`.sol`.
- **`fit/deltas.json` + `fit/derived.json`** — דלתאות-התאמה ומילואות נגזרות.
- קירות מעוקלים (`isArcWall`), סגנון-ראש/קצה-קיר, גרף-חיבורי-קירות — כולם אובדים ב-ORDX; נשמרים ב-`.sol`.

## 4. פער-האינטגרציה החשוב ביותר: `.sol` מול ORDX

הממיר **קורא ORDX, לא `.sol`**. עד שנכתב קורא-`.sol` ייעודי, המסלול המעשי:

1. **טווח-קצר:** ה-`.sol` מטמיע `measured/source.ordx`. הממיר מריץ את הפרסר הקיים על ה-ORDX הזה → כל 4 הפורמטים. **מגבלה:** נכנס רק מה ש-ORDX-הליבה מחזיק — קירות + אביזרים צמודי-קיר. ארונות/סטטוס/דלתאות-התאמה **נופלים בשקט**.
2. **טווח-בינוני:** להוסיף בלוק `<Ext xmlns:sol="soline">` לכל `Wall`/`Furnishing` ב-ORDX, שנושא את שדות-ה-`.sol` ש-InnoDraw לא מכיר (status, protrusion, arc, connectivity, cabinets-ref). הממיר יתעלם ממה שלא צריך — אבל שום דבר לא ייעלם בשקט.
3. **טווח-ארוך (יעד Michael):** **קורא-`.sol` מקורי בממיר** שקורא את השכבות ישירות (`design/`, `measured/`, `fit/`, `catalog/`) ומזין את מודל-האובייקט — ואז ORDX הופך לעוד **פלט**, לא לפורמט-הביניים. זה מה שהופך את `.sol` באמת ל"מקור-האמת".
