## §1 — מפת-פונקציות מלאה של CVSM (לפי סעיפי-המדריך)

### א. פרויקטים (`#cat-a`)
המסך-הבית מציג את כל הפרויקטים הפעילים; כל פרויקט = חדרים + מסמכים + פרטי-לקוח/משלוח.

| # | פונקציה | תיאור (עוגן-מדריך) |
|---|---------|--------------------|
| A1 | יצירת פרויקט חדש | FAB `+` → שם(חובה)+תיאור; חץ "פרטים נוספים" פותח בבת-אחת את כל פרטי-הלקוח והמשלוח (שם/כתובת/עיר/טלפון/מייל/איש-קשר/הערות/כתובת-משלוח-נפרדת); "הוסף" עובר ישר למצב-תוכנית (`#f-proj-create`) |
| A2 | עריכת פרטי פרויקט | אותו טופס כמו-ביצירה; צ'קבוקס "זהה ללקוח" למשלוח (`#f-proj-edit`) |
| A3 | מסמכי פרויקט | 📎 "הוסף מסמך" → 3 מקורות: 📷 צילום-ישיר / 🖼️ גלריה (בחירה-מרובה) / 📄 קבצים (PDF/Word/Excel/תמונה/טקסט); כל קובץ נפתח/משותף/נמחק (`#f-proj-docs`) |
| A4 | ארכיון פרויקטים | 📦 מעביר-לארכיון (נעלם מהרשימה, **לא נמחק**); במסך-הארכיון שחזור או מחיקה-לצמיתות; אי-אפשר להיכנס לפרויקט-מארכב בלי לשחזר קודם (`#f-proj-archive`) |
| A5 | תצוגת רשימה / רשת | מעבר בין רשימה-מפורטת לריבועים-צבעוניים; ההגדרה נשמרת בנפרד ממסך-החדרים (`#f-proj-view`) |

### ב. חדרים (`#cat-b`)
חדר-חדש נפתח במצב **הוסף** (מוכן-לשרטוט); חדר-עם-קירות נפתח במצב **חזית** (תצוגה-בלבד).

| # | פונקציה | תיאור |
|---|---------|-------|
| B1 | יצירת חדר חדש | שם(חובה)+תיאור; **גובה-חדר**(חובה) עם 📏×3 תמיד-זמין + P2P אם-Leica (רצפה→תקרה) או "מדוד" עם-Bosch; **סגירה-עליונה** ברירת-מחדל 0מ"מ (`#f-room-create`) |
| B2 | עריכת חדר | אותם-שדות; שינוי מתעדכן אוטומטית בכל הקירות **שלא-נערכו-ידנית** (`#f-room-edit`) |
| B3 | תצוגת רשת חדרים | כל ריבוע-חדר מציג **מיני-שרטוט אוטומטי** של צורת-הקירות בפועל (לא אייקון); חדר-ריק מציג אייקון-בית (`#f-room-grid`) |
| B4 | מחיקת חדר | מוחק כל הקירות/אביזרים; אישור מציג כמה יימחקו (`#f-room-delete`) |

### ג. שרטוט קירות — מצב תוכנית (`#cat-c`)
לרוחב: סרגל-הכלים עובר לסרגל-צד קבוע בימין (~75% מסך פנוי לשרטוט).

| # | פונקציה | תיאור |
|---|---------|-------|
| C1 | לשוניות בסרגל-הצד (לרוחב) | 3 לשוניות: 🧱 קירות / 📐 CAD / 👁️ תצוגה; מעל-הן קבועים: כותרת + מצב-עבודה + תלת-ממד + בטל; הלשונית קופצת אוטומטית לפי הכלי-הפעיל; סיבוב-הטאבלט שומר-הקשר (`#f-plan-railtabs`) |
| C2 | מצבי-עבודה: הוסף/ערוך/מצב-חזית | הוסף=שרטוט-חדש · ערוך=בחירה+עריכה · מצב-חזית=לחיצה-על-קיר פותחת חזיתו; חדר-קיים נפתח תמיד ב"מצב-חזית" (`#f-plan-modes`) |
| C3 | קו ושרשרת | קו=קיר-בודד בין-2-נקודות; שרשרת=קירות-רצופים, כל-קיר מתחבר לקודם (`#f-plan-line`) |
| C4 | ריבוע מהיר | חדר-מלבני שלם ב-2-לחיצות (פינה-נגדית), 4-קירות-מחוברים, 90° (`#f-plan-box`) |
| C5 | אשף תבניות-חדר | 📋 בורר-צורה: מלבן/L/U/T/Z (+סיבוב-90°/שיקוף); שרטוט-מודרך — בוחר-קיר, יורה-לייזר, סמן-קופץ-לבא; קירות-מקווקווים = **נגזרים** (מחושבים לבד); "צור-קירות" בונה-הכל ב-90° מדויק (`#f-plan-wizard`) |
| C6 | נעילת 90° | ⊾ מתג שנועל כל-קיר-חדש לזווית-ישרה מול צירי-המסך ומול הקיר-הקודם; סגירת-חדר-על-פינה גוברת; נשמר בין-הפעלות (`#f-plan-ortho`) |
| C7 | יצירת קירות בלייזר תלת-ממד | 🎯 (Leica-X6 בלבד): דורש מיקום-מדידה 📍; ישר(2נק')/קשת(3נק'); כל-ירייה=נקודה, כל-2/3-נקודות=קיר-אוטומטי (`#f-plan-3dcapture`) |

### ד. עריכת קירות (`#cat-d`)

| # | פונקציה | תיאור |
|---|---------|-------|
| D1 | יישור אופקי/אנכי | ─/│ מופיע רק כשקרוב-לאופקי/אנכי; מיישר-בול בלי מדידה-חוזרת (`#f-wall-align`) |
| D2 | שינוי אורך קיר | בורר-כיוון: איזה-קצה זז (התחלה/סוף/שניהם-מרכז-קבוע); כפתורי לייזר/P2P/×3 (`#f-wall-length`) |
| D3 | שינוי גובה קיר | עוקף ברירת-מחדל-חדר; אחרי-עריכה-ידנית הקיר לא-מושפע-יותר משינוי-חדר (`#f-wall-height`) |
| D4 | חיבור T + שיטת-חיבור-T | לוחץ T על הקיר-שאסור-לזוז ואז על-השני; **הראשון לעולם-לא-זז**, השני נחתך/מתארך; מעבר-לקצה=חיבור-פינה לפי הגדרת-שיטה; קיר-קשת מסרב (`#f-wall-tjoin`) |

| D6 | העתק + הזז קיר | 📋 עותק מוזז במרחק-מוזן לכיוון-פנים/חוץ (`#f-wall-copy`) |
| D7 | מרחק בין קירות | 📏 בוחר קיר-שני, מודד מינ'/מקס'/X/Y/ישר; "◀ הזז-A"/"הזז-B ▶" קובעים מי-זז להתאמת-המידה (`#f-wall-dist`) |
| D8 | מחיקת קיר | (`#f-wall-delete`) |
| D9 | פאנל מאפייני-קיר | **לחיצה-ארוכה** → פאנל-צד: מיקום-התחלה/סוף, אורך, זווית, גובה, סגירה-עליונה, עובי, סוג-קיר, סגנון-ראש, מצב-חיבורים-בקצוות, ניווט; לחיצה-קצרה רק-בוחרת (`#f-wall-panel`) |
| D10 | עובי-קיר + סגירה-עליונה | עריכה-חופשית; **העובי מתרחב תמיד כלפי-חוץ** — הקו-שנמדד נשאר-במקום (`#f-wall-thickness`) |
| D11 | סגנון-ראש-קיר | ישר / משופע-שמאל / משופע-ימין / גמלון(Cathedral) / שקוף(Peninsula — קו-במבט-על, לא-קיר-אמיתי); למשופעים שדות גובה-רכס+מיקום-פסגה (`#f-wall-topstyle`) |
| D12 | ניווט בין-קירות | ◀ ▶ מעבר לקיר-הבא/קודם ברשימה בלי-לתפוס-באצבע (`#f-wall-nav`) |
| D13 | כלי-פינה: חיבור/פילטה/זווית | לחיצה-על-פינה → תפריט-צף: העבר-נקודה / חבר-קירות / נתק / **צור-פינה-מעוגלת**(רדיוס) / 📐 זווית: לשונית "זווית-ישירה" + לשונית **"משולש-זהב"** (A/B/C, כל-אחד לייזר/×3, קיצורי 3-4-5/6-8-10/5-12-13, ▶A/▶B מיישם ומסובב) (`#f-wall-corner`) |

## §3 — הדוח האינטראקטיבי של CVSM (`cvsm_html_export/`)

**ארכיטקטורה:** קובץ `.html` **יחיד עצמאי** — `index.html` הוא תבנית עם 4-מציני-מיקום מוחלפים בזמן-ייצוא (`export/HtmlExporter.kt`): `__STYLES__`, `__DATA__` (JSON-החדרים), `__APP__` (app.js). **בלי ES-modules, בלי fetch** — נפתח בלחיצה-כפולה מ-`file://` בכרום ובדפדפן-טאבלט (הערה מפורשת ב-index.html). זו אותה-ארכיטקטורה של אפליקציית-המטבח-הדסקטופ של-הבעלים.

**מבנה-הדוח (מ-app.js):**
- **מצבים (SPA):** `welcome` → `room` → `elevation`, ניווט ב-`goWelcome/goRoom/goElevation`, `topbar`+פירורי-לחם.
- **עמוד-פתיחה (`renderWelcome`):** hero-gradient (טורקיז) + **stat-tiles** (חדרים/קירות/ארונות/אביזרים) + `field-grid` פרטי-לקוח/משלוח (`customerInfo`/`shipTo`) + **room-grid** — כרטיס-לכל-חדר עם **מיני-שרטוט SVG** (`.room-card-thumb`) ומטא (ארונות/אביזרים).
- **תצוגת-חדר (`renderRoomView`):** `room-body` בגריד 2-פאנלים — **תוכנית-SVG** (`buildPlanSvg`: זום/גרירה `makePannable`, קירות-פוליגון, ארונות-footprint, אביזרים, פתחים+נפתחי-דלת `door-swing`, זוויות-פינה, קווי-מידה-מדורגים, הערות+סמלים) לצד **קנבס-תלת-ממד** (`attach3dViewer` — extrude-קירות/ארונות, סיבוב-בגרירה, `project`). מתחת — **detail-section** (לחיצה-על-אלמנט פותחת שורות-מאפיינים) + **schedules**.
- **תצוגת-חזית (`renderElevationView` / `buildElevationSvg`):** שרשראות-מידה (`chainSegments`/`layoutChainRows`), קיבוץ-לפי-גובה (`clusterByHeightLayer`), קווי-גובה מקווקווים (`height-band`), פינת-תוכנית-קטנה (`plan-corner`) עם הקיר-הנוכחי מודגש.
- **טבלאות (`buildSchedules`):** **טבלת-ארונות** — עמודות `# | שם | סוג(class) | מידות ר×ג×ע | קיר | מרחק-משמאל | מרחק-מלמטה`; **טבלת-אביזרים** — `# | שם | קטגוריה | מידות | קיר | משמאל | מלמטה`. גלילה-אופקית.
- **בקרת-שכבות (`buildLayersControl`):** תפריט-נפתח עם מתגי-נראות (ארונות/פתחים/שמות-אביזרים-מובחנים `distinctAccessoryNames`) + מתגי-מידות (`toggleDims`/`toggleCadDims`) — מירר את הנראות-באפליקציה.
- **פרטים-טכניים:** `applyConstantTextSize`/`scheduleTextScaleFix` — טקסט-קריא-בכל-זום; יחידות-SVG = מ"מ (viewBox); i18n מלא דרך `t(key)` (RTL, כל-הכותרות מתורגמות); פלטת-שרטוט מ-`styles.css` (`--cab-fill`, `--cad-dim-color` כחול, `--note-fill` צהוב).

**מה Soline צריך לאמץ / לעבור:**
1. **להטמיע את `viz_engine.js` הקיים** (WebGL, צוקל, טקסטורות, שכבת-תכנון, התנגשויות, הצללה, הסתרת-קירות — HANDOFF §5) כפאנל-התלת-ממד בדוח → **Soline כבר עדיף** אם מטמיעים, כי ל-CVSM יש רק canvas-extrude פשוט.
2. **טבלאות-לוח (schedules)** — ארונות+אביזרים עם אותן-עמודות + **גם חומר** (עמודה ש-CVSM אין) ו**סטטוס-מדידה** (`MeasureStatus`).
3. **מבנה-3-מצבים** welcome/room/elevation עם מיני-שרטוטים ב-room-grid — לאמץ 1:1.
4. **בקרת-שכבות + מתגי-מידה** בדוח — לאמץ.
5. **קובץ-יחיד file://** (בלי-fetch, מציני-מיקום) — לאמץ כדפוס-הייצוא; להוסיף **מיתוג-Soline** (טורקיז→כתום/טורקיז-מותג, לוגו).
6. **הצללת-אביזרים לפי-קטגוריה** (`categoryColor`) + נפתחי-דלת + זוויות-פינה בתוכנית.

### ה-UUID-ים — זהים לשלנו, פלוס אחד
שירות Leica: **`3ab10100-f831-4395-b29d-570977d5bf94`** (זהה). מאפיינים (props מהלוג-החי):

| Char | תפקיד ב-CVSM | Props | אצלנו |
|------|--------------|-------|-------|
| `3ab1010d` | Distance + V.Angle | 34 = READ+INDICATE | ✅ `LEICA_MEAS` |
| `3ab1010f` | H.Angle (מ-DST 360) | 34 = READ+INDICATE | ✅ `LEICA_HANGLE` (poll) |
| **`3ab10120`** | **Command Write (הפעלת DST 360)** | **8 = WRITE** | ❌ **חסר לגמרי אצלנו** |

(`3ab10101` = D2 distance — אנחנו תומכים, CVSM 5.9 לא-משתמש.)

### הממצא המרכזי — CVSM **כן** כותב פקודת-הפעלה שאנחנו לא
זרימת-החיבור של `LeicaDistoManager` (מלוגים + שמות-מתודות):
1. סורק → מוצא שירות `3ab10100` → **`Found Leica DISTO service!`**.
2. ממפה 3 מאפיינים: `Found Distance + V.Angle characteristic` (010d), `Found H.Angle characteristic` (010f), **`Found Command Write characteristic (for DST 360)` (0120)**.
3. מפעיל indicate/notify על כל-המאפיינים-הניתנים (כותב CCCD `2902` עם `ENABLE_NOTIFY`=`01 00` / `ENABLE_INDICATE`=`02 00`).
4. `Starting H.Angle polling (fallback for indications)` — פּוֹל של 010f (בדיוק-כמונו).
5. **`Reading H.Angle characteristic to wake up DST 360...`** — קריאת-עֵר של 010f.
6. **`activateDST360Mode` / `tryActivateDST360`** → כותב ל-`3ab10120` את המחרוזת-ASCII:

   ```
   "raiseEvent 100\r\n"          ← 16 בייט, נמצא ב-classes5.dex וגם בלוג-החי
   ```
   לוג-חי אמיתי:
   `🎯 ACTIVATING DST 360 P2P MODE! Sending: "raiseEvent 100\r\n"` →
   `onWriteCharacteristic() … status=GATT_SUCCESS, length=16` →
   `✅ DST 360 P2P activation command sent! H.Angle should now work!`

   אם 0120 חסר: `No command write characteristic (3ab10120) found - DST 360 activation not possible`.
7. אם ה-H.Angle **לא-משתנה** (זהה שוב-ושוב) → `recordHAngleForMonitoring`/`checkHAngleSame`/`hAngleModeError` מרימים דגל, וה-UI מציג `LaserModeErrorDialog` (מחרוזות `laser_not_3d_mode_title`/`laser_not_3d_mode_message`/`laser_3d_mode_restored`). יש גם `reconnectWith3DMode` — מתחבר-מחדש ושולח שוב את הפקודה.

### מה CVSM עושה ואנחנו לא (התמצית)
1. **כותב `raiseEvent 100\r\n` ל-`3ab10120`** מיד-אחרי-החיבור — זו פקודת ההפעלה של מצב-ה-P2P/הזוויות של ה-DST 360-X. **זה בדיוק החוֹר שלנו:** אנחנו קוראים 010f ומקבלים אפסים כי מעולם-לא-אמרנו למכשיר להתחיל לשדר זוויות. אנחנו לא מגדירים ולא כותבים ל-0120 בכלל (`LaserBle.kt` companion: יש 010d/0101/010f — אין 0120, אין raiseEvent).
2. **קריאת-עֵר** מפורשת של 010f לפני-הפעלה (`wake up DST 360`).
3. **גילוי-מצב-שגוי אוטומטי**: אם הזווית לא-משתנה → דיאלוג "המכשיר לא-במצב-3D" + ניסיון-חיבור-מחדש. (אנחנו כרגע פשוט מציגים אפסים.)

הערה-הוגנת: בלוג-החי-שברשותנו ה-H.Angle נשאר `0.00°` גם אחרי-הפקודה — כנראה ה-DST היה מפולס/לא-מסובב באותו-רגע, או שהיה צריך ירי-P2P בפועל. אבל **המנגנון חד-משמעי**: הכתיבה ל-0120 היא הדבר שמפעיל את ערוץ-הזוויות. ה-`raiseEvent 100` הוא הפקודה המדויקת, מאושרת גם ב-DEX וגם ב-write של 16-בייט מוצלח.

### המלצה — מה לאמץ ל-`LaserBle.kt`
**פעולה יחידה, זולה, בעלת-ערך-גבוה:** להוסיף מאפיין רביעי ולכתוב אליו את פקודת-ההפעלה מיד-אחרי גילוי-השירות:

```kotlin
// ב-companion של LaserBle.kt:
val LEICA_CMD = leica("0120")                       // Command Write (DST 360 activation)
val DST360_ACTIVATE = "raiseEvent 100\r\n".toByteArray(Charsets.US_ASCII)  // 16B, WRITE (props=0x08)

// אחרי onServicesDiscovered, אחרי enable-notify/indicate ולפני/במקביל ל-poll של 010f:
findChar(g, LEICA_CMD)?.let { c ->
    g.readCharacteristic(findChar(g, LEICA_HANGLE))   // "wake up" קודם (כמו CVSM)
    c.value = DST360_ACTIVATE                          // או writeType=WRITE_TYPE_DEFAULT (with-response)
    g.writeCharacteristic(c)
}
```

ב-`P2PMeasureScreen.kt`: אחרי-אימוץ, אפשר להסיר את-הדרישה שהמודד יכניס-ידנית את-ה-DST למצב-P2P/מפלס דרך-המכשיר — האפליקציה תפעיל-לבד. כבונוס לאמץ גם את **גילוי-המצב-השגוי** (אם 010f מחזיר אותו-ערך N-פעמים → להציג "הכנס מצב-3D / מפלס" ולנסות-שוב), מקביל ל-`LaserModeErrorDialog` של CVSM.

**לא-להעתיק:** אין קוד-P2P-קואורדינטות מיוחד ב-CVSM שאנחנו חסרים — ה-P2P שם נשען על אותם 010d(מרחק+אנכי)+010f(אופקי) שאנחנו כבר-קוראים; ההבדל היחיד המהותי הוא פקודת-ההפעלה `raiseEvent 100` ל-0120.

### תקציר (3-5 שורות)
CVSM מתחבר לשירות `3ab10100`, מפעיל indicate/notify על 010d(מרחק+זווית-אנכית) ו-010f(זווית-אופקית), פּוֹל את-010f, **קורא-עֵר את-010f, ואז כותב את-המחרוזת `"raiseEvent 100\r\n"` ל-מאפיין-הפקודה `3ab10120` כדי להפעיל את מצב-ה-P2P של ה-DST 360-X** — ורק-אז הזוויות-האופקיות מתחילות לזרום. אם הזווית לא-משתנה הוא מזהה-זאת ומרים דיאלוג "לא-במצב-3D" + מתחבר-מחדש. **הדבר-האחד-הכי-שימושי לאמץ:** לכתוב `raiseEvent 100\r\n` ל-`3ab10120` אחרי-החיבור — זה כמעט-בוודאות מה שיגרום ל-azimuth שלנו להפסיק להחזיר אפסים בלי שהמודד יצטרך לגעת במכשיר.
