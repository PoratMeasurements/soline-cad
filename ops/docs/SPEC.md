# Soline Ops — אפיון מלא (Functional Spec)

מסמך אפיון פונקציונלי מלא של פלטפורמת התפעול. גרסה 1.0 · 2026-08-15 · בעברית.
נלווה ל: `WORKFLOW.md` (תהליך), `ROLES_PERMISSIONS.md`, `PRICING_CATALOG.md`, `METRICS_ENGINE.md`, `ADMIN_DASHBOARD.md`, ו-`OWNER_ANALYSIS.md` (ניתוח עסקי).

## 1. מבוא ומטרות
**מה זה:** פלטפורמת שירות שמנהלת את כל תהליך המדידה של Soline — מרגע שנגר מזמין עבודה ועד שהוא מקבל בחזרה את קבצי התכנון (DXF/PDP).
**הבעיה שהיא פותרת:** היום הזרימה ידנית, מבוזרת (טלפונים/וואטסאפ/אקסל), אין שקיפות לנגר, אין מדידת רווחיות, וקל לאבד עבודות או לחזור לשטח פעמיים.
**המטרות:**
1. שקיפות מלאה לנגר (הזמנה + מעקב + קבצים במקום אחד).
2. תפעול חלק וללא נפילות בין השלבים.
3. **offline-first** — המודד עובד בשטח גם בלי רשת.
4. מדידת עלות ורווחיות אמיתית לכל עבודה (למנהל בלבד).
5. תשתית לצמיחה — עוד נגרים, עוד מודדים, בלי לשבור את התהליך.

## 2. המודל העסקי (מי משלם למי)
- **הנגר** = הלקוח המשלם. מזמין מדידה, משלם לפי קטלוג מק״טים.
- **Soline** = נותנת השירות: מודדת בשטח, ממירה ל-DXF/PDP, בודקת, ומחזירה.
- **לקוח־הקצה** (בעל הבית) = לא משתמש במערכת; רלוונטי רק לתיאום כניסה לאתר.
- הכנסה = Σ מחיר הזמנות. עלות = זמן (משרד+מודד) + נסיעה + עיבוד. רווח = הכנסה − עלות.

## 3. משתמשים ותפקידים (Personas)
| תפקיד | Persona | צורך עיקרי | מכשיר |
|---|---|---|---|
| **נגר** | בעל נגריית מטבחים, עסוק, לא טכני | להזמין מהר, לדעת מתי מוכן, לקבל קבצים תקינים | טלפון/מחשב (web) |
| **מודד** | טכנאי שטח, בשטח רוב היום | לראות מה למדוד היום, לקלוט מהיר, לעבוד בלי רשת | סמארטפון (APK) |
| **מתאם** | תפעול במשרד | לא לאבד עבודות, לשבץ נכון, לתמחר, למסור בזמן | מחשב |
| **מנהל** | Michael, בעלים | לראות הכול — רווחיות, צווארי בקבוק, יעילות | מחשב |

מודל ההרשאות המלא: `ROLES_PERMISSIONS.md`. עיקרון־על: **בידוד דייר** — כל נגר רואה רק את שלו; כל מודד רק את שהוקצה לו.

## 4. סקירת המערכת — ארבע תצוגות, אפליקציה אחת
אותו קוד (web + Capacitor APK), התצוגה נגזרת מהתפקיד:
- **פורטל נגר** — הזמנות שלי, טופס הזמנה, מעקב, הורדה.
- **אפליקציית מודד** — העבודות שלי, קליטת מדידה (offline+GPS).
- **קונסולת מתאם** — תור, כל העבודות, בירור, שיבוץ, תמחור, בדיקה, מסירה.
- **דאשבורד מנהל** — KPI, קטלוג/מחירונים, מנוע מדדים, משתמשים, הגדרות.

## 5. מסע העבודה מקצה לקצה
11 שלבים (`submitted → accepted → assessment → scheduled → in_field → measured → processing → review → delivered → approved → closed`) עם 5 לולאות תיקון. פירוט מלא ותרשים: `WORKFLOW.md`.

## 6. אפיון מסכים

### 6.1 פורטל הנגר
**מסך התחברות** — טלפון + OTP (שלב 1: בורר משתמש dev). לאחר התחברות → "ההזמנות שלי".

**ההזמנות שלי (בית)**
- רשימת כרטיסי הזמנות של הנגר בלבד, ממוינות לפי עדכון אחרון.
- כל כרטיס: קוד עבודה, לקוח־קצה/כתובת, **סטטוס מפושט** (צבע), מחיר, תאריך.
- סינון: פעילות / הושלמו / הכול.
- כפתור ראשי: **+ הזמנה חדשה**.
- Badge על הזמנה שמוכנה להורדה.

**טופס הזמנה חדשה** (הלב של הפורטל)
שדות:
1. סוג עבודה (מטבח / דירה מלאה / חדר רחצה / ארונות / אחר).
2. פרטי לקוח־קצה: שם, טלפון, כתובת מלאה.
3. איש קשר לכניסה לאתר + טלפון (יכול להיות שונה מלקוח־הקצה).
4. **בחירת מק״טים** (שירותים) עם כמות → מחיר מוערך מתעדכן חי לפי מחירון הנגר.
5. תוצרים נדרשים (DXF 2D / DXF 3D / PDP / PDF).
6. הערות ודגשים (טקסט חופשי).
7. צירוף קבצים (סקיצות, תמונות, קובץ עיצוב).
8. דדליין מבוקש (אופציונלי).
- שמירה כטיוטה / שליחה. שליחה → יוצרת עבודה בסטטוס `submitted` + התראה למשרד.

**כרטיס הזמנה (מעקב + הורדה)**
- פס סטטוס מפושט (5 מצבים: נשלחה / התקבלה / בעבודה / מוכן / הושלם).
- פרטי ההזמנה + הצעת המחיר (עם פירוט מק״טים).
- כשיש הצעת מחיר לאישור → כפתור **אשר הצעת מחיר**.
- כשמוכן (`delivered`) → כפתורי **הורדת קבצים** + **אשר קבלה** / **בקש שינויים** (עם סיבה).
- יומן סטטוס (מתי כל שלב).

### 6.2 אפליקציית המודד (סמארטפון, offline)
**העבודות שלי (בית)**
- רק עבודות שהוקצו למודד, ממוינות לפי מועד. ברירת מחדל: "היום".
- כל כרטיס: כתובת, סוג, שעה, **זמן משוער** (מהבירור), כפתור ניווט.
- אינדיקטור offline + מונה עבודות שממתינות לסנכרון.

**כרטיס עבודה בשטח**
- פרטי אתר + איש קשר (חיוג/ניווט בלחיצה).
- כפתורי מנוע (נסתר-פסיבי): **יצאתי לאתר** → **הגעתי** (חותמים זמן+GPS).
- **מדידה ב-Soline Measure** (מערכת המדידה של סוליין — ראה `MEASURE_TOOL_SPEC.md`): המודד מודד **בתוכנה של סוליין**, לא ב-InnoDraw. שרטוט קירות + תשתית + DISTO → כותב ישירות לשכבת `measured/` של ה-`.sol`. (ייבוא ORDX נשמר לתאימות/מקרי-קצה.)
- צילומים והערות שטח נוספים למדידה.
- תחילת/סיום מדידה חותמים זמן (למנוע). שמירה → `measured` (DR1).
- **צ׳קליסט שלמות** לפני סיום (למניעת חזרה לשטח — ראה `OWNER_ANALYSIS.md`).
- **סיימתי וחזרתי** → חותם זמן+GPS (סוגר זמן/ק״מ נסיעה).
- הכול נשמר מקומית; מסתנכרן כשיש רשת.

### 6.3 קונסולת המתאם (מחשב)
**קונסולה (בית)** — תור הזמנות חדשות (`submitted`) בראש + לוח כל העבודות עם סינון לפי שלב/מודד/נגר + חיפוש.

**כרטיס עבודה (ניהול)**
- כל הפרטים: נגר, לקוח־קצה, הזמנה, מק״טים, סטטוס, יומן.
- פעולות לפי שלב: **קליטה ואישור** · **תמחור/הצעת מחיר** · **בירור ואימות שטח** · **שיבוץ + לו״ז** · **בדיקה DR2** · **מסירה**.
- קידום/החזרה בין שלבים (כולל לולאות תיקון).

**בירור ואימות שטח** — טופס: אופי העבודה, אימות מצב שטח (גישה/מורכבות/גבהים), **הערכת זמן וק״מ למודד**, החלטה: מספיק לשיבוץ? (אם לא → בקשת מידע מהנגר).

**שיבוץ ולו״ז** — הקצאת מודד + מועד (משך לפי ההערכה) + תיאום כניסה. תצוגת לו״ז יומי/שבועי לפי מודד.

**תמחור** — הרכבת הצעת מחיר משורות מק״ט (מחיר לפי מחירון הנגר), שליחה לאישור הנגר.

**בדיקה ומסירה** — מעקב תוצרים מהממיר (DXF/PDP), בדיקת DR2, ומסירה לנגר (`delivered`).

### 6.4 דאשבורד המנהל (מחשב) — אדמין בלבד
- **דאשבורד + KPI** (מסך בית): תפעול, כספים, שטח, דיוק הערכה. פירוט: `ADMIN_DASHBOARD.md`.
- **מנוע מדדים נסתר**: זמן/ק״מ/עלות/רווחיות לכל עבודה. פירוט: `METRICS_ENGINE.md`.
- **ניהול קטלוג ומחירונים**: מק״טים, מחירי בסיס, מחירון מיוחד לנגר. פירוט: `PRICING_CATALOG.md`.
- **ניהול משתמשים והרשאות**: הוספת/עריכת משתמשים ותפקידים, שיוך נגר.
- **הגדרות מערכת**: תעריפי עלות (שעה/ק״מ), תבניות התראה, גיבוי.
- גישה לכל מה שהמתאם רואה.

## 7. חוקי עסק (Business Rules)
1. **מעברי סטטוס** קדימה לפי ה-pipeline; אחורה רק דרך לולאות התיקון המוגדרות.
2. **בידוד דייר**: כל שאילתה של נגר מסוננת ל-`carpenterId` שלו; מודד ל-`surveyorId` שלו. נאכף בשכבת הנתונים.
3. **תמחור**: מחיר אפקטיבי = מחירון־נגר(מק״ט) אם קיים, אחרת מחיר בסיס. `total` = Σ שורות.
4. **אישור מחיר**: עבודה לא עוברת לשיבוץ לפני `approvedByCarpenterAt` (אלא אם המנהל עוקף).
5. **מנוע מדדים**: זמן משרד מחושב אוטומטית ממשך שלבי־משרד; זמן/ק״מ שטח מ-GPS. נראה למנהל בלבד.
6. **מחיקה רכה** בלבד (`archived:true`) — אין הרס נתונים.
7. **הרשאות**: כל פעולה נבדקת מול מטריצת ההרשאות; UI מסתיר + שכבת נתונים חוסמת.

## 10. ממשקים ואינטגרציות
- **Soline Measure** — מערכת המדידה של סוליין (המודד מודד בה, לא InnoDraw). ראה `MEASURE_TOOL_SPEC.md`.
- **DISTO (Leica) ב-Bluetooth** — קליטת מדידות ישירה לתוך Soline Measure (ראה `../../docs/disto_integration.md`).
- **ממיר ORDX→PDP** (`../ordx-pdp-converter`) — מנוע המרה/ייצוא; ORDX נשמר לתאימות (ראה `INTERFACE.md`, `SOL_FORMAT.md`).
- **מפות/ניווט** — פתיחת ניווט לכתובת + חישוב ק״מ.
- **וואטסאפ** (WhatsApp Business API) — התראות. **iCount** — מסמכים חשבונאיים. עתידי: אחסון ענן, ספקי CNC/marketplace.

## 11. דרישות לא-פונקציונליות
- **Offline-first** — כל פעולת שטח עובדת בלי רשת; סנכרון אוטומטי.
- **אבטחה ופרטיות** — הרשאות בשכבת נתונים; בידוד דייר; אין נתונים אישיים ב-URL; הצפנה בתעבורה (כשיהיה backend).
- **ביצועים** — טעינה מיידית מ-IndexedDB; עובד על מכשירי מודד בינוניים.
- **רב-דיירות** — הפרדה לוגית מלאה בין נגרים.
- **עברית / RTL** — מלא, כולל תאריכים ומספרים.
- **גיבוי ושחזור** — ייצוא/ייבוא נתונים; (עם backend — גיבוי אוטומטי).

## 12. שלבי פיתוח (Roadmap)
- **שלב 1 — MVP מקומי (offline, ללא backend):** 4 התפקידים, 11 השלבים, קטלוג/תמחור, מנוע מדדים בסיסי, דאשבורד. בורר תפקיד dev. **מתחילים מפורטל הנגר.**
- **שלב 2 — Backend + סנכרון + התחברות אמיתית + התראות SMS/וואטסאפ.**
- **שלב 3 — חיבור חי לממיר + DISTO + אופטימיזציית מסלול + חשבוניות.**
- **שלב 4 — BI/דוחות מתקדמים, אפליקציית נגר בחנות.**
