# תמחור וקטלוג מק״טים

כל התמחור והמק״טים מנוהלים **בתוך התוכנה הזו**. המק״טים מגדירים מה מזמינים ובכמה (הכנסה);
המנוע הנסתר נותן את העלות; ההפרש = רווחיות (ראה `METRICS_ENGINE.md`).

## הבחנה מרכזית: מחיר מול עלות
- **מחיר** (מה שהנגר משלם) = מהמק״טים. גלוי ל**נגר (שלו)** ול**משרד**.
- **עלות + רווחיות** = מהמנוע הנסתר. **רק האדמין הראשי.**

## קטלוג מק״טים
טבלת שירותים, כל אחד עם מק״ט, יחידה ומחיר בסיס.
```
catalog (store): sku, name, category, unit, basePrice, active, notes
```
דוגמאות (להתאמה מולך):
| מק״ט | שם | יחידה | מחיר בסיס |
|---|---|---|---|
| `MDD-KIT` | מדידת מטבח | יח׳ | ₪— |
| `MDD-BATH` | מדידת חדר רחצה | יח׳ | ₪— |
| `MDD-CLST` | מדידת חדר ארונות | יח׳ | ₪— |
| `MDD-FULL` | מדידת דירה מלאה | יח׳ | ₪— |
| `ADD-3D` | תוספת DXF 3D | יח׳ | ₪— |
| `ADD-PDP` | תוספת קובץ PDP | יח׳ | ₪— |
| `ADD-FLOOR` | תוספת קומה | קומה | ₪— |
| `ADD-RUSH` | עבודה דחופה | יח׳ | ₪— |
| `ADD-REVISIT` | ביקור/מדידה חוזרת | יח׳ | ₪— |
| `TRV-KM` | נסיעה מעבר ל-X ק״מ | ק״מ | ₪— |

## מחירון מיוחד לנגר (rates)
לכל נגר יכול להיות מחיר מוסכם משלו שגובר על מחיר הבסיס.
```
carpenterRates (store): carpenterId, sku, price
מחיר אפקטיבי = carpenterRates[carpenterId][sku]  ??  catalog[sku].basePrice
```

## תמחור הזמנה
ההזמנה נבנית משורות מק״ט:
```
job.order.items[]: { sku, name, qty, unitPrice, lineTotal }
job.pricing:       { subtotal, discount, total, currency:'₪',
                     quotedAt, approvedByCarpenterAt }
```
`total` = ההכנסה של העבודה. הרווחיות (admin) = `total − עלות מהמנוע`.

## איפה זה קורה בתהליך
1. **בהזמנה (נגר)** — הנגר בוחר מק״טים ורואה **מחיר מוערך** לפי המחירון שלו.
2. **בקליטה/בירור (משרד)** — אחרי שהיקף העבודה מאומת, המשרד מרכיב את **הצעת המחיר הסופית** (`accepted`/`assessment`).
3. **אישור הנגר** — הנגר מאשר את הצעת המחיר (`approvedByCarpenterAt`) והעבודה ממשיכה לשיבוץ.
4. **סגירה** — `total` מוזרם לחישוב הרווחיות של האדמין.

> קישור למנוע: `TRV-KM` (מחיר נסיעה לנגר) מול ק״מ בפועל (עלות) — אחת הדוגמאות שבהן מחיר ועלות נפגשים.

## מודל התמחור — היברידי (החלטה 2026-08-15)
שני מודלים אפשריים, ונבחר ההיברידי:
- **מחיר קבוע (Flat):** מחיר קבוע לכל מק״ט. פשוט וצפוי לנגר, אבל מפסידים על עבודה רחוקה/קשה.
- **לפי זמן/עלות בפועל:** מחיר לפי זמן+ק״מ+מורכבות. תמיד רווחי, אבל לא צפוי לנגר.
- **✅ היברידי (נבחר):** מחיר בסיס קבוע לכל שירות **+ תוספות אוטומטיות** שהבירור מזהה (`TRV-KM` מרחק, `ADD-FLOOR` קומה, מורכבות/גישה, `ADD-RUSH` דחיפות). הנגר מקבל הצעה ברורה (בסיס + תוספות בשמן); החברה לא מדמם על עבודות קשות. המנוע הנסתר משווה הערכה↔בפועל ומכייל את הבסיס והתוספות עם הזמן.
