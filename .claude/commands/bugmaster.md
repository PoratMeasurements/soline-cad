# מנהל-הבאגים (Bugmaster)

נהל את מחזור-חיי-הבאגים מקצה-לקצה. מקורות-הבאגים:
- `bug_reports/` — דיווחי-🐞 מהאפליקציה (PNG מסומן + JSON).
- באגים שהבעלים מדווח בצ'אט מהשטח.
- `SURVEYOR_BUGS.html` (דו״ח-המודד, Artifact `0fd1bbf2…`) = מקור-האמת למעקב.

## כלל-זהב (הבעלים, 2026-08-26)
**אל תקפוץ למסקנה ואל תתקן לבד.** על באג-מהשטח: הצג **אבחון** (שורש-משוער, file:line) + **אפשרויות-תיקון** (לפחות 1-2, עם יתרון/חיסרון) — ו**הבעלים מחליט מה התיקון**. רק אחרי-החלטתו — בַּצֵּעַ. אבחון≠אישור-לתקן. זה חל גם כשהשורש "ברור".

## הזרימה — אחד-אחד עד תיקון-מלא
1. **אסוף** את כל הבאגים הפתוחים לרשימה אחת מדורגת (🔴 חוסם · 🟠 גבוה · 🟡 בינוני · ⚪ נמוך). הבחן **באג** מ**דרישת-שדה**.
2. **קח את הבא-בתור** (החמור-ביותר). הצג לבעלים: מה-קרה · שורש-משוער (`ui/…` file:line) · **אפשרויות-תיקון**. **הבעלים בוחר** — אל-תבצע לפני-בחירה.
3. **תקן** (רק אחרי-שהבעלים בחר את התיקון) (מסלול-אפליקציה סדרתי, build-ירוק חובה — `$env:JAVA_HOME="C:\android-dev\jdk-17.0.20+8"`, מחיקת-desktop.ini, `& "C:\android-dev\gradle-8.9\bin\gradle.bat" testDebugUnitTest assembleDebug`; **בלי-להתקין** — ה-APK נבנה במרוכז בסוף-סשן לפי בקשת-הבעלים).
4. **עדכן את `SURVEYOR_BUGS.html`** — הזז את הבאג פתוח→בתיקון→✅לבדיקה-חוזרת, ופרסם-מחדש ל-URL הקבוע (`0fd1bbf2…`) כדי שה-QR של המודד יתעדכן.
5. **המשך לבא-בתור** עד שכל-החוסמים/הגבוהים ✅.
6. **החזרה למודד:** כשה-APK-הבא מוכן, רשימת "לבדיקה-חוזרת" בדו"ח מכוונת את המודד מה-לבדוק; אחרי-אישורו → ✔️ אושר.

## עקרונות
- **אחד-אחד**, לא-הכל-בבת-אחת — לפרק, לתקן, לאמת, ואז הבא.
- כל-תיקון **מצטבר** ל-APK-של-סוף-הסשן (אין התקנות פר-באג).
- דרישת-שדה (חסר, לא-שבור) → `docs/MEASUREMENT_PROCESS_UPGRADE.md` / roadmap, לא-כבאג.
- אחרי-טיפול, העבר את זוג-הקבצים ב-`bug_reports/` ל-`_processed/`, ועדכן `SESSION_STATE.md`.

אם `$ARGUMENTS` נותן מסך/חומרה — התמקד בזה.
